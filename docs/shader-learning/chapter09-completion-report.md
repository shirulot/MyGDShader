用户最终解释：“实际上扫描相当于时最后覆盖上去的 但是其实除了扫描以外 其他的地方都做了位置计算 所以本身就没有覆盖相关的操作 实际的覆盖就只有扫描和其他。”教师明确：其他层仍计算颜色混合，Mask将网格限制到外圈内侧，使主要可见交叠来自扫描层。这是对当前实现合成关系的解释证据，不推广为任意合成系统掌握。

## 当前参数、视觉节奏与合同

当前独立画布512×512；场景材质已与以下Shader默认值对齐：

| 输入 | 当前值 | 单位/职责 |
| --- | --- | --- |
| radius | 0.4 | 画布UV半径，固定可见范围 |
| ring_width / ring_edge | 0.01 / 0.0025 | UV距离，外圈宽度与内外柔边 |
| grid_count / grid_width | 20 / 0.004 | 全幅每轴20格；全幅UV中的线宽 |
| grid_alpha | 0.2 | 网格颜色混合强度，不是最终Alpha |
| scan_width / scan_edge | 0.1 / 0.05 | UV.y跨度；双侧扫描过渡 |
| scan_speed | 0.4 | 每秒0.4 UV的进度增长；fract回绕，完整周期静态推得2.5秒 |

最新grid_width范围0.001～0.1、scan_edge范围0.0001～0.1，已包含默认值。当前其他范围与代码无除零或反向smoothstep的结构性冲突；在半径很小/宽度很大、柔边重叠、密度为0等端点，形状会融合、减弱或填满。这些是当前公式的语义边界，不宣称任意参数组合均保留细线网格/完整亮环，也不伪造相关运行测试。

关键实际修复证据：先前场景材质保存grid_width=0.001、ring_width=0.001、ring_edge=0.01、grid_alpha=0.01；学习者后续保存为0.004、0.01、0.0025、0.2，与默认值对齐。随后自行修正hint_range，解释“实际上这么写可以动 但是不符合规范”。教师澄清这是参数声明与使用范围不一致，并非Shader语法错误。
