# 敌人固定母稿动作流程 v002 草案

状态：待技术美术总监验收。此文记录巡逻兵 move_down v004_r1 的制作方法，不改变既有五动作规格，不代表任何动作已经获得正式通过。当前仍先审巡逻兵八帧，未扩展其余十九条。

## 固定来源与可编辑性

每款角色保留一份已认可的正向原生母稿，并记录 SHA256。动作通过同一份区域划分、部件安装点、关节和遮挡顺序驱动。巡逻兵参考为 `art-source/ember/enemy-patrol-move-v004/source/canonical.png`，可编辑参数见同目录 `rig.json`，动作实现见 `fixed_rig.gd`。不靠每帧另生整只角色来维持身份。

隐藏面若确实缺失，应一次补入母稿并作为新的源版本审查；不能用逐帧临时填块掩盖断接。头胸、工具以及关节区域必须登记用途，不能把背景或相邻肢体随同区域一起移动。

## 机械部件与接地

- 硬壳与连接轴分开：膝甲应保持可识别的体积；暗胫、踝袖和靴口用关节姿态与前后遮挡表现收腿，避免整片装甲压成扁带。
- 支撑点是语义接触点。俯视投影下前后足的屏幕高度可以不同，不能逐帧按包围盒最低点齐底。
- 骨端使用原骨段自身基底中的映射，并记录真实节点变换。目标关节数值正确不等于图块端点或实际像素已经正确连接。
- 双足、四足、双履带和双转子的运动规则分别制定。不能套用同一个上下抖动来替代各自的运动机制。
- 待机与攻击固定支撑；单次动作末帧应衔接同一中性姿态。死亡按实际接地与唯一残骸验收，保留原组件数量和安装侧。

## 原生显示与导出颜色

画布128×128、root(64,104)、帧数与FPS继续沿用 `ember-enemy-animation-standard-v001.md`。源RGBA与游戏实体材质规则分别记录。v004_r1使用独立材质的0.5二值覆盖，仅作为明确的渲染规则；不能以此宣称原生轮廓与色簇整理已完成。

透明Viewport读回需明确Alpha表示。普通PNG、atlas与SpriteFrames应采用同一份正确颜色表示的帧，并分别在黑底和白底与原rig实际渲染进行同帧比较。连续Alpha的8位反除可能损失精度，不宣称低Alpha源字节可完全恢复。

最终预览播放导出的原生帧，再使用Nearest整数放大；不要把放大的关节几何重新栅格化结果当作原生PNG细节。放大联系图采用各帧一致的观察区域，不改变资产注册位置。

## 固定交付与判定

每次提交冻结独立版本，附源图、可编辑参数、逐帧PNG、atlas、SpriteFrames、catalog、1×/4×黑白底重点帧及正常/慢速/末首播放证据。元数据和检查记录绑定源图、图集或catalog的SHA。技术检查和TA视觉结论分别保存。

统计或导出脚本出错即停止打包，不能留下默认数值并继续写PASS。每条数值结论保存逐项记录，确保独立重算。固定包不得覆盖；内部无效包旁注明确原因并保留追溯。

工具：`tools/verify_enemy_patrol_endpoints.ps1 -Version v004` 独立重算32个真实骨端；`tools/package_enemy_patrol_pilot.ps1 -Version v004 -Revision r1` 验证版本绑定并拒绝覆盖现有交付。此打包工具目前仅适用于巡逻移动首关，不直接用于其它角色和动作。

最终放行由「技术美术总监」给出，技术PASS不替代造型、体积、步态、轮廓、动作衔接与落地的美术验收。
