## 当前长期有效的规则

1. **优先级与覆盖。** Shader 学习最高优先级。游戏、美术或商业范围不能删课程；全部具名效果最终在可玩学习项目中应用，课程掌握、游戏应用、商业验证分开。依据：2026-09-27、10-01 的明确要求及 requirements.md。
2. **熟悉与新概念分开。** 已教过或明确熟悉的内容，先给精确需求和文字方法，让学习者写，未求助不主动贴已学公式/代码；新概念先讲含义、输入输出与做法，必要局部 API/参考及时提供。依据：C03 明确反馈，见 chapter03-teaching-feedback.md。旧“先自行试，不懂再问”不适用于尚未讲清的新概念。
3. **需求要具体。** 从实际用途和可见目标出发，写清对象、必要数值/单位、变化方式和当前验收。颜色等非目标输入直接给默认RGB/RGBA；示例强度供调画面，不将教师自选中间值映射当固定考试。数字用于解释当前代码、单位和边界；用户要求“具体点”不等于索要答案。依据：C03明确反馈及[C08报告](chapter08-completion-report.md)的默认色值/实际需求修订。
4. **节奏与数学。** 一次一个小目标、一个数学关系，依据最新作品证据合并或省去已经证明的基础重复练习，保留尚未覆盖的核心标准。新关系先教用途、输入输出及局部方法，再给有限实践；缺少画面概念时按需提供可调目标预览，预览不泄露答案。数字、像素距离与可见结果连接；不从接触过vec/mat推定理解。用户写关键逻辑，教师可准备最小连线和默认采样。依据：C02/C03及C08明确反馈。C09再次确认：若学习者提出一步自主实现，可按作品合并检查；先说明当前未教的新核心，不能为固定步骤反复重做已证明内容。
5. **审查与推进。** 先读最新保存文件；“好了/写完了”及写后审查按用户已经正常运行确认处理，不重复追问同一画面或编造测试次数。给出具体评论：当前小步无问题再给下一小步，有问题停留排错；Section 切换仍按确认规则。依据：M0/C03/C04 反馈，C04 明确原话“审查完之后给出评论 如果没问题直接继续下一步 有问题在停留”。
6. **保留有效选择。** 区分真实错误、静态风险、可选整理和延期；保留已验证的替代实现，不因命名/风格不同返工，不在收尾无限追加挑战。调参后的保存值、Shader 默认值和教师示例分别记录；满足参数合同与可见目标时，不要求改回示例。依据：M0/C03/C04 的已接受方案与 requirements.md；C07 原话“因为测试我拖动了值所以你看到最终值会不一样 无伤大雅”，见 [C07 报告](chapter07-completion-report.md)。
7. **游戏和练习的素材选择。** 游戏默认用自制像素机器人与新地板；练习由教师按概念选材，适合时可试用新素材，测试图仍用于清晰对照，不为换图中断已开始练习。依据：2026-10-06 统合 Chat 三次明确补充。当前文件入口以 resources.md 为准，不把版本号当成永久偏好。
8. **调度职责与主动交接。** 章节教师只完成本章，结课按授权自动将报告发给指定统合者；由统合者核对后选择后续课程并新开一个 Chat，普通结课不需用户再次传话/说继续。依据：C04 调度纠正及2026-10-07本 Chat 的明确补充，见 handoff-protocol.md。2026-10-21补充：伴随游戏接入仅在用户明确提出需要时安排，不因C13或其他章节结课自动启动C07-A/M课；Shader课程照常续调度。教师不得自行开章；这不取消 Section 确认、不新增任意跨 Chat 消息权限、轮询监控、自动代写或商业扩展。
9. **长期累积。** 每章回收并更新需求/习惯，下一次分章节读取完整现行记录，而不是只带上一章的几句话。明确的新要求修订旧规则，保留来源与修订原因。依据：本页维护授权。

10. **严格编辑边界。** “审查”“不用你改了”按只读执行；“只改四个颜色”只授权指定颜色字段，不连带改强度、Alpha、范围、运动或场景其他参数。再次修改需有对应请求，不能以视觉接近或“逻辑没动”扩写。区分Shader默认、保存材质与未核验编辑器状态；修改前读最新值，修改后核对实际差异并说明影响。依据[C09报告](chapter09-completion-report.md)及直接人类纠正；这不禁止以后明确授权的调参，也不取消新课最小连线。

## 已采纳的教学方法改进

- C04：每一步明确旧逻辑哪些保留、哪些替换、哪些仅注释留档，以及最终输出由什么构成；复用旧代码时先说明本步实际需求、复用输入与职责，不只说“复制上一章”。这是针对本章切换困难采纳的教学方法，不包装为性格判断。
- C05：先用一句话说明本步输入将服务哪个可见效果，再拆小目标；不要把明确目的拆成一长串失去联系的调参。数字例子标注“Inspector 参数 / 某位置采样值 / 单位”；替换函数时说明下游判断和输出哪些要同步改变。依据 [C05 反馈](chapter05-completion-report.md#长期需求习惯反馈)，作为教师方法改进，不推导不喜欢理论或永久能力不足。
- C06：分开说明“采样坐标 → 读到的颜色/Alpha → 输出”，数字标源纹理像素、UV 与显示距离；一次只处理一个关系，再接下一步。依据 [C06 报告](chapter06-completion-report.md)及[教学记录](chapter06-teaching-notes.md)，同轮混讲相位/坐标/偏移不利于当前理解，拆开与源图采样位置查证有效；纳入教学方法改进，不将暂时困难当永久数学能力。C07 先复习 Alpha，再单方向邻域，保留全部核心内容。
- 没有新增用户偏好的章节，写“无新增，沿用现行规则”，并可指出哪些已有规则本章再次有效；不强行制造新习惯。

- C07：中断数日后先读最新保存文件，用短链条回顾“输入 → 处理 → 输出”，再继续当前小目标。复杂累计或合成用当前代码的一个具体像素逐轮代值，分开邻域最大值、Mask、输出通道与颜色份额；图解按需要提供，不推断永久只接受图解。依据 [C07 报告](chapter07-completion-report.md)的原话“距离上次看这个回复中间隔了几天 有点忘了……可以详细点么”“代码图解一下”。完整参考请求仅授权当次，随后“那我自己写一次”仍支持学习者编写，不改成默认代写。

- C08：先给实际用途与可见目标，再讲一个新关系的局部方法，连接当前代码后布置有限练习。明确求助时及时给当次局部参考；正常审查指出实际偏差，让学习者修正，不能反复只复述目标。作品已证明的基础合并检查，不固定拆成重复课步。配色作为输入直接给默认RGB/RGBA。抽象参数缺少画面概念时可提供不含公式/实现代码的可调预览，随后仍由学习者实现。数字用于当前代码的代值、单位与边界解释，不代替实际效果需求。依据[C08报告](chapter08-completion-report.md)与[过程记录](chapter08-teaching-notes.md)：用户既反对“单纯对值”，也主动请求追踪当前裁切代码的具体像素，两者适用场景不同；不概括成不要数学或一律只接受图解。

- C09：允许学习者基于已学方法自主完成整体原型，按作品、解释、调试和参数证据合并验收；先说明新核心，不强制跟完预设小步。名字与配色可作为输入直接给。审查只读、编辑只按指定字段，改前核对最新文件/保存覆盖值，未知编辑器状态如实标注。教师越界修改grid_alpha及撤回是执行事故，不记为学习者错误或独立排错成就，相关因果未复现不强断。来源与用户原话见[C09报告](chapter09-completion-report.md)。

- C10：遇到生命周期顺序卡点，按当前代码追踪一次具体事件，明确引用非null、对象有效性、kill、中止后终值和新建对象的先后；局部方法仍不清楚且明确求助时及时给可运行的局部参考，再由学习者迁移。接受有效的自主封装与编辑器材质隔离，不强迫改成预定脚本方案。用户明确界定的Demo范围/延期单列后推进，实际接业务时再核验；不反复以同一明确延期卡收尾。见[C10报告](chapter10-completion-report.md)。

- C11：解释动画时分别指出“参数从何值到何值”和“画面最后恢复成什么常态”，持续状态改变常态不等于取消瞬时动画。signal连接、发送当次数值、初始同步分别给局部方法。每步突出当前编辑文件、运行入口、实际节点/材质；学习者把后节并入旧文件时，明确“此文件已扩为综合成品、预备文件不再是入口”，不要按编号误读或为命名搬移代码。GUI连接、单Shader、反向进度/守卫/visible=false等一致有效的实现均保留。见[C11报告](chapter11-completion-report.md)。
