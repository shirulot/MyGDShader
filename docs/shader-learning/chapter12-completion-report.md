## 当前参数合同与实际保存值

### 12.1

- ScreenWindow明确偏移180～540，360×360区域；以720×720原实验布局为基准。12.1/12.2固定几何不冒称为任意窗口自适配组件。
- `zoom`：Shader默认2，范围1～4，材质保存4。围绕SCREEN_UV中心(0.5,0.5)缩放采样；当前输出平均灰度、Alpha1。
- 多个读屏节点不会自然形成连续后处理链的边界已解释，实际场景只用一个读屏输出节点。

### 12.2

| 输入 | Shader默认 / 范围 | 当前材质保存值及关闭方法 |
| --- | --- | --- |
| scan_strength | 0.25 / 0～1 | 约0.2；设0关闭扫描线明暗 |
| curvature | 0.15 / 0～0.5 | 约0.5；设0关闭曲率 |
| glitch_offset | 0.01 / 0～0.03 | 0.01；设0关闭故障横移 |
| rgb_offset_px | 1 / 0～3像素 | 1；设0关闭通道相对偏移 |
| pixel_size_px | 4 / 1～16像素 | 16；1时绕过量化 |

- 扫描线使用180个周期，每周期前1/4为暗段。
- `floor(TIME*5)`每0.2秒跳变；模5的阶段0/1开启，2/3/4关闭，故障空间只在SCREEN_UV.y的0.4～0.6横带。横移方向由模2决定。
- 最终`mirro`已经读取`pixel_uv`；R/B在该坐标基础上取左右邻点，G取中心样本。越界检查也使用`pixel_uv`。各关闭逻辑由最新代码核对，未编造所有开关组合的GPU实测。

### 12.3

- 根节点为满矩形Control，ColorTest与ScreenEffect也满锚点，根与两个Control子节点均忽略鼠标GUI事件。Sprite2D机器人仍先于ScreenEffect绘制。
- `center_uv`为viewport内0～1坐标；来自InputEventMouseButton.position / get_visible_rect().size。只在左键按下更新，无Camera2D或父变换的世界位置转换任务。
- 半径与半宽使用视口高度归一化单位。计算差值的x分量乘宽/高，修正后求距离与方向；再用SCREEN_PIXEL_SIZE将径向偏移像素数变回UV。
- `ring_radius`范围0～0.8，当前材质保存0；每次点击设0并在0.6秒内扩大到0.6。`ring_half_width`保存0.015，固定总厚度0.03。
- `refraction_px`范围0～24，Shader默认8，材质保存12；_ready设0，每次点击恢复12，0.6秒内并行降为0。结束保持0，停止旧Tween后再次点击会重新设起点。
- 用户最终把恢复12放在登记两条tween_property之后，同一次无await的输入处理内完成；此顺序实测有效，初值在PropertyTweener启动时取得。不是必须为风格返工的错误。
- `marker_color`及旧定位点注释保留，但最终输出是屏幕折射，不叠蓝色圆环。
- 当前半径终点不保证扫过任何点击位置的整个屏幕；核心目标为局部扩散并淡出，不等同完整转场揭示。高分辨率极端值、相机/多viewport、多效果串联、HUD隔离及性能不在已验证范围。

## 典型排错、有效替代与教师方法修正

- 初次读屏将对象UV当屏幕UV，窗口内部出现整屏缩影；通过区分输出几何、采样坐标、屏幕拷贝解释修正。
- step比较方向、阶段0且阶段1不可能同时成立、像素编号与UV单位混用，均在局部反馈后修正。用户自述“一时没缓过来”不转化为长期能力判断。
- 像素化曾遗漏中心采样，导致G保留未量化值；最新已保存修正。教师此前对黑边应使用哪个坐标的要求前后不一致，用户指出需求错位后已统一，不归因于学习者。
- 学习者用外圆减内圆代替绝对距离形成环；顺序乘法、if限制环带、有效函数抽取均保留，不按教师预设形式强制重做。
- **教师场景错误**：初始12.3用Node2D根加满锚点Control而无有效矩形，运行时背景/ScreenEffect均(0,0)。最初未经验证推测编辑器坐标问题，后用headless尺寸诊断确认并纠正；学习者最终改为Control根，尺寸正常。不能把场景准备事故记为学生Shader错误。
- 点击归一化误用Rect2.position而不是size；_on_ready未自动调用；Tween遗漏中心/半径复位，以及await完成后恢复强度使效果重新出现。用当前文件的执行顺序与参数终值定位，修正已验证。
