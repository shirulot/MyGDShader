# Ember UI 风格与制作规范 · 边缘标记 v1.0

更新：2026-10-06。适用于 Ember 的 HUD、设备终端、详情、菜单、设置、确认、结算及后续同风格界面。

本规范整理自用户选定的 A「边缘标记」参考图、后续修改意见和 v006 实际 Godot 实现。**以横向生命、完整窗口交互的 v006 为当前基准。** 原 A 图用于确认视觉语言；其中竖排生命已被用户否定，不再沿用。

v006 的既有组件及专项可交互示例已通过 [TA 审核](../../art-source/ember/ta-review-v001/ui-v006-independent/review-ui-v006.md)。本文新增的扩展约定用于后续制作，不代表新页面已经实现或通过审核。资源与运行入口见 [最终 UI 资源索引](../../assets/ember/ui_final/README.md)。

## 1. 风格定位与优先级

**低饱和旧工业像素 UI：深蓝灰底、暖米白文字、青色状态、少量黄铜结构，使用细线、角括号和留白组织信息。** 世界里的机器保留结构与材质细节；界面保持平静，让设备、危险和可操作项容易辨认。

制作优先级依次为：实际拼装和交互正确 → 与通过稿一致 → 信息清楚 → 像素清晰 → 装饰变化。单张概念图的漂亮程度不能替代真实组件验收。

| 维度 | 统一要求 |
| --- | --- |
| 构图 | 常驻信息沿屏幕边缘排列；现场中央保留给角色、设备和危险范围。详细信息使用侧终端或居中窗口 |
| 轮廓 | 直线、方角、局部阶梯转折、开放角括号；主结构线以原生 1–2 px 为主 |
| 材质 | 平整暗底与少量像素明暗；黄铜集中在端夹、拉手和按下反馈等小面积位置 |
| 强调 | 用状态颜色、明确形状、文字和焦点角层强调；同一状态在所有界面使用相同语义 |
| 节制 | 避免整圈厚金属边、密集铆钉、大片高亮铜色、强霓虹光晕、玻璃模糊和照片式金属纹理 |
| 一致性 | 更换地图时优先替换设备肖像、标题和数据；保留 UI 颜色含义、线宽、字号层级和交互习惯 |

## 2. 颜色、文字与尺度

### 颜色

以下取自当前皮肤清单与 `edge_ui_state.gd`，扩展时按用途复用。

| 用途 | 色值 | 使用规则 |
| --- | --- | --- |
| 主暗底 | `#101820` | 窗口、读数底板，隔开复杂地图背景 |
| 次暗底 | `#182631` | 行背景、滚动轨道和局部层级 |
| 低对比结构 | `#2B3E4B` | 分隔线、程序绘制的轨道 |
| 钢灰结构 | `#4D6470` | 框线、滚动抓手、皮肤结构 |
| 次级文字 | `#829BA3` | 说明与辅助标签；需结合暗底检查可读性 |
| 主文字 | `#ECE9D8` | 标题、关键数字、可操作项 |
| 青色 | `#51C5C2` | 安全、采集、有效填充和滑条焦点 |
| 琥珀色 | `#E5A44B` | 预警和需要注意的后果 |
| 爆发红 | `#E65B4A` | 危险爆发、失败信息 |
| 冷却／禁用灰 | `#566B78` | 冷却、不可用；同时给文字说明 |
| 黄铜 | `#B77C4B` | 小型结构与按钮按下反馈；皮肤阴影 `#7B4D35`、亮面 `#E2B77A` |

安全用菱形，预警用三角，爆发用星形，冷却用时钟。**状态必须有文字或形状辅助，不能只靠颜色。** 未知状态显示“未知”并停止可采集提示，不能自动当作安全。

### 文字

- 标题 28 px；设备小标题／分节标题 24 px；主按钮 22 px；正文与常规标签 20 px；辅助读数／紧凑入口 18 px。已通过的紧凑例外包括生命折叠计数与侧终端「采集目标」标签 16 px；侧终端关键目标读数使用 26 px 强调。保留这些现有例外，16 px 不作为正文默认值。
- 文字始终由 `Label` 或按钮渲染。设备名、数字、百分比、倒计时、状态名、键位和语言内容都不烘焙进 PNG。
- 当前字体工厂使用粗体 CJK 系统字体并关闭字体抗锯齿，按原生字号渲染。字体比例本身保持可读，不通过非等比缩放制造“像素感”。
- 地图上裸露的 HUD 文字使用 2 px 暗描边；面板内正文保持干净。长正文换行，长标题在固定区域省略；关键数值不能无提示截断。
- 当前通过环境为 Windows。正式跨平台发布前需选定可分发的 CJK 字体并重新检查字宽、换行和布局，当前没有统一内置字体交付。

### 屏幕尺度与布局数值

UI 使用屏幕像素空间。当前对比画布为 **720×720、UI scale=1**；世界瓦片的 `0.25` 缩放不应用到 UI。

| 项目 | 当前基准 |
| --- | --- |
| 纹理采样 | `NEAREST`；无损 PNG，不生成 mipmaps；位置尽量落在整数像素 |
| 间距 | 扩展优先复用 4 / 8 / 16 / 24 / 32 px；现有经验证的小尺寸例外可保留 |
| HUD 留边 | 默认 36 px；设置页开放 16–60 px、步长 4；底层 HUD API 支持 16–80 px，并在小视口压缩 |
| 普通按钮 | 最小 160×52；紧凑入口实际 124×44；关闭按钮 84×48 |
| 生命槽 | 单槽 24×32，横向步进 32，即槽间 8 px |
| 角件／状态图标 | 角件 16×16；四状态图标各 32×32，保持比例 |
| 侧终端 | 默认宽 248，底层可调 224–320；最小宽 224 |
| 模态窗口 | 常规最大宽 600，距视口边缘至少 24；正文左右各 24，正文项间 16；标题和关闭固定 |

皮肤扩大范围时使用九宫格拉伸中心与边，不拉伸角件。不要将完成后的整张 UI 截图缩放成其他分辨率。

## 3. HUD 与页面布局

**生命固定横排，从左向右排列。** 当前生命仅控制填充，失去生命后保留空槽。默认展示 3 格；现有组件按空间最多显示 6 格，更多生命或空间不足时保留准确的 `当前 / 上限` 数字。窄屏不能改回竖排生命。

常态 HUD：生命在左上，时间在右上，能量横条在底部，设备标签靠近关联设备；详情和菜单入口与生命左边缘对齐。右侧终端展开后，时间、能量和世界标签依据剩余区域重新布局。

| 页面 | 内容与结构 | 行为 |
| --- | --- | --- |
| 设备详情 | 名称、真实肖像、状态、目标／进度、采集说明 | 居中模态；可以固定到侧终端；关闭后恢复入口焦点 |
| 侧终端 | 肖像、累计能量、四状态行、说明和返回 | 非模态信息面板；四状态行是只读显示 |
| 暂停 | 继续、界面设置、帮助、重开、返回起始页 | 模态；宿主收到阻断信号后暂停相应玩法 |
| 设置 | 留边滑条、设备标签开关、保存和取消 | 修改草稿；保存成功才应用，取消／关闭放弃草稿 |
| 确认 | 具体后果、当前进度、继续当前巡检／确认操作 | 默认焦点在取消；重开和返回起始页分别确认 |
| 起始页 | 开始、设置、帮助 | 开始由宿主执行；不能关闭页面穿入未开始的巡检 |
| 结算 | 宿主传入的成功／失败、真实统计、重试／返回 | 禁止 Esc 穿回已结束的一局 |
| Toast | 简短反馈，如保存成功、固定终端 | 默认 3 秒；不抢焦点、不拦截鼠标 |

小屏处理顺序：先调整可用宽度与换行，再让正文滚动，再折叠非关键展示。当前剩余世界宽度小于 300 px 时，时间换到下一行；小于 224 px 时，终端优先完整显示，现场生命／时间／能量暂藏。模态窗口的小屏正文可滚动，标题和关闭仍固定。

## 4. 图片、程序与遮盖的拆分合同

**会随数据、输入、语言或尺寸变化的部分必须独立。** 一张资源只承担清楚的职责，不能把整块“看起来完成”的 UI 合成一张图片交付。

| 组件 | 图片承担 | 程序承担 | 裁切／遮盖规则 |
| --- | --- | --- | --- |
| 生命 | 空槽轮廓、填充各一张 | 数量、亮灭、横向排布、折叠计数 | 隐藏 Fill，保留 Outline |
| 能量 | 轨道、填充、铜端夹分开 | 真实数值、比例、百分比、宽度 | 只裁填充；轨道与铜夹固定在裁切层外 |
| 时间 | 暗底、角件 | 格式化倒计时 | 不把数字裁进边框；窄屏重排 |
| 世界标签 | 图标、暗底 | 状态、文字、投影、可见性 | 标签完整位于可见世界内；被终端挤出或设备失效时隐藏 |
| 状态行 | 形状、行底、强调线 | 同源状态映射与颜色 | 状态显示不伪装成改变玩法的按钮 |
| 设备肖像 | 独立设备图、独立肖像框 | 当前设备注入、比例适配 | 肖像容器负责必要裁切；框覆盖在上；设备失效时清空旧肖像 |
| 按钮／滑条 | 角件、透明焦点层；其他底色可程序绘制 | normal / hover / pressed / disabled / focus、数值 | 焦点层独立开关，不截获输入，不改变控件布局 |
| 窗口 | 不透明底板、装饰框 | 标题、内容容器、关闭、正文滚动 | 全屏遮罩与窗口底板分开；长内容只在正文区裁切 |

当前共 **18 张 UI 皮肤 PNG**，完整尺寸和职责在 [inventory.json](../../assets/ember/ui_final/skins/inventory.json)。关键九宫格边距顺序为左／上／右／下：96×96 面板、文本底、状态行、焦点层、肖像框均为 `8/8/8/8`；能量轨道 32×16 为 `8/4/8/4`；强调线 4×32 为 `1/2/1/2`。角件、生命槽、状态图标和铜件按原生比例使用。

透明区域必须是真实 Alpha。底板承担遮住地图的职责，透明边框与角件承担装饰职责。白色蒙版只用作程序遮罩或染色载体，不能当可见白底使用。

叠放关系：世界 → 世界标签与 HUD → 侧终端底板／内容 → 模态遮罩 → 模态底板／正文／控件 → 各控件焦点层。Toast 可显示在反馈层，但始终不获得输入。

当前模态遮罩是深蓝黑、Alpha 0.80；窗口底板不透明。装饰节点使用 `MOUSE_FILTER_IGNORE`；窗口遮罩、窗口交互区域使用 `STOP`；侧终端只消费自身区域鼠标事件。**视觉上遮住角色不等于暂停角色输入。** 宿主应依据 `blocking_changed` 或 `is_blocking()` 管理移动、时间与采集。

## 5. 交互、数据与状态规则

- 鼠标、键盘、手柄必须完成同一条流程。Tab／Shift+Tab 切换焦点，确认键执行，Esc／返回逐层退出；当前手柄默认 A 确认、B 返回、Start 菜单，确认／返回可局部改键。
- 获焦必须看得见。按钮沿用角括号焦点层，滑条使用青色焦点角层；失焦或禁用时隐藏。悬停不能代替键盘／手柄焦点反馈。
- 模态内焦点循环，不能跳到被遮盖的 HUD。关闭后恢复入口或上一页对应控件；滚动区内获得焦点的控件自动进入可见范围。跨 Viewport 重挂后仍依据当前视口处理。
- 一次确认只提交一次。危险确认默认取消；不可用控件退出焦点链。保存失败保留设置窗口并显示错误，不能误报保存成功。
- UI 接收真实状态，不按能量百分比猜危险。`145 / 380` 在当前玩法中是全局累计能量／目标，不表示设备储量。
- 采集遵循现有玩法：游戏进行中、角色进入采集范围并停下、站点处于安全或预警。移动中断；爆发／冷却不能采集。详情页不新增“点击开始采集”来替代这套机制。
- 进度比例处理 0 上限、负数、超量和非有限数；显示层有安全降级。无设备、设备删除、未知状态需明确处理，不能留下上一台设备的有效外观。

当前实现以即时状态反馈为主。未来如增加动效，需保持文字、轮廓和焦点清晰，避免全屏闪烁、强发光与长时间过渡；动效不能延迟输入或代替状态信息。

## 6. 扩展方式

新地图继承统一 UI，差异优先体现在地图名称、真实设备肖像、内容和用途上。新功能优先组合现有窗口壳、按钮、状态行、进度条和提示，不为每个页面重新画一整套边框。

背包、任务、商店、装备、页签、筛选、物品列表和提示浮层属于后续扩展，**当前不宣称已实现**。新增时先定义数据、入口、返回路径、空态、满态、禁用态、长文字和小屏行为，再制作缺少的原子部件。购买、出售、丢弃等行为需要先有对应玩法和后果定义。

新增资产应附：用途、原生尺寸、透明／不透明职责、九宫格边距、锚点、允许缩放方式、动态区域、状态清单和真实组装示例。界面大幅换皮或流程变化需要重新验证与审核。

可直接用于下一批 UI 设计的风格描述：

> 为 Ember 制作「边缘标记」风格 UI。沿用低饱和旧工业像素语言、深蓝灰不透明底板、暖米白文字、青色有效状态、少量黄铜端件；使用细线、方角、开放角括号和充分留白。HUD 沿屏幕边缘布局，生命横向排列，设备信息采用右侧终端或居中详情窗口。图标、边框、填充、焦点、遮罩和文本独立，尺寸及状态遵循现有组件合同。提供能够在 Godot 中实际拼装的组件和窗口状态，概念展示与引擎截图分别标明。

## 7. 交付与验收

每次交付需同时能看、能用、能追溯：保留选定参考与制作源，提供透明皮肤及尺寸合同、可复用场景／脚本、可操作示例、真实 Godot 截图和范围明确的检查记录。效果图不得代替组件，也不能把示例宿主的通过扩大为主游戏已经集成。

沿用当前验证尺寸：320×480、480×640、720×720、960×540、1280×720、1920×1080。新增窗口重点检查：长中文与数字、空数据、生命 0／满／多格、进度 0／中间／满／越界、四状态／未知／断开设备、鼠标与键盘／手柄完整流程、焦点可见和恢复、滚动、遮罩点击、重复确认与跨视口重挂。

最终资源统一放在 `res://assets/ember/ui_final/`：皮肤在 `skins/`，引擎截图在 `previews/`。运行主示例打开 `res://assets/ember/ui_final/demo.tscn` 后按 F6；可复用总入口为同目录 `ui.tscn`。两个入口复用项目已有场景，基础脚本／场景的 `v001` 与流程的 `v004` 仍是活动依赖，不能按后缀误删。内容基准沿用 **v006**；本次目录迁移另有记录，原 v006 ZIP 保留原路径供历史复验。

当前验收边界：UI 组件和潮汐港专项交互宿主通过，包含横向生命、设备详情／终端、暂停／设置／帮助、确认、起始／结算与 Toast；M0 主玩法接入及其他平台字体适配需在对应集成任务中验证。
