# Ember 人形像素角色制作与动画验收规范 v001

日期：2026-10-07。适用：人类 A 勘探员、C 信号员；后续人形角色可复用流程，须单独登记比例与身份。

本文按用户要求整合现有项目规则与 GitHub / itch.io 参考。本次只建立规范，不继续生成、修图、安装工具或替换游戏资源。

## 1. 优先级与状态

优先级：**角色同一性与连接正确 → 动作与循环自然 → 固定注册与方向一致 → 像素风格与细节 → 扩充数量**。任一前置项失败，不以素材数量、技术检查通过或远距离看不明显抵消。

- 继承：[统一美术规范](ember-art-unified-v001.md)、[TA 验收规范](ta-art-review-standard-v001.md)、[基础循环合同](../../art-source/ember/human-ac-basic-v002/loop-contract.md)。本规范是人形专项补充，不改写其他角色合同。
- 用户选中了 A/C 形象，不代表每张方向母版、动作或生产规格已经通过。
- v003 保持 NEEDS_REVISION；v004 只修订播放注册，不能消除源图里的转向、比例和身份变化，也未取得生产通过。
- 下文“必须／禁止”为后续人形制作硬要求；“建议”是待代表小样验证的起点，不是行业统一数值或已获用户认可的运动参数。

## 3. 形象、视角与八方向母版

### 3.1 身份合同

保留低饱和旧工业风、蓝灰结构、浅色衣甲、克制黄铜与清晰像素块面。人体使用自身比例，不套机器人的大头短腿；不靠新增大背包或长衣摆遮住问题关节。

| 角色 | 必须保留的识别特征 | 制作前登记 |
| --- | --- | --- |
| A 勘探员 | 白额发、斜襟浅短外套、单侧深肩部 | 发区形状、衣襟方向、肩部装具的解剖学侧别与安装点 |
| C 信号员 | 黑白短发、小耳机、高领修身上装 | 黑白发分区、耳机解剖学侧别、连接结构与各方向遮挡 |

侧别必须以形象源图和专项记录核对；当前 C 耳机登记证据不充分，不能在规范中自行假定为左或右。每个不对称部件建立八方向“可见／部分遮挡／完全遮挡＋遮挡者”表。看不见不等于消失，不得换边或复制另一份来保证可见。

### 3.2 母版合同

1. 先做八方向静态母版与比例表，再扩动画。每向登记头顶、颈、双肩、骨盆、肘、腕、膝、踝、脚跟／脚尖及配件安装点。
2. 正式地图角色采用同一套正交俯视投影；具体俯角以通过的母版为依据，目前不臆定为45°或60°。已有左侧视试样可以保留作研究，不能据此认定俯视八向已经统一。
3. 方向与项目一致：`down / down_left / left / up_left / up / up_right / right / down_right`，对应 S/SW/W/NW/N/NE/E/SE。外部包的方向编号须显式映射，不能按文件顺序猜。
4. 同一动作中相机、比例和基础朝向固定。允许有设计依据的肩髋轻微反向扭转，禁止半周期突然从侧身切成正面或背面。
5. 左右方向不直接镜像成品交付。不对称装备、衣襟、头发和场景光向都要逐向核对。

TA澄清：八向母版是扩量前的闸门。本轮代表小样先冻结对应方向；C八向身份登记可使用已有源图，未定方向标待审，不以重生整套八向阻塞三组小样。

## 4. 画布、根节点与身体运动

| 项目 | 合同 |
| --- | --- |
| 导出单帧 | 64×96，固定格，RGBA PNG |
| 地面根锚点 | `(32,80)`；它是角色世界位置的投影基准，不是每帧脚底最低点或腰部中心 |
| Godot 绘制 | `centered=false`，固定 offset `(-32,-80)`；世界位移由角色节点控制 |
| 像素显示 | Nearest；主体 Alpha 为0或255，烟光另层；棋盘背景不进入素材 |
| 源稿转换 | 保留原始画布与转换记录；同一角色整套动作共用登记的比例及坐标变换 |

必须区分三个层次：世界 root、相对 root 的身体动作、图集装箱坐标。待机／原地走跑的动画不写入额外世界位移；骨盆、胸、头仍可以在 root 周围按动作规律运动。

**禁止逐帧包围盒居中、齐脚底、对头顶、独立缩放，或锁死腰部掩盖原稿漂移。** 装箱确需裁切时，必须保留能无损还原原固定格的偏移；装箱偏移不能充当姿态修复。v004 的逐帧 draw offset 属于诊断修订，不作为后续源稿生产方法。

建议小样的骨盆活动预算：idle 水平0～1px、垂直0～1px；walk 水平中心±1px、垂直中心±1px；run 水平中心±1px、垂直中心±2px。仅用于发现明显漂移，不机械裁平运动；预算可依据完整步态调整并登记。蹲下、跳跃、受击不套用这些范围。

所有可见像素必须完整容纳在合同画布内。若动作越界，先复核姿态与构图；确需更大画布，新增登记统一锚点的动作画布，不能静默缩小该动作人物。

## 5. 骨架、关节与分件

### 5.1 制作数据

建立 `root → pelvis → chest → neck/head`，从肩部连接上臂／前臂／手，从髋连接大腿／小腿／足。左右均指解剖学左右，不能在脚交叉时交换身份。鞋底、护板、工具等刚性件不可拉伸；衣物随身体弯曲，但身份纹样跟随所在部件。

每帧记录骨架关键点、动作相位、支撑脚、接触状态、遮挡顺序与事件。二维姿态点另记可见性和近远关系，避免把遮挡误判成关节缺失。3D骨架固定真实骨长；2D投影长度可因朝向和透视缩短改变，不能把所有屏幕骨段长度强行锁成相同值。

### 5.2 膝盖与脚的硬要求

- 必须保留真实屈膝。髋、大腿、膝、小腿、踝、足要形成可解释的连续结构，不能通过锁腿或藏腿回避动作。
- 屈伸围绕固定解剖结构发生，膝点不得滑到大腿中部或鞋面。明确该方向的屈膝平面；2D IK记录弯曲侧，3D IK固定膝盖目标方向，避免跨越近伸直姿态时突然反折。
- 正面／背面屈膝会产生投影缩短和遮挡，不照搬侧面膝盖的屏幕轨迹；不能只凭三个二维点的夹角判定正确。
- 关节必须有可读厚度与承接。近侧轮廓遮住远侧关节时仍要读成同一条肢体；禁止细线吊着护板、暗部横切肢体或一像素桥勉强连接。
- 脚掌作为整体改变角度，踝部负责过渡。禁止鞋尖与鞋跟反向折叠、鞋体长短跳变，或为齐底把踝压入鞋中。
- 蹲下／拾取要同时协调髋部后移或降低、膝屈曲、躯干前倾及支撑关系，不能只把小腿折起来。

### 5.3 支撑与遮挡

脚是否滑动必须按空间判断：原地走跑图中，支撑脚相对角色向后移动是正常的；当角色世界位移抵消此运动后，接地点才应近似固定。禁止把支撑脚在精灵坐标中全程钉住而使游戏内滑步。静止蹲下／拾取则按登记接触点维持支撑；主动换步要画出过程。

层次根据方向和姿态登记，过中线时检查前后肢体交替；不能全动作固定“左腿永远盖右腿”，也不能无因交换。分件搭接须覆盖活动范围，最后在原生像素下修整轮廓。技术连通、IK骨端相接不等于视觉连接合格。

## 6. 动作与循环合同

建议后续试样沿用已知节奏，避免同时改造型、动作和速度：

| 动作 | 帧与时序起点 | 播放合同 |
| --- | --- | --- |
| idle | 4帧×250ms，1秒；已有8帧候选须单独记录，不自动删帧 | 无限循环；稳定支撑，呼吸主导局部变化 |
| walk | 8帧×120ms，0.96秒 | 正向完整两次换步；含左右接触、下沉、经过、抬升 |
| run | 8帧×80ms，0.64秒 | 正向完整两次换步；支撑／离地相按该步态设计，不能硬套行走 |
| crouch / jump / collect | 帧数依动作分段登记 | 区分进入、保持或工作、退出；跳跃区分起跳、空中、落地 |
| push / pull | 工作循环与进入／退出分开 | 登记手部接触点、物体运动及脚下支撑；脱离物体的空演不能作为完整验收 |

上述参数是人形小样起点，不修改旧包，不套用机器人或敌人时序。所有新增动作在制作前明确游戏循环还是单次；审阅页自动重播不改变运行合同。采集需要持续工作时，制作可循环的工作段，并独立处理进入和退出。

循环采样覆盖 `[0,T)`；T时刻回到首帧相位。**尾帧不要求与首帧画面相同，要求尾→首的运动连续。** 不额外复制首帧导致停顿。走跑禁止倒放、乒乓播放、交叉淡入或混帧掩盖缺失换步。

必须联合检查 `F(N-2) → F(N-1) → F0 → F1`：关节位移与速度趋势、支撑切换、摆臂、头胸朝向、配件和衣物运动都要自然。若采用连续骨架曲线，周期边界的姿态与速度应衔接；像素取整造成的小台阶由视觉检查判断，不强求逐帧像素差相等。

八方向同一动作共享周期与相位语义。方向切换保持归一化相位，不重置到第一帧；帧数不同时按累计帧时长映射，不能直接复用帧下标。单次动作结束到同向 idle 的姿态衔接另验。

TA澄清：10周期和尾首闭环仅适用于循环段；单次动作独立登记能否中途切向、取消和事件唯一触发规则。跳跃需登记画内升降与角色节点高度的分工，禁止两者重复叠加同一段腾空位移。

## 7. 制作流程与工具边界

1. **范围登记**：角色、方向、动作、循环方式、第三方参考职责与来源。只生产本轮授权范围。
2. **锁母版**：通过静态比例、侧别和方向检查；八方向属于同一个人、同一个投影系统。
3. **做运动底稿**：由模板提取关键姿态与时序，适配 A/C 比例，先看骨架／简化体块动画。二维点要人工校正，不能只依赖自动估计。
4. **明确三类约束**：root、相机、身份部件为固定项；关节轨迹、接触与遮挡为逐帧项；头发衣摆等为次级运动。模型未真实执行的约束不能记为已锁定。
5. **制作外观**：每次一个角色、一个方向、一个动作。使用同方向母版和全周期姿态；禁止一次提示生成整套八向动作作为最终生产输入。
6. **局部返修**：保留合格帧与已认可方向，局部修改要检查未修改区域；重新生成导致头发、肩具或衣襟变化同样退回。
7. **像素整理与固定导出**：在64×96实际像素预算检查；大图缩采样只能标候选或诊断，不直接宣称原生完成。使用已登记共享色板，不每帧独立量化。
8. **先小样后扩量**：建议先验 A右下idle/walk、C左下run及C八向身份板，对应已发现的问题；通过后按同方法扩展现有授权范围。

工具选用原则：分件／骨架编辑适合显式控制关节和轨迹；骨架条件生成适合在姿态约束下制作外观；通用生图仅有文字和参考图时，约束仍是软性的。AI工具如需方形画布，可统一补边处理，再按同一固定窗口还原；不得逐帧自动裁切人物。工具版本、输入骨架、冻结帧、局部编辑范围与实际输出都要留档。

## 8. 验收门槛

| 检查 | 通过证据 | 退回条件 |
| --- | --- | --- |
| 身份与方向 | 八向母版；头发、胸衣、肩具、耳机逐帧对照 | 半周期变朝向；部件换边、增减；脸和衣服重设计 |
| 根与比例 | 固定root和共同变换；骨架／体块轨迹叠加 | 无因整身平移、缩放；靠注册补偿隐藏形变 |
| 关节与足部 | 1×及4×Nearest、深浅背景逐帧＋动态 | 断裂感、反折、脚掌折叠、无因膝点迁移 |
| 支撑与接触 | 标记支撑相；原地预览＋实际位移／交互预览 | 滑步、手穿物体、腾空相被齐底抹去 |
| 循环 | 每段正常速度连续观察≥10周期；慢放和接缝四帧 | 末首停顿、跳变、倒放凑帧、两个半周期不一致 |
| 切向／状态 | 八向相邻45°方向同相位切换；单次结束回idle | 变体量、左右腿重置、工具跳边、结束瞬移 |
| 技术与引擎 | 固定格、Alpha、时长、索引、Godot实际播放 | 裁切、滤波、路径失效、网页通过却引擎错误 |

机器检查只证明尺寸、文件、时序和可计算异常；连通域、bbox、像素差及循环计数均不能单独证明动作自然。只检查部分动作时，必须列出实际覆盖，不能标整包通过。已见明确视觉问题即可退回，不用继续跑全矩阵掩盖问题。

状态独立登记：`technical_status`、`visual_status`、`runtime_status`；值使用 `not_reviewed / needs_revision / pass`。只有范围内三类验收全部通过、无未决阻塞时才可标 `production_ready=true`，用户形象偏好与技术验收另记。

TA澄清：通过状态绑定具体角色、方向、动作、版本及运行场景；查看器通过不暗含主游戏交互、碰撞、事件接入通过。规范接纳回执见[TA审阅](../../art-source/ember/ta-review-v001/human-animation-standard-v001-review/review.md)。

## 9. 交付结构

每次在新版本目录中交付：

```text
README.md                 # 范围、状态、已知限制、可复现步骤
identity.json             # 角色比例、侧别、八向可见性、母版引用
manifest.json             # 工具版本、来源、许可、变换、文件哈希
source/                   # 可编辑分层/骨架工程、原始生成稿与输入
poses/                    # 每帧关键点、支撑/遮挡、相位与事件
final/                    # 固定格PNG、SpriteFrames或明确导入元数据
qa/                       # 技术结果、逐段视觉/引擎覆盖与问题帧
previews/                 # 正常/慢速动画、联系图、末首对照
```

每段元数据至少包含：角色、动作、方向、cell、root、逐帧duration、loop、相位/事件、atlas region、源版本与三类验收状态。坐标说明原点在左上、x向右、y向下；骨架的浮点坐标与最终像素位置分开记录。WebP/GIF用于审阅，PNG及正式元数据用于引擎。

保留原v002/v003/v004与已认可左向源文件，不覆盖历史证据。规范建立不改变它们当前的候选或未通过状态。
