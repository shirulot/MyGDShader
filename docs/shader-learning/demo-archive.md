# Demo 归档规则

项目整理者在用户要求“保存当前 demo”“暂存当前 demo”或“开始下一个 demo”时，先归档当前 Shader，再进行后续工作。仅约定规则时不创建快照。

## 来源与目录

- 当前源文件：`shader/main.gdshader`。
- 归档路径：`shader/demos/chapterXX/demo_NNN_effect_name.gdshader`，例如 `shader/demos/chapter01/demo_001_grayscale_blend.gdshader`。名称根据实际效果使用简短的英文 snake_case。
- 章节按统合者的 `curriculum.md` 和 `progress.md` 确定；用户明确指定当前作品所属章节时，以该说明为准。
- 切换章节时，当前作品归入它所属的旧章节，不归入即将开始的新章节。无法确认归属时先询问。

## 编号与复制

1. 扫描 `shader/demos/` 所有章节下已归档的 `demo_NNN_effect_name.gdshader`（兼容旧的 `demo_NNN.gdshader`），提取编号。
2. 全项目统一递增，不随章节重置；首次为 `001`，以后取已使用的最大编号加一。数字至少三位，不补用删除留下的空号。
3. 每次用户要求保存一份，就新增一个编号；不得预先为课程小节批量编号或生成 demo。
4. 创建对应章节目录，按下方“内容筛选”规则从源文件生成副本；目标已存在时不得覆盖，重新选择未使用的下一个编号。
5. 不修改、清空、重命名或移动 `main.gdshader`，不修改场景引用，不复制 `.uid` 文件。
6. 比较归档操作前后源文件的 SHA-256，确认原文件未改变；核对副本保留的代码与源文件一致、引用依赖完整且无无关声明。汇报归档路径、编号和过滤内容。

## 内容筛选

- 以源文件中存在的 `fragment()` 和 `vertex()` 为入口，保留函数签名和完整函数体，包括内部局部变量与注释；不改写内部逻辑。
- 递归保留入口调用的自定义辅助函数，以及这些辅助函数继续调用的函数。
- 仅保留上述代码实际引用的全局参数和声明，例如 `uniform`、全局变量、常量、`varying`、结构体；声明的类型、初始化表达式等继续引用的依赖也一并保留。
- 依赖分析以实际代码为准，注释中的名称不算引用；跨 `vertex()` 与 `fragment()` 使用的声明须保持完整。
- 删除未被引用的外部函数和变量，包括未使用的 `uniform`；不保留独立的 `light()` 入口及其专属依赖，也不保留注释掉的外部示例函数。
- 保留 Shader 文件必需的 `shader_type` 以及影响入口行为的 `render_mode`、必要预处理声明。遇到宏或 include 时先核对实际依赖，不凭简单名称搜索删除不确定的依赖。
- 保留声明原有的默认值、hint 和相对顺序；筛选仅作用于新建副本，禁止修改源文件。
- 在承担效果的 `fragment()` 或 `vertex()` 上方添加中文学习注释，说明本 demo 的主题、实际使用的知识点和可观察的效果；若两个入口均承担学习内容，分别注释。不把尚未使用的参数或功能写为已学习内容。

例如：若 `fragment()` 使用 `gray_progress`，但两个入口及辅助函数都没有使用 `white_flash`，则副本保留前者并过滤后者。

归档仅保存 Shader 脚本，不包含场景中的材质参数、贴图或其他依赖，不视为独立可运行场景，也不自动改变课程完成状态。
