# 学习游戏：全课程效果应用覆盖

日期：2026-10-01。依据用户要求“学习的游戏开发项目里要用到课程里的所有效果”建立。

**这是必须达到的学习项目目标，不是已完成清单，也不是商业成品扩关批准。** 下方矩阵仍为完整目标用途；实际应用进度以 [progress.md](progress.md) 和本文件的证据记录为准。2026-10-02 M0 已接入部分 Shader 反馈，不能继续笼统写“全部尚未实现”，也不能据此宣布 48 小节完整覆盖。

## 1. 覆盖范围与完成口径

- 保留 [curriculum.md](curriculum.md) 的 6 Phase / 16 Chapter / 48 Section、前置与原掌握标准。48 小节并不等于 48 个 Shader 文件或 48 套玩法。
- 每个小节的核心知识有实际游戏应用；目录中明确列出的效果类型全部覆盖，包括原分支中的 3D 护盾与全息，以及水、草、风格化材质。原主作品的二选一/三选一仍用于确定深入独立作品，其余类型也需完成代表性游戏应用，不能从覆盖清单删去。
- “全部效果”不要求每一个可选挑战的参数、方向、配色和变体都成为新玩法；这些变体仍可用于练习。若新增独立效果类型，先补入清单，再安排依赖和应用。
- 单概念实验仍先做，随后接入可玩场景。只保存 Shader、在 Inspector 调参、播放演示视频、点击“展示效果”按钮，不算游戏应用。
- 应用必须与玩家事件、游戏状态、目标交互或可解释的环境状态关联，并有视觉职责、逻辑/材质接口和运行证据。持续环境效果不必强行变成按键技能，但要能在实际任务中观察其用途或状态变化。
- 多个效果可以服务同一任务，不要求同时开启。质量档位可以关闭重效果，但需保留能运行验证的学习场景、对应实现和应用证据；不能拿关闭或商业删减当作全覆盖完成。
- 课程掌握和游戏应用分别验收。小节可先完成原实验与解释，应用随后接入；最终学习目标须同时满足课程标准和本清单，不能提前宣称“全效果已用到”。

## 2. 两个可玩载体，不是两款商业成品

### A：2D《余烬采能站》学习版

沿用 M0 核心及未来经验证的商业探索方向。学习版增加两个可复用应用场景，是否保留在发行版另行评审：

| 场景 | 玩家目标、操作与结果 | 覆盖职责 |
| --- | --- | --- |
| 采能/维修场 | 移动、停留采能、判断预警、完成维修；受伤或失败可重试 | 范围、状态反馈、描边/柔光、溶解、能量环；雨、水流、热区及修复前后照明 |
| 远程维修终端 | 操作远端维修代理，校准观察/扫描装置，检查目标并恢复设备与通信；错误操作或代理失效可重试，成功返回现场 | UV 变换、局部屏幕观察、灰度/反色诊断、像素化、色散、CRT、Glitch；信号恢复后显示也恢复。不是效果选择菜单 |
| 小型通路训练任务 | 使用一次实际传送跨越隔断，再利用有限保护窗口操作危险区设备；成功开放出口，失败复位 | 扫描传送、2D 护盾、局部受击亮点、一次性冲击与转场；复用移动/交互/伤害，不做技能树、战斗或复杂敌人 |

终端与通路任务是应用候选，具体布局、失败规则和数值需教学与低成本试玩确认，不因为有覆盖表就假定玩法有趣。它们不是当前 M0.1～M0.5 的新增要求。

### B：小型 3D 可玩学习项目

候选主题为“恢复一座信标”。用简单几何体与少量低模，组织一个短路线/紧凑场地：观察全息目标 → 启动风机与水泵 → 通过有保护窗口的维修通路 → 恢复信标。角色有移动与交互，危险触发受击/失败；成功、失败、暂停与重开有明确状态。

水渠用于展示泵运行结果与通路边界；草片/叶片表现风向；风格化维修代理参与实际移动与交互；全息指引对应当前目标；护盾保护状态与接触亮点对应真实事件。材质、法线、光照和空间效果服务同一组设备，不做独立球体陈列代替游戏。

不要求第二款商业游戏，不新增开放世界、战斗 AI、长剧情或大规模模型制作。到 Chapter 14 的前置具备后再逐步准备，不现在创建项目、下载 3D 包或提前实现高阶 Shader。3D 场景可以与 2D 场景放在同一 Godot 工程中；“两个载体”不等于必须两个仓库或立刻改渲染器。

## 3. 48 小节应用矩阵

下面是计划用途，不是已存在功能。2D 指上述学习版；3D 指上述小型学习项目。表中应用可在先完成对应概念实验后逐步接入，脚本驱动仍需相应 Chapter 10～11 能力，不能绕过原章节依赖。

| Section | 载体与实际用途 | 应用验收重点 |
| --- | --- | --- |
| 01.1 | 2D 玩家/站点的纹理材质，作为正常游玩显示 | 场景能运行，节点—材质—Shader 连接正确；不是仅测试图 |
| 01.2 | 2D 停机设备灰度、修复后恢复原色，不同站点状态染色 | 状态驱动混合，0/0.5/1 与 Alpha 正确；与受伤反馈有优先级 |
| 01.3 | 2D 玩家实际受伤闪白/染色 | 伤害事件触发恢复，透明轮廓不变；独立课程运行已确认，实际游戏应用另验 |
| 02.1 | 2D 管线能量纹、水纹滚动，反映设备运行 | 控制流向/速度和采样边界，逻辑物体与范围不随 UV 移动 |
| 02.2 | 2D 终端中心缩放观察窗，帮助辨认维修目标 | 玩家操作影响观察，中心不漂移，目标判定不由画面缩放代替 |

| 03.1 | 2D 待机呼吸灯、采集脉冲，表示不同设备状态 | 周期/速度可解释；暂停后的关键状态与逻辑一致 |
| 03.2 | 2D 预警条带、终端扫描线与棋盘校准网格 | 重复频率和移动方向正确，条纹不能单独决定危险时间 |

| 05.1 | 2D 火焰/烟轮廓与水纹的不同 Noise 尺度 | 在真实设备上比较粗细信号，能说明选择与采样成本 |
| 05.2 | 2D 代理失败、设备关停时的 Noise 溶解 | 全显/全隐正确，结束接失败/隐藏流程，重开复原 |
