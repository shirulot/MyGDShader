# Godot 游戏 Shader 学习需求

本文定义课程目标、教学边界和验收标准。课程面向已有片元着色器与图像处理经验、但需要系统建立游戏 Shader 能力的学习者。

## 项目目标

课程以 Godot 为 Shader Lab。你会在制作可见游戏效果的过程中，逐步学会拆解、设计、编写、调试和复用 Shader。

2026-10-01 商业目标补充：伴随游戏以最终发展为可发布的商业独立游戏为目标，当前 Kenney 美术为可替换的临时资源。需要另行完善产品定位、持续可玩的内容、关卡变化、视听表现和成品质量；不能把换素材视为已达到商业成品标准，也不保证商业收入。Shader 学习仍为最高优先级，完整课程不因商业范围而删减；游戏开发继续由独立教学 Chat 逐步复习。

2026-10-01 方向确认：成品采用像素美术，偏氛围探索与轻叙事，接受必要交互与内容成本。区域数、任务数、总时长与高级视觉仍是待验证提案，不因偏好确认而自动批准完整内容制作。商业策划修订与验证状态见 [progress.md](progress.md)；完整提案见 [commercial-game-plan.md](commercial-game-plan.md)。

2026-10-01 全效果应用要求：学习的游戏开发项目必须实际使用完整课程的全部具名效果，不能以“只适合独立实验”为最终交付。用 2D 学习版和小型 3D 可玩学习项目共同覆盖，单概念实验仍先做，应用可随依赖延后但不能永久取消。商业发行版是否保留全部效果另行评审，不要求第二款商业成品，也不要求同屏叠满效果。原分支中的护盾/全息、水/草/风格化都要代表性应用，独立主作品的选择标准保留；可选挑战的每种参数变体不自动成为新游戏功能。逐节用途、验证与边界见 [game-effect-coverage.md](game-effect-coverage.md)。

完成课程后，你应能：

- 从一个游戏视觉效果反推 UV、颜色、Mask、Noise、距离场和时间动画等组成部分。
- 独立设计主要 Shader 逻辑，并用小实验验证每个假设。
- 将 ShaderMaterial、GDScript、Tween 和游戏状态连接为完整反馈。
- 在 2D `canvas_item` 与 3D `spatial` 场景中迁移通用知识。
- 判断何时自己推导，何时让 AI 查询 API、寻找资源、排错或减少重复劳动。

## 已有基础

课程会复用你在商业美颜 Shader 中接触过的知识，但不会默认这些知识已经熟练。

- 片元 Shader、纹理采样、`sampler2D` 和 UV。
- UV 镜像、旋转和二维坐标变换。
- RGB、YUV、HSV 和基础颜色处理。
- `mod`、`fract`、`smoothstep`、向量和矩阵基础。
- 白平衡、美颜和初步美型处理。

颜色、采样和 UV 操作会采用“快速复习后迁移”的方式。游戏状态反馈、透明轮廓、程序图案、2D 灯光、屏幕纹理、3D 材质和坐标空间视为游戏 Shader 新知识。

## 课程范围

2026-09-27 优先级补充：Shader 学习高于伴随小游戏开发。不得为了适配《余烬采能站》的玩法、美术、性能或开发范围删减课程知识、实验或降低完成标准。游戏不能容纳的内容继续在独立实验场学习；只有学习者明确要求，或通过原有抽查规则验证已经掌握后，才可跳过。游戏范围可以收缩，课程覆盖不能因此收缩。

课程从 Godot 2D `canvas_item` 开始，再进入 3D `spatial`。知识顺序遵循视觉操作、UV、时间、图案、Mask、Noise、扭曲、组合效果、游戏逻辑、屏幕效果和 3D 的依赖链。

课程覆盖：

- 2D 颜色、UV、动画、程序图形、Mask、Noise 和 Distortion。
- 灰度、闪白、描边、发光、溶解、像素化、CRT、Glitch、水波、热浪、传送、护盾、能量波和冲击波。
- ShaderMaterial、uniform、GDScript、Tween、实例参数、资源复用和性能观察。
- Screen Texture、环境效果、2D 光照和可调试的屏幕特效。
- 3D 表面材质、法线、光照、顶点动画、坐标空间、Fresnel、风格化渲染和组合效果。

## 教学契约

2026-10-06 长期反馈要求：每章结课时，教师必须整理学习者明确需求、有效协作方式、旧偏好变化、带来源的本章观察及下一章可执行建议。统合者核对后持续维护 [长期教学需求与偏好](learner-preferences.md)，并用于后续所有章节的交接，而非一次性针对下一章。已明确的需求不反复询问；暂时困难与掌握证据留在 progress.md，不变成人格/长期能力结论。没有新偏好也要写“无新增，沿用现行规则”。教师交付报告，不自行决定或新开下一章；此要求不降低课程标准或新增自动监控。

2026-10-07 自动交接授权：用户要求章节结束由子 Chat 自动回来通知统合者，让统合者继续调度。教师须在结课同轮保存带习惯反馈的报告，并向指定统合 Chat 主动发送；统合者核对后在既定课程范围内选择下一段 C/M，一次新开一个 Chat，普通结课不再等待重复“继续”。详细人类来源、接收方、失败与去重规则见 [交接协议](handoff-protocol.md)。教师不得自行开章；Section 确认、核心练习、验收标准、重大选择需询问和商业/游戏边界均不变，不新增定时轮询。

每个 Section 原则上只引入 1～2 个核心概念。章节 Chat 按“观察 → 概念与做法说明 → 目标 → 尝试 → 按需提示 → 编写 → 运行 → 解释 → 修改 → 再观察”推进；尚未讲清的新概念不能只给目标、反复要求自行实现。

教学期间必须遵守以下规则：

- 每节都优先产生可立即观察的视觉变化。
- 先说明新概念是什么、输入输出和本次具体做法，再给目标、约束与验收，由你编写关键逻辑；已理解的内容可直接进入小目标。
- 不默认提供 30～50 行的完整答案。
- 每次只添加足够验证当前假设的最小改动。
- 数学随效果引入，不单独铺设脱离视觉目标的数学课。
- 章节 Chat 负责教学；统合者只管理路线、状态、依赖和交接。

只有在你明确要求、代码已严重混乱、实现不是当前学习重点，或效率明显高于教学价值时，章节 Chat 才可给出完整参考实现。给出后仍需标记关键逻辑，并安排一次由你独立修改的验证。

### 已确认的协作偏好（2026-10-02）

来自用户在 M0 教学中的明确要求与经验证的互动，适用于后续游戏开发和 Shader 教学：

- 默认先给当前一步的具体需求、约束和可运行验收条件，让学习者自行实现。用户原话：“你说出需求我不懂再问你好了。”不主动逐行铺好答案；用户问机制时再给局部 API、短提示或必要注释。
- 每次只推进一个小目标，定期说明当前剩余项；“需要更具体的需求”不等于“需要完整代码”。不要在里程碑收尾时无限增加可选修整。
- 代码审查先读取最新保存版本，以自然执行顺序和正常运行证据为准。区分复现错误、静态风险、可选整理与延期，不用人为停止 Timer 等异常条件宣称正常流程有错。
- 解释模板、Autoload、信号和架构变动的实际职责与依赖；保留已验证满足目标的替代实现，不强制统一回最初方案。
- Shader 是当前学习目标时，不以 `Sprite2D.modulate` 替代核心练习；已有用户代码、运行有效的闪烁/错峰方案和确认延期项均应保留，具体记录见 [progress.md](progress.md)。
- 这些是当前教学偏好，不是性格判断或全概念掌握证明。新增必做范围、重构或重新推翻验收前，先给证据与理由，不自行扩大 M0。

2026-10-04 C02 交接补充：数学按零基础节奏，一次只引入一个小概念，以具体数字/像素距离和可见结果解释，不凭已有 vec/mat 经历推定理解。用户选择先用旋转模板，矩阵含义、乘法与推导在独立数学补课 Chat 继续；模板使用、提示后的修改及独立推导必须分别记录。C02 应用主练习通过不等于矩阵推导已掌握，延期推导也不删除后续坐标/空间的原完成标准。

### 当前教学调整（2026-10-05；2026-10-06 补充，优先于旧偏好）

依据 C03 人类用户明确反馈与 [教学反馈记录](chapter03-teaching-feedback.md)：

- 新概念先讲清“是什么、输入输出、怎么做”，用具体数字和可见结果说明局部方法，再让学习者写。不得以只有需求或反复提问替代必要讲解；不必等学习者多次卡住才解释公式/API。
- 已教过或学习者明确熟悉的概念，先给精确需求与文字方法，让其自行实现；未求助时不主动贴实现代码或已学公式。新概念所需的局部说明与 API 参考仍可提供，不把两种情况混为一谈。
- 每次需求都明确对象、数值、单位、变化方式和预期画面；例如说明亮度系数作用于 RGB 而非 Alpha。用户要求“具体点”不是索要代码，不能因此代写答案。
- C04 方法补充：每步说明旧逻辑保留/替换/仅留档的部分和最终输出；复用已学代码先讲本步需求与输入职责，不只让学习者复制。审查必须给具体结论，同一小步无问题再推进、有问题停留；Section/Chapter 的授权边界不变。最新长期规则以 learner-preferences.md 为准。
- 按需要给公式、局部代码或完整参考，说明各步职责并如实记录提示级别。关键逻辑仍由学习者写入、解释和修改验证；使用参考不登记成独立推导或任意范围迁移。
- 教师可协助搭场景、准备纹理与材质连接；练习 Shader 起点只保留默认纹理采样，未获要求不把效果答案预写进文件。不默认代写整个游戏或已学效果的集成代码。
- 学习者说“好了／写完了”时，按其已正常运行确认处理，教师主要检查最新保存逻辑；不重复索要同一现象。必要的新接口/回归验收可以明确提出，但不补造未报告的参数组合、测量时间或测试次数。
- 一次一个小目标，数学一次一个小概念；课程掌握、参考提示后的修改、独立推导和游戏应用继续分别验收，完成标准与全课程范围不降低。

## 实验与资源原则

2026-10-06 素材选择：用户要求后续游戏采用其新生成的像素机器人与地板，明确游戏不是 Shader 练习的强制换料要求，随后补充“如果练习用到素材也可以试着用一些，这个看你来决定”。因此，后续游戏搭建和真实效果接入默认使用项目自制像素素材；旧 Kenney/测试角色保留历史与对照，不作为后续游戏正式视觉的默认选择。独立练习由教师按当前概念选用：角色闪白、描边、溶解等适合时可试用新机器人，地面采样/流动/扭曲等可用新地板；需要暴露 UV、通道或数值问题时仍用 Test Sprite、UV Grid、ColorRect、Mask、Noise 等最小资源。不得为了统一美术少学内容，也不因换料打断已开始的实验。当前 C04 起点与已验收 M0 不自动改写；下一次实际游戏接入时安排最小美术连接并验证锚点、比例、Alpha、材质隔离和重开。最新素材入口见 [资源计划](resources.md)，这不是全部候选素材的最终美术验收，也不批准扩关或降低课程覆盖。

Godot 场景是所有概念的验证环境。每个实验必须有一个肉眼可辨的结果和一个明确的完成标准。

- 优先程序生成 UV Grid、Checkerboard、Gradient、Circle Mask、Noise 和颜色测试图。
- 每节只准备完成当前实验所需的最低限度资源。
- 外部资源优先使用 CC0 或明确允许免费商用的许可。
- 所有外部资源必须在资源台账中记录来源、作者、许可和使用位置。
- 找不到合适资源时，可以生成仅服务于当前实验的资源。

## AI 使用边界

持续教学偏好：学习者希望同时复习游戏开发。统合者按需安排独立游戏开发教学 Chat，与 Shader 章节 Chat 分工。游戏场景、输入、碰撞、状态、UI 和脚本也采用学习者尝试、分级提示、运行验收的方式，不默认由 AI 一次性实现整款游戏。Shader 学习仍是最高优先级，游戏教学不删减或替代课程实验。

AI 可以帮助查询 Godot API、准备测试资源和场景连接、讲清新概念及实现方法、解释编译错误、定位问题和审查代码。关键 Shader 逻辑由你在必要说明后编写并说明思路，不要求在概念未知时凭空尝试。

章节 Chat 不应因 AI 能一次生成最终效果而跳过拆解过程。排错时先帮助你定位现象、输入和假设，再给最小修复提示。

## 初始统合阶段限制（历史边界）

以下是创建课程时的统合任务限制，不否定之后人类用户已授权的章节与游戏教学；统合者本身仍不代替章节教师编写练习代码。

当前阶段只允许建立需求、课程、依赖、资源、进度和章节 Chat 模板。

当前阶段不得：

- 开始 Chapter 01 教学或讲解具体 Shader 知识。
- 编写正式 Shader 教学代码。
- 替你完成练习或创建大量场景。
- 下载大量资源或一次生成完整效果。
- 未经确认自动推进任何章节。

## 课程完成定义

课程级完成不以“看过全部内容”为标准。你必须完成各章核心实验，并能在有限提示下完成综合任务。

最终证据包括：

- 一组从单概念实验逐渐演化出的 2D 与 3D 游戏效果。
- 至少一个由游戏状态驱动的 2D 反馈链路。
- 至少一个使用屏幕纹理的高级 2D 效果。
- 至少一个组合了材质、顶点或坐标空间知识的 3D 效果。
- 能口头或书面拆解陌生效果，列出输入、空间、Mask、动画和组合顺序。

学习项目另需完成 [全效果应用台账](game-effect-coverage.md)：为 48 小节核心知识与全部具名效果提供真实可玩用途、实际文件、参数/事件接口和运行证据。课程掌握与应用分别验收，不能仅凭效果代码或展示按钮宣称完成用户的全覆盖目标。
