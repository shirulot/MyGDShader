## 典型错误与排错过程

1. 纹理 Mask 的灰度数据与最终颜色目标曾混在一起；通过区分权重与白色混合目标修正，原 Alpha 始终作为单独输出检查。
2. 04.2 最初将 `feather` 直接用作 smoothstep 内边界。明确实际语义后接受有效变体，按外边界减内边界理解宽度；当前显隐同时影响 RGB 和 Alpha，也如实保留为变体。
3. 04.3 曾在相加时保留差集的条带反转、在圆减星形时沿用旧并集底形、在交集时保留星形反转。教师此前没有充分交代旧逻辑的去留，是这些切换困难的教学原因之一。之后明确本步输入、保留/替换项和最终输出结构，学习者完成修正。
4. 圆图大部分为 0/1，灰度边缘很薄。接受用户对 min/乘法视觉近似的观察，不强迫其从薄边中寻找明显差异；相加实验临时将圆权重乘 0.5，以便观察灰度叠加。
5. 两次读取到 04.3 Shader 回到默认采样起点，原因未确认。一次由用户恢复，另一次按刚审查通过的学习者版本恢复，并补回星形 uniform。随后直接检查 Shader 参数列表与材质纹理绑定，确认星形为 256×256；检查前后源文件未变化。不能把场景加载无报错当作所有参数已连接的证据，也没有证据将回退归因于用户操作。

当前 04.3 的 `newUV`、旧圆纹理采样和旧并集计算没有接到最终输出，属于可选整理，不阻塞验收。04.2 的原 Shader 默认值为外边界 0.25、内边界 0.30，顺序不符合当前软边圆定义；现有材质覆盖为 0.40/0.35，实际练习有效。报告不宣称将 Shader 直接用于新材质时的默认配置已通过，也不要求本轮为了整理而回改已接受练习。
