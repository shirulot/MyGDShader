## 定位与玩法

面向正在学习 Shader 的开发者，先做桌面键盘操作、单屏俯视角、约两分钟一局的小型采能游戏。沿用现有 720×720 实验环境与机器人图片。玩家操纵维修机器人，在三个固定采能点之间移动，趁安全窗口停留采能，并在危险爆发前撤出。

核心循环：观察各点状态 → 选择目标并移动 → 停留采集 → 判断是否继续冒险 → 撤离并转向下一个点。累计能量达到目标即获胜；生命耗尽或倒计时归零则失败，可以立即重开。

主要决策是：预警已经出现，是继续采一点还是立即撤离？靠近危险点、估算离开范围的时间与切换路线，构成玩法挑战。

## 最小规则

首版用一套规则证明可玩性，数值通过实际试玩调整。

| 项目 | 规则 |
| --- | --- |
| 输入 | WASD/方向键移动，R 重开；不用鼠标瞄准 |
| 采能 | 位于采能范围内且停止移动时自动累积；离开即停止；得分即时累计 |
| 站点状态 | 安全采能 → 预警（仍可采能）→ 危险爆发（不能采能）→ 冷却（不能采能）→ 安全采能 |
| 布局 | 三个固定点呈三角分布，危险范围不覆盖整个场地，保留可撤离区域 |
| 节奏 | 阶段时长固定、三站错峰；2026-10-02 已接受随机初始 BURST/COOLDOWN 与随机延迟启动，初始化期间关闭物理逻辑，不强制改回原固定相位 |
| 受伤 | 进入爆发范围或爆发开始时仍在范围内，扣一格生命；短暂无敌避免一帧内重复伤害 |
| 胜负 | 能量达标获胜；生命归零或超时失败；同帧事件优先级为旧目标，用户已明确延期，不作为当前 M0 收尾阻塞 |
| UI | 菜单开始 → 游玩（生命、能量、时间）→ 结果 → 重开；操作说明已由用户延期 |
| 重开 | 重置机器人、站点阶段、能量、生命、倒计时、无敌及所有视觉参数 |

不增加背包、存款、射击、敌人 AI、技能树、Boss、随机地图和多关卡。主循环稳定后再讨论任何新机制。

初测数值：120 秒、3 格生命、目标 380 能量；安全 3 秒、预警 2 秒、爆发 2 秒、冷却 2 秒，三点相位各错开 3 秒。采集速度每秒 5，点间距约 260 像素，移动速度每秒 200 像素，采集半径 55、危险半径 80 像素，无敌时间暂设 1 秒。这些是试玩起点，尚未验证目标可达性。单点每 9 秒最多采集 5 秒，120 秒内单点理论上限约 340 能量；380 的目标用于鼓励换点，若无伤路线无法达成则下调目标或增加采集窗口。允许玩家学会固定路线，不为打破最优解预先增加随机系统。

## Shader 与脚本分工

“纯着色器加少量素材”在本方案中指主要视觉由 Shader 制作。输入、碰撞、采能、计时和胜负保存在简单 GDScript 中。Shader 输出不能作为游戏判定的唯一来源。

- Shader：地面网格、能量流、范围与预警、局部热浪、轮廓光、溶解、冲击波。
- 简单素材：复用现有机器人 PNG；早期圆点/方块可用基础节点；UI 使用 Godot Label。
- GDScript：移动、范围判断、状态机、计分、伤害、胜负和重开；用少量参数把真实状态传给 Shader。
- 共享数据：危险中心、判定半径和阶段进度必须与视觉来自同一组逻辑数据。`TIME` 可用于装饰流动，不能独立决定伤害时刻。
- 每个站点单独管理显示状态，避免一个点预警导致所有点同时变化。发光外缘不算伤害区域，危险边界必须可识别。

## 试玩与范围控制

先检验占位画面的规则，再评价 Shader 美术。M0 核心功能及重开已通过教学验收；下方风险收益、路线效率与未来暂停联动仍需对应试玩，不表示商业可玩性已通过。

- 玩家只看现场预警即可撤离，受伤位置与显示边界一致。
- 两分钟目标应鼓励切换站点；守一个点的效率明显更低，但移动路线不要求精确逐帧操作。
- 对比一局保守撤离与一局贪采，观察能量、受伤次数和失败原因，确认有可理解的风险收益。
- 连续重开三次不继承上一局状态已通过，三种结果和游玩中均有证据；未来接入暂停时再核验逻辑预警与显示进度一起停下，不追溯为当前 M0 必做。
- 增加每项效果前先明确用途；不适合商业主流程的效果在可玩学习任务寻找合适应用，不能只留实验场。先低成本验证用途，不靠堆同屏效果掩盖玩法缺口。
