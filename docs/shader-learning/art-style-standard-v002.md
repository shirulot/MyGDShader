# 《余烬采能站》美术规范 v2：原生像素与连续场景

日期：2026-10-06。地板部分已被[参考效果生产标准 v002](reference-floor-v002-production.md)补充：用户要求交付素材实际拼出效果图，因此新地板改为128纹理／32世界格／0.25层缩放、二格宽桥。以下32原生格与单格桥建议属于早期方案；角色／设备和颜色方向仍供参考。

完整建筑另按[建筑样式与交互规范 v002](../../assets/ember/buildings_final/docs/ember-building-standard-v002.md)执行，以选中完整母图、最终注册、同源功能层及实际交互为准；独立建筑使用自身登记缩放。

UI 以[边缘标记 UI 专项规范](ember-ui-style-guide.md)为现行唯一详细规范，尺寸、字号、九宫格、横排生命和完整交互流程均以该文及实际 inventory 为准；本文仅保留共同材料与状态语义。当前通过范围及独立复验入口见 [UI 最终资源入口](../../assets/ember/ui_final/README.md)，新规范不扩大 v006 原验收范围。

角色动作与方向按[TA 审查规范 §3.3](ta-art-review-standard-v001.md)中的最新补齐清单分批生产；本文第6节四向/20帧为早期建议，不覆盖当前机器人24段/112帧与敌人160段/960帧目标，也不表示新增方向已通过。

本规范依据本轮用户反馈制定，优先于旧生产文件中的写实金属、128px 瓦片、强制逐格边框等要求。它约束后续新资源，不自动改动现有图片、场景、碰撞、视口或课程进度。

## 1. 参考范围与当前问题

用户确认 [原生比例板 full_native_scale_v003](../../art-source/ember/references/full_native_scale_v003.png) 是可接受的像素基准，随后明确其中的地板仍不满意。

| 内容 | 本轮如何使用 |
| --- | --- |
| 比例板中的机器人、采能站、门、控制台 | 参考像素簇、形状、装甲与钢材关系、统一比例；不是要求直接复用所有旧成品 |
| 比例板的配色与原生像素尺度 | 新规范的基准；允许有记录的小幅调整 |
| 比例板中的四种地板 | **重新设计，不作为已认可的地板样稿** |
| Kenney | 保留当前运行用途和来源记录，不作为这套自制美术的造型基准 |
| v003～v007 自动瓦片及 v008 correction 样稿 | 历史技术与失败案例；不把“配置通过”当作风格认可 |
| 新角色 Rivet、旧角色修复动画 | 保留历史资源；本轮不据此切换玩家形象 |

当前视觉问题是风格与尺度漂移：原生像素设备、光滑高分辨率金属和细密划痕混在一起；地板重复小框、亮边或铆钉后容易抢占注意力。当前技术问题是部分构件各自生成，接头宽度、板缝与明暗不一致。后续先验证一个完整小场景，再扩展数量。

## 2. 视觉方向

方向：**安静的旧工业维护站，清楚的像素块面，克制的材料与状态色。**

- 俯视三分之四正交视角：看到顶面与少量正面；地面方格横平竖直，无消失点。
- 机器人和设备沿用同一制造语言：浅色装甲、蓝灰结构、圆筒或圆角外壳、少量黄铜接口，工具感明确。
- 基础图采用少量可辨认的明暗块，轻微左上体积光；接地影、灯光、发光和天气单独控制。
- 地面以连续低对比底面组织路线；设备提供结构细节；状态提示提供高对比。
- 阅读顺序：玩家与危险边界 → 当前交互目标 → 可走路线 → 环境装饰。
- 维护痕迹集中在功能位置。锈、裂纹、油渍和杂物按场景布置，不均匀铺满每张图。

## 3. 像素尺度、尺寸与锚点

新套资源建议采用 **32×32 原生纹理 = 32×32 世界格，TileMapLayer scale=(1,1)**。这与所选比例板一致，避免将 128px 细节压到 32 世界单位后出现不同的像素密度。该选择是本次设计规则，不是已实施的工程迁移。

现有 128px/32世界格/0.25 资源继续保留。新套建立独立 TileSet；不能只替换 PNG 然后沿用旧 atlas、缩放和碰撞配置。模型生成大图可以作为设计原稿，正式 PNG 必须在目标原生尺度整理与验收，不能靠 Nearest 缩图宣称像素美术完成。

| 资源 | 正式画布 | 最大主体或占地建议 | 固定锚点，坐标为原生像素 |
| --- | --- | --- | --- |
| 面状地形、单格网络构件 | 32×32 | 见[瓦片专项规范](autotile-production-standard-v002.md) | 网格原点；开放接头到画布边 |
| 玩家每帧 | 64×96 | 主体约40×64；固定画布 | 脚底 `(32,80)` |
| 采能站 | 128×160 | 主体约96×128；地基约3×3格 | 基座 `(64,144)` |
| 控制台、小设备 | 96×96 | 主体约64×64 | 基座 `(48,80)` |
| 泵、排热、冷却设备 | 160×192 | 主体约128×160 | 基座 `(80,176)` |
| 中继核心 | 192×256 | 主体约160×224 | 基座 `(96,240)` |
| 开关门 | 96×128 | 两态共用门框与占地 | 基座 `(48,112)` |
| 灯、记录载体、小道具 | 64×64 | 主体不超过48×48 | 接地点或安装点逐项登记 |
| HUD／任务图标 | 状态图标32×32；其他按UI专项清单 | 角件、生命槽等有各自尺寸 | 按组件布局登记，不套世界锚点 |
| UI 九宫格 | 面板等96×96；轨道与强调线另有尺寸 | 按UI专项规范及inventory逐项登记 | 不将四侧margin=8套到全部皮肤 |
| 水纹、泡沫、烟形 | 64×64 | 水纹平铺；烟与泡沫真实透明 | 登记平铺轴、发射点和覆盖范围 |

画布、接地点和碰撞占地分别记录，不能拿整张 PNG 的透明边当碰撞。设备以基座接地点参与遮挡；高处外壳和前景部件可拆层。图标用屏幕尺度，不强行套世界坐标。

当前工程是 720×720、`canvas_items`、Compatibility；本轮保持原配置。后续像素场景先在该视口以 Nearest 验证，再评估整数倍率的演示尺寸。不要直接把旧规范的 960×540 写入主工程。

## 4. 配色、明暗与像素簇

下列是共享锚定色，不要求每张图都用满，也不要求导出文件恰好只有16种 RGB。必要的增补色记录用途与共享色阶；禁止每批重新产生一套偏色钢材。

| 材料／语义 | 色阶 |
| --- | --- |
| 轮廓与结构阴影 | `#101820` → `#182631` |
| 蓝灰涂装钢 | `#2B3E4B` → `#4D6470` → `#829BA3` |
| 浅装甲／陶瓷 | `#829BA3` → `#BECBC4` → 小面积 `#ECE9D8` |
| 铜锈／黄铜 | `#7B4D35` → `#B77C4B` → `#E2B77A` |
| 低对比水底 | `#203A4B` → `#406B78` |
| 可操作／能量 | `#51C5C2` |
| 预警／危险／冷却 | `#E5A44B` ／ `#E65B4A` ／ `#566B78` |

- 一种材料通常用3～4个主要明暗层，边缘高光只占小面积。地板主体主要使用钢材暗部与中间色。
- 用连成片的色块表现体积和磨损。涂装钢可采用认可场景中的低振幅细颗粒，但避免均匀高对比撒点、满面刮痕、柔焦和连续写实渐变。当前地板实际取样材质以 `#4B6876` 为中心，5阶增补记录在[材质处理 JSON](../../art-source/ember/pixel-standard-v002/floor-production-v001/material_processing_v002.json)。
- 主体轮廓通常1px，较大设备局部可2px；内部线更低对比，不能每块板面都描黑框。
- 静态颜色图的实体像素 alpha=255、真实透空 alpha=0。烟、光和特效另用连续 Alpha；Normal／Mask／Noise 不套美术色板。
- 圆角通过清楚的像素阶梯表现，跨朝向共享曲率；固定左上光照下的成品不能直接旋转冒充新方向。
- 装饰灯与黄铜避免占用预警和危险的视觉强度。灰度查看时，玩家与当前危险边界仍须读得清楚。

## 5. 地板重新设计：连续底面，边界收口

旧比例板的地板只保留材料家族，重新设计内部组织。首选 **低对比涂装钢底面 + 外露边梁 + 局部功能铺装 + 独立维护贴花**。

| 部件 | 新设计规则 |
| --- | --- |
| 连续中心 | 大块蓝灰中间色；少量成簇变化。左右、上下衔接后不能出现每格独立的厚框、明暗斜坡或四角铆钉 |
| 内部板缝 | 0～1px、低对比；如经过格边，登记两端位置并贯通。基础笔刷不强制每32px画满一圈板缝 |
| 外露收边 | 2px总宽的低对比面板切边，只出现在地板对非同类格的闭合周界；连接到同类地板的一侧无端帽。切边不做厚结构梁，水边的8px结构岸体由水域笔刷负责 |
| 金属高光 | 集中在外边、功能构件和少数转角；连续中心不使用陶瓷亮色或密集黄铜 |
| 格栅 | 用于栈桥、检修区、排水功能带；统一条距，控制密度，普通大地面不全铺格栅 |
| 磨损／湿面 | 裂痕、油渍、锈迹是独立贴花；湿润由局部 Mask 与材质控制。普通中心不反复烘焙同一伤痕 |
| 大板节奏 | 如以后采用64px或更大的连续板缝，须使用确定性地图相位或独立装饰方案；随机选47型的变体无法保证大板相位一致 |

基础地板只做一套完整结构。整洁、磨损、湿润先通过装饰与状态表达，不先复制四套近似底图。对每一张地板先看6×6以上的整片效果，再看单块精细度。

地板效果的验收目标：角色和站点站上去更清楚；路径边界有结构，区域内部安静；在普通游戏尺度下看不到规则性的亮框、明暗棋盘或铆钉阵列。

## 6. 人物、设备、UI 与特效

### 人物与设备

- 首版保持比例板的紧凑维修机器人与浅装甲设备家族。明确四向轮廓、工具侧与固定锚点，再补帧。
- 基础动画为四向待机各1帧、四向行走各4帧，共20帧，8 FPS作为预览起点；不因单张参考确认就视为全部动画通过。
- 左右工具有非对称性时独立制作；禁止自动裁切造成帧间跳动。整体轮廓、脚底和色阶在全循环内稳定。
- 设备共用圆筒、矩形基座、模块面板与黄铜接口；一台设备只保留1～2个主要视觉焦点。
- 底座、外壳、灯窗、活动门板、前景遮挡、接地影分别登记；开关态保持相同安装点与碰撞契约。

### 状态与 UI

| 状态 | 颜色与形状组合 | 底图职责 |
| --- | --- | --- |
| 安全／可采集 | 青色稳定点或环；采集时轻微脉冲 | 中性灯窗与结构轮廓 |
| 预警 | 橙色条带／分段边线 | 不烘焙预警色 |
| 危险爆发 | 红色清楚边界＋实心或方向性标记 | 不烘焙爆发火焰 |
| 冷却／停机 | 低亮蓝灰、暗轮廓 | 设备仍可辨认 |

状态显示与判定来自同一逻辑数据；外部光晕不扩张实际危险边界。图标和状态还须用轮廓、纹样或节奏区分。

UI 使用已选 A「边缘标记」的细线、开放角括号、深蓝灰底、米白文字、留白与少量黄铜，生命指示保持横排。具体配色、字号、组件尺寸、九宫格和焦点/输入契约统一查阅[UI 专项规范](ember-ui-style-guide.md)，不从设备浅装甲外壳推导厚重 UI 边框。文字由 Godot 字体呈现；皮肤、数据、交互和遮罩分别承担已登记职责。历史 A 图的竖排生命已被用户后续要求覆盖。

### Shader 与技术输入

- 彩色底图只承担材料与轻微体积。水波、雨、火焰、热浪、发光、受击、溶解、护盾和屏幕效果保留独立控制。
- 配套 Mask 必须与正式底图具有一致画布、锚点、裁切与 atlas 注册；发布目录注明每个通道、数据范围和采样设置。
- 水纹、噪声、溶解图标明平铺轴。水域、热区、露天区 Mask 由实际地图布局派生，不能拿旧设备 Mask 代替新版几何。
- Normal 与高度图根据已定稿几何派生并核对方向；所有数据图不受16色与二值Alpha约束。
- 当前渲染路径不以 Bloom 为前提，关键发光在 Compatibility 下也必须可识别。
- 本规范不删减课程效果，也不代写学习者 Shader。未来3D纹理延续材料家族，仍按独立3D输入规格交付。

设备区域Mask沿用已登记的通道职责：`R=局部换色`、`G=发光`、`B=允许扰动`、`A=底图Alpha`。新版几何须重新派生；色彩图与数据图分别设置色彩／线性采样，按实际Shader采样流程验收。

## 7. 生产顺序与交付

1. **结构样本**：新地板的中心、四向直边、外角、凹角、孤岛、窄路、T口；先以灰色语义模板确定共享接口。
2. **风格小样**：新地板6×6试铺、机器人、采能站、控制台同尺度对照。只比较新版地板，不拿旧地板替代新设计结果。
3. **首套自动笔刷**：地板47型全部完成、实际铺刷验收；同步测试一套管线16型和水岸关键案例。
4. **可审阅小场景**：一块维护前庭，含可走路径、边界、一个设备、少量贴花、角色和最小HUD；正常显示与关闭效果都检查。
5. **扩展资源**：再补水岸47、墙体47、栏杆与单格栈桥16、门与灯、动画、UI、配套数据图。商业四区先保留预算，避免在玩法尚未确定时批量扩图。

新稿建议放在 `art-source/ember/pixel-standard-v002/`，正式入库目录另行在验收后建立。保留原稿、提示词、参考范围、裁框、整理步骤、版本、SHA256、结构登记、Godot检查证据和拒收原因。

生产提示词必须分清参考职责：比例板只约束角色、设备、配色与像素尺度；新地板按本文第5节重新设计。结构模板只表达邻接与端口，不当作最终造型。每次写明目标原生尺寸、真实Alpha、固定光照、禁止内部封端／重复外框、独立动态层，以及该批仍是候选。不能把“像素风、工业、无缝”三个词当作完整生产要求。

采用状态分开记录：`SOURCE_CREATED` → `PIXEL_FINISHED` → `CONNECTIVITY_PASS` → `ENGINE_PASS` → `VISUAL_CANDIDATE` → `USER_ACCEPTED`。候选文件存在、图块数量齐全或自动选块正常都不等于用户接受。

生产前阅读 [瓦片专项规范](autotile-production-standard-v002.md)；参考 [可视规范页](art-style-standard-v002.html) 查看新地板结构意图与47／16邻接表。页面中的色块与几何都是规范示意，不是新资源交付。
