## 1. 玩家最终会看到、会做什么

你操纵一台小型维修机器人，走进一座停机的工业能源设施。画面是俯视像素场景：暗蓝钢板、失去供电的指示灯、露天平台上的雨、桥下持续流动的冷却水，以及热处理区尚未排尽的余热。角色、设备和地形有明确轮廓；Shader 让能量沿管线移动，让水面、火焰和状态反馈活起来。

平时可以慢慢探索，不挂着全局倒计时。你检查一块控制台，读到几行维修记录，找到需要恢复的设备，再主动启动一次短暂抢修。任务中，几个采能站依次经历安全、预警、爆发和冷却；你在站内停下充能，判断还能否多等一点，然后撤到安全地面、换另一个站。能量达到任务要求，设备恢复，场景发生可见变化：灯亮了、泵开始运转、积水退去露出维修通道，或通信天线重新工作。

例如进入露天泵区时，你先沿栏杆看到水渠上的旧桥，检查旁边的排水控制台。启动任务后，近处站点安全、远处站点正在冷却；你先采近处，预警条带出现后撤出，从桥绕到另一站。完成任务后，原先被淹的维修走道开放，你发现一条说明当年停机原因的短记录，并继续前往热处理区。失败只重试这次抢修，已经完成的维修和读过的记录保留。

这是一段通过维修逐步理解设施的旅程。主线叙事暂定为：当年的值班人员为了隔离异常能源主动停机；机器人逐步恢复安全系统，最后把未发送的维修记录传回外界。没有分支结局、长对话或大量角色。具体故事文字在垂直切片验证氛围后再定稿。

## 3. 产品定位与范围上限

**目标体验：安静观察设施，短暂冒险取能，再亲手看到设施恢复。** 主要卖点假设是“维修带来的环境变化”和“可读的能源状态”，而非效果数量。是否能吸引玩家，必须用实际切片验证。

| 内容 | 首选范围 |
| --- | --- |
| 主线结构 | 4 个区域，合计约 10 个手工制作的屏幕/小房间，6 次必要抢修 |
| 角色 | 1 个玩家机器人；不做敌人 AI、战斗、NPC 日程 |
| 交互 | 检查设备、读短记录、启动任务、打开修复后的通路 |
| 叙事 | 10 条短记录，暂按每条约 80～150 汉字、1～3 个短段落；核心信息在主路，补充信息在小支路 |
| 任务时长 | 教学任务约 60～90 秒；商业压力段先对比 90～180 秒与原 180～240 秒上限方案，不统一锁为 3～4 分钟；按变化密度、路线与失败成本确定 |
| 整体时长 | 暂不承诺。记录新玩家的探索、阅读、失败与通关时间，再判断内容是否足够 |
| 成长 | 维修完成标记、路线开放、环境恢复、记录发现；不做技能树、装备经济或数值养成 |
| 重玩 | 可从任务列表重试已完成抢修，分别保存最快完成与无伤完成记录；不是通关必需 |
| 排除项 | 无限随机地图、Boss、背包搬运、建造模拟、动态火灾、水体物理、分支剧情、联机 |

四个区域仍属于同一工业设施，复用地板、管线、栏杆、控制台和站点。每个区域只增加少量特有标识、地形组合、环境层与声音。约十屏是内容预算上限假设，不能用十张几乎相同的图充数。

### 3.1 时长与可玩性的修订：以区域过程为单位

2026-10-01 用户指出单局周期偏短的疑虑。确实，原案还没有证明玩法深度：如果采用旧 9 秒四阶段周期，每个站点在 180～240 秒任务里会循环约 20～27 次；路线固定、后续选择不变时，延长任务只会增加等待。短也不能自动证明节奏紧凑。

需要区分三层：站点的秒级状态循环、一次采能的压力段，以及由探索/维修/环境变化组成的区域过程。3～4 分钟原本是抢修的候选失败上限，既不是整段游戏的长度，也不应是所有任务固定的长度。按一个 60～90 秒教学任务加五个 180～240 秒常规任务算，计时上限合计也仅约 16～21.5 分钟，熟练完成可能更短，不能据此宣称商业内容已足够。

首选修订是让 B 区现有两次维修构成连续过程：观察桥与水渠、判断路线 → 排水抢修 → 新走道开放 → 安全探索与检查冷却控制台 → 利用改变后的路网完成冷却抢修 → 管线恢复、进入下一地区。成功时用现场反馈继续探索，不每次强制退出到成绩菜单；失败仍保留明确结果与快速重试。六任务与屏幕预算暂不扩张，也不把所有任务一律变成多段。

泵区暂以 **8～12 分钟完整区域体验**作为切片观察假设，不是必须填满的时长。其中第一次抢修可试 90～150 秒，第二次在新通路上试另一组相位。桥路较短但撤离空间窄，外围路较长但安全平台更多；排水后新增走道改变两站之间的距离与撤离方向。要让玩家重新判断，而不只是给同一操作换背景。若玩家更快完成仍感到充实，不用延长采集；若觉得空洞，修订空间与选择，不能靠提高配额、长文本、来回走或反复死亡补时间。

切片比较原连续 3～4 分钟采能与两次短压力段加中间环境变化，保持区域资源与路线预算相近，分别调至合理难度。记录：玩家改变计划的时刻、连续空等时间、相同操作重复轮数、修复后主动探索行为与继续意愿。每个区域应有真正影响下一步的修复结果；每次任务应有可解释的路线取舍。允许玩家学会固定路线，不为强迫重新判断而添加随机打乱。

总游玩时长仍待测，四区/六任务只是首轮内容预算。若切片表明探索和抢修无法互相支撑，先改核心设计，再讨论扩关。可参考开发者对小型探索世界的关卡、美术和写作取舍复盘，但它不是本项目可玩性或时长的证据。[《A Short Hike》作者的 GDC 复盘介绍](https://www.gdcvault.com/play/1026613/Independent-Games-Summit-Crafting-A)

## 4. 操控、循环和规则

### 4.1 操控与 UI 流程

WASD/方向键移动；E 检查、确认、启动控制台；Esc 暂停；任务失败后以界面确认或 R 重试。输入动作需可改键，手柄作为后续有条件支持项，不把未测试支持写进发布承诺。

流程为：主菜单 → 继续/新旅程 → 安全探索 → 检查任务面板 → 主动启动抢修 → 现场完成反馈 → 修复后探索 → 下一地区。成功不强制打开成绩页；失败显示结果并允许重试。任务列表用于回玩；暂停可以继续、设置或退出到菜单。读记录时暂停任务压力；首选设计把记录交互放在任务外。M0 仍保留其简单结果/重开流程。

### 4.2 安全探索

探索期间站点处于待机，不能采能，也不释放伤害。水渠、栏杆和设备是清楚可见的静态通行约束。没有隐藏的雨天减速、打滑或随机伤害。主路指向当前维修目标，每区至多一条短支路，并放在既定屏幕预算内。

每完成一次维修保存进度；已读记录及时记入存档。失败、退出任务、重新加载都不撤销已完成维修。再次进入任务从安全入口开始，生命和任务状态重置。

### 4.3 抢修规则

| 规则 | 首选规格与理由 |
| --- | --- |
| 启动 | 从危险范围外的控制台主动启动，先展示目标与站点概况，并留准备时间；不在读文字时突然开始计时。 |
| 采能 | 位于采能范围内、没有移动意图、站点为安全或预警、尚有储能时自动累积；不增加瞄准或采集按键。 |
| 四阶段 | 安全 → 预警 → 爆发 → 冷却。预警仍可采，爆发和冷却不可采；中心、半径、进度由逻辑驱动显示。 |
| 风险收益 | 多停留能更早完成，但会压缩撤离余量；远处高产站可缩短采集时间，却增加路程或撤离风险。没有随机暴击或押注损失。 |
| 有限储能 | 商业任务的新增设计假设：总储能暂按目标的 150%，单站不超过目标的 50%，至少两种可行站点组合；三站可各 50%，四站重新分配而不自动提高总量。只增加剩余储能和耗尽提示，不做背包。先在切片试验，教学任务可豁免。 |
| 耗尽语义 | 储能耗尽只停止产出，余热仍按四阶段运行。UI 分别显示“无储能”与危险阶段，不能把灰色耗尽误读为安全。若试玩证明双重读数负担大，优先简化该规则。 |
| 站点类型 | 首先只有常规站；切片验证后最多加入一种同脚本参数变体“高产/短窗口站”。不再扩展多种新交互。 |
| 生命 | 暂沿用 3 格与短暂无敌；准确伤害节奏由 M0 和切片试调。没有永久耗材或跨任务损伤。 |
| 胜利 | 任务能量达标即完成，自动交付设备，不增加背着能量返回出口的环节。 |
| 失败 | 生命归零或任务超时。给出受伤站点/阶段、当前能量和简短原因，可立即重试当前任务。 |
| 同帧事件 | 沿用原规则优先处理伤害与死亡，再判断有效采集达标，最后判断超时；显示、结算与测试需统一此顺序。 |
| 暂停/重开 | 逻辑阶段、任务倒计时与关键视觉进度同步停下；重试重置位置、储能、相位、生命、无敌和所有一次性动画。 |

有限储能、高产站与探索交互属于商业版新增成本，**不要求当前 M0 实现**。如果有限储能只让玩家按固定顺序走完，应回到路线、供能比例与窗口组合试调；不能继续加系统掩盖核心决策不足。

### 4.4 数值与关卡数据

原 120 秒、380 能量、半径 55/80、移动速度 200 等仍是旧策划初测值；实际 M0 移动脚本目前为 300。它们都不是商业版已验证平衡，像素版换坐标尺度后尤其不能直接照抄。

未来任务配置至少描述：任务 ID、入口与复位位置、时间上限、能量目标、参与站点、初始相位、成功维修标记、失败说明。站点配置描述：中心、采能/危险半径、四阶段时长、产出速度、储能上限与视觉预设。区域配置描述：通行图、修复前后资源、记录 ID、环境强度。

调参先测两条能无伤完成的路线，记录移动耗时与有效采集量，再确定目标与预警宽容度；同时记录守单站、保守撤离和贪采的结果。常规任务必须有足够储能、至少一条可行路线和可辨识的撤离空间。新增高产站要真的形成选择，否则取消。

任务差异至少改变一种真正影响选择的条件：站点间最短路、等待位置、相位、可采窗口、产出/储能组合。只换背景、颜色或天气不算新任务。

探索的主要回报是理解空间与看到维修结果；可选支路给记录和观察点，不放必须回捡的钥匙。修复引起的排水与路线开放用清楚的“修复前/后”布局、Mask 和碰撞状态表达，不进行实时流体模拟。先开通路，再允许进入，避免把玩家夹在地形变更里。

无伤完成与最快完成分别记录，不强制同时达成，不锁主线。回玩使用独立任务上下文，结束返回任务列表或原探索状态，只更新回玩成绩；不重复打开通路、播放首次结尾、改写维修标记或覆盖主线位置。后期回玩入口只复用六次任务，不追加日常刷取、在线排行榜或无尽模式；如果试玩者没有重玩意愿，优先修订任务而非假设奖章能解决问题。

## 6. 火焰、雨、河流/水面波动的明确安排

**三种都纳入首选商业视觉，但以可控的基础版本为目标。** 这里的河流首先是开放式工业冷却水渠：它有方向性流水、扰动和岸边泡沫，服务桥路与维修主题；不额外建一套自然河谷生态。如果以后换主题，水面模块可复用。

## 7. Shader 模块、显示层和效果矩阵

### 7.1 按职责组织，而不是按效果数量数文件

下面的模块是职责边界，不是承诺八个文件完成所有效果。同组可以共享 Noise、Mask、参数命名和计算思路；Sprite、粒子显示和屏幕采样的输入不同，必要时分别保存材质。也不建议做一个带几十个开关的万能 Shader。

| 模块 ID | 职责与复用对象 | 参数所有权与边界 |
| --- | --- | --- |
| V1 对象反馈 | 角色染色、闪白、低血、溶解；也可复用到可关闭设备 | 对象自身管理反馈强度和进度；共享 Shader，独立状态参数。 |
| V2 轮廓强调 | 角色、可检查控制台、可采站点的描边与克制柔光 | 强调等级由交互/状态逻辑决定；不等于伤害范围。 |
| V3 站点表面 | 内部能量流、安全、预警、爆发、冷却的表面观感 | 每站独立阶段、进度和储能；装饰流动不能自行决定阶段。 |
| V4 范围与径向事件 | 采能圈、危险圈、预警条带、能量波、冲击环、涟漪 | 圈的公式可以复用，但危险边界与装饰波前分开显示；一次性事件有结束与重播。 |
| V5 热区与粒子显示 | 火焰、烟、火花的形状、颜色、显隐 | 火焰受站点/设备状态驱动；粒子发射与运动另由粒子系统管理。 |
| V6 水与湿地表面 | 水纹滚动、扰动、岸边泡沫、湿地高光 | 水区/岸线 Mask 与场景资源管理，统一水流参数；不承担通行判定。 |
| V7 降雨显示 | 雨滴、落地水滴的着色与简单动画 | 发射区域、落点、寿命由粒子/脚本负责，环境参数统一管理。 |
| V8 画面处理 | 局部热浪/水折射、画面过渡、短促色散/Glitch | 屏幕复制与绘制顺序集中规划，禁止各效果随意添加采样层。 |

环境色调、灯光与修复状态还需要场景节点和统一参数管理，并不必然需要新 Shader。像素地板和设备底图也不应为追求“纯 Shader”全部重写。

### 7.2 显示层与共同接口

建议以地面/水面 → 设备/角色 → 局部装饰 → 清晰的交互与危险指示 → HUD/菜单组织显示。具体绘制顺序由未来游戏教学实现；热浪/折射应处理背景与装置后再画关键指示，不能让提示和 HUD 被扭曲。烟或前景物件若遮挡角色，应降低透明度或限定区域。

“主要画面由 Shader 完成”指状态表现、流动、颜色、Mask、扭曲和转场主要由 Shader 承担。输入、碰撞、计时、采能、伤害、存档、交互和输赢仍由 GDScript/节点负责；雨滴、火花的数量、位置、速度和寿命可用粒子系统。它不是一张纯全屏 Shader 实现整个游戏。

未来接口必须共享危险中心、真实半径、阶段、阶段进度与逻辑时间。`TIME` 只用于不影响判定的装饰，关键预警倒计时采用可暂停、可重置的逻辑进度。每站参数隔离；全局雨强、水流方向和区域色调可共享。接口名称在教学时确定，本计划不先改用户材质。

范围判定还必须统一玩家参考点。商业首选用玩家根节点的世界位置判断是否在采能/危险半径内，素材锚点与这一位置对齐；不按 PNG 透明边或碰撞胶囊擦圈决定范围。当前 M0 用 Area2D 与胶囊交叠触发，不能只比较两个半径就宣称显示一致；具体迁移由游戏教学先运行复习，本轮不改代码。

**共同验收：** 边界按同一中心/半径生成，测试参考点贴边内外位置，明确边界等号归属。像素边线存在离散误差，需让玩家看得清保守安全位置，不用外光/泡沫扩张实际范围。爆发起止、暂停、连续受击、连续重播、换分辨率和重开后，判定与指示始终一致。状态通过颜色加形态区分：安全为细边/稳定流动，预警为斜条与进度提示，爆发为明确实线/填充，冷却为暗轮廓与冷却标记。耗尽另用储能图标表达。装饰光晕与扩散环不是伤害边界。

### 7.3 矩阵说明

阶段含义：**M0** 仅用已学效果与占位完成规则；**商业核心** 是首选成品的基础表现，按课程依赖接入；**可选打磨** 可取消或简化；**独立实验** 仍按原课程完成，不强塞进游戏。复杂度是相对比较：低为少层且单输入，中为状态/多层组合，高为屏幕采样、叠放或较多资源；不是工期承诺。

### 7.4 Compatibility 与官方资料核验

本轮只规划当前 Compatibility 工程，没有更换渲染器。官方当前渲染器表列有 Compatibility 的屏幕纹理与 Glow 支持，同时列出 2D HDR、计算 Shader、屏幕空间反射及部分高级功能限制；不能用旧版本印象写成“完全没有 Glow”。首选仍用对象描边/假柔光与受控表面高光，实际安装版本、Glow 设置与目标设备表现由后续实测确认。[Godot 官方渲染器对照](https://docs.godotengine.org/en/stable/tutorials/rendering/renderers.html)

热浪、水折射与屏幕冲击波叠放时，必须安排复制与绘制顺序；多个 2D 屏幕采样节点不会自动逐层复制，区域复制外的采样也有边界风险。因此不承诺这些效果可以随意重叠。需要时只保留一个重要采样效果，其他使用对象/表面材质。[Godot 官方屏幕采样说明](https://docs.godotengine.org/en/stable/tutorials/shaders/screen-reading_shaders.html)

雨、火花和烟可由粒子系统配合显示材质；CPU/GPU 粒子选择按当前版本、数量与设备实测，不直接保证某方案性能更好。官方粒子教程当前还标有 4.7 更新提醒，具体属性以实际编辑器为准。[Godot 官方 2D 粒子说明](https://docs.godotengine.org/en/stable/tutorials/2d/particle_systems_2d.html)

## 8. 像素美术、资源替换与可读性

### 8.1 首选美术规格

2026-10-03：用户要求从零制定标准并彻底替换原资源。美术生产尺寸更新为 32×32 地面图块、64×96 人物帧（有效轮廓最大 40×64），新美术构图基准为 960×540；角色四向待机与移动共 20 帧，采集动作可选增加 8 帧。设备画布、锚点、调色板与完整资源预算以[全新美术与生图标准](art-generation-standard.md)为准，取代此前试拟尺寸。当前只更新生产规范，工程显示配置与实际素材尚未迁移。

画面使用深蓝灰工业底色、清楚的金属轮廓，青色能量、橙色预警、红色爆发；水面低亮度，避免与可采状态争抢注意力。修复后的暖灯和稳定管线产生回报。暂试一套受控调色板，再按读数和显示设备调整，不能把指定色数当质量保证。

像素一致性要覆盖整个流程：

1. 底图使用一致的有效像素尺度；视觉位置按逻辑画布像素对齐，角色实际碰撞与计时保持可靠连续，不用视觉取整代替物理规则。
2. 水纹、Noise、程序图案、描边以逻辑像素尺度校验；UV 扰动需限制幅度并评估量化后的运动，不能只开 nearest 就假设所有效果都像素化了。
3. 雨线、火花和烟避免亚像素闪动。装饰动画可用较低更新节奏，危险时点和进度指示仍由逻辑准确更新。
4. 外描边先测试一逻辑像素；角色纹理需留边，避免轮廓出界。柔光采用克制的层级，优先保留轮廓而非大面积模糊。
5. 转场、热浪与屏幕采样需要统一逻辑画布/采样坐标；分别测试整数倍窗口、非整数窗口和全屏。若折射造成像素爬动，先取消折射，保留表面扰动。
6. 首选整数放大配合留边；非整数窗口用可读的缩放/留边策略，不改变关卡可见范围。新美术基准 960×540 在 1920×1080 是两倍放大，实际显示迁移时需切片验证。
7. 中文文本使用经许可核对、字形覆盖完整的字体；像素风不能成为字体过小、句子截断或按钮难读的理由。HUD 与菜单可采用清楚的独立 UI 缩放。

切片先用已学能力和简单显示测流程，不需要等全课程结束才试玩。随着课程补齐基础环境与综合反馈后，才评审切片的最终视觉；高阶效果等待对应知识。切片不必同时完成火焰、热浪、反射、CRT 与全屏冲击。

切片的最少美术集合是：一台四向机器人、一套共用工业图块、一个站点底图及窗口 Mask、一块控制台、一段桥/水渠、排水前后通路变体、小雨滴/Noise 和 UI 图标。最少声音是移动/采集、预警、爆发、任务成功、雨/水与机械循环；可先使用经许可确认的占位声音，成品再统一。

若切片中探索只是在任务之间走路、日志无助于理解空间，或抢修仍只有机械等待，先修订目标、路线和信息呈现。不得自动扩满十屏。预算不足时可以收缩到更少区域/任务，但必须据试玩明确保留完整旅程；不能砍课程覆盖来赶游戏进度。

## 11. 从学习 Demo 到商业成品需要补齐的质量

| 工作项 | 切片必须有 | 发布候选必须验证 |
| --- | --- | --- |
| 玩法与内容 | 完整任务、修复结果、失败重试；数据可调 | 六任务各有意义；全流程可完成，无依靠隐藏信息或逐帧精确操作的必过要求。 |
| 美术与动画 | 统一有效像素尺度与调色方向，四向移动/待机，核心状态 | 全区域比例/锚点一致，前后状态完整；无缺帧、错层、读数不清；不能只换主角图。 |
| 声音与音乐 | 阶段和交互音效、环境循环与音量控制 | 混音不掩盖预警；循环平滑；许可/署名清楚；音乐可少而完整，不承诺大量曲目。 |
| 菜单、设置、暂停 | 开始/继续、暂停、结果、音量、基础显示/效果开关 | 新游戏/继续/任务回玩清楚，改键提示正确；焦点、确认/返回、退出流程可用。 |
| 存档与检查点 | 修复标记、已读记录、设置；成功后能退出再继续 | 版本与默认值策略；异常存档可恢复/提示；多个维修标记与地图一致；保存失败不能假报成功。 |
| 退出中断语义 | 明示未完成任务退出后从入口重试，不保存半局能量 | 关闭程序/加载后不重复奖励、不丢已完成维修；无恢复到危险中心或黑屏过渡中。 |
| 输入 | 键盘全流程可用、可改键；移动与交互不冲突 | 焦点丢失后无按键卡住；输入显示与实际绑定一致；若支持手柄需单独走通，不预先宣称。 |
| 分辨率与文字 | 候选像素画布、两种窗口尺寸、中文可读 | 整数/非整数窗口、全屏、UI 缩放、不同宽高比与高 DPI；危险中心不随缩放错位。 |
| 可访问性 | 状态用颜色+形态；关闭抖动/强闪烁/后处理；清楚文字 | 低闪烁、独立音量、色觉与无声测试；可考虑延长预警/任务时间的宽容选项，记录方式区分但不阻止体验叙事。 |
| 性能 | 效果开关对比，限制粒子与透明覆盖；记录测试设备 | 在选定最低目标设备上实测。60 FPS/16.7ms 仅为 PC 目标假设，记录帧时间分布、峰值与卡顿原因，不凭平均 FPS 宣布合格。 |
| 稳定性 | 重试/暂停/重复受击/转场连续操作 | 长时间玩、连续多次任务重试、存读档、窗口切换；无崩溃、泄漏积累、信号重复或遗留 Tween。 |
| 试玩 | 观察新玩家理解，记录卡点/失败/读数误判 | 多轮陌生玩家验证探索意义、任务差异、完成时间和氛围；用户自行组织，当前 Chat 不自动联系他人。 |
| 发布准备 | 暂不阻塞切片 | 实际平台确定后核验当前官方规则；导出与干净设备测试、操作说明、许可信息、截图/短片和准确产品描述。 |

质量降级顺序首选：减少宽柔光和透明叠层 → 减少雨/烟/火花数量 → 关闭热浪/水折射/动态反光 → 保留基础水纹、火焰与状态指示。任何质量档位都不能改变伤害、站点周期、危险边界或必需文字。

商业目标需要完整、稳定、可理解的产品体验；替换素材只解决其中一部分。本计划没有查询市场或定价，不提供销量、收入、售价与商业成功承诺。定价、发行平台和宣传定位在切片及内容证据足够后另行研究。

## 12. 验收、设计假设与当前下一步

### 12.1 需要留证据的试玩项目

| 验证点 | 方法与观察 | 未满足时如何处理 |
| --- | --- | --- |
| 核心决策 | 比较保守采集、贪采、不同站点组合；记录采集量、等待/移动时间、受伤原因 | 调布局/相位/产出和任务目标，先不增加技能与敌人。 |

| 环境可读性 | 同局对比雨/烟/柔光/折射开启和关闭，含无声与色觉检查 | 降密度、调层级、取消高阶采样；保留危险指示。 |
| 世界状态 | 成功后回访、退出继续、失败重试、任务回玩，核对水位/通路/灯光/记录与主线位置 | 统一维修标记与数据来源，隔离回玩上下文，修复软锁与存档不一致。 |
| 生命周期 | 连续受击、暂停后恢复、转场中重试、重复进出任务 | 明确取消/重入策略，停止遗留动画与粒子；重置视觉与逻辑两侧。 |

### 12.2 已确认与待验证

## 13. 专业策划自评：保留方向，暂缓商业内容扩展

2026-10-01，针对用户要求进行独立审视。以下是基于设计规则与制作范围的判断，**不是实际试玩、市场调查或商业成功概率**。

**总评：作为 Shader 学习项目与玩法原型，方向合适；作为商业游戏，主题和制作组织已形成，但核心决策、探索与抢修的联系、叙事吸引力仍不足以支撑正式扩关。** 保留工业维修/环境恢复，继续低成本切片验证；暂不按四区六任务全面生产。不因本评审重做当前 M0，也不降低课程标准。

### 13.1 值得保留的部分

维修结果可直接改变空间、照明、声音和水流，是最有潜力的玩家记忆点。安全探索、主动启动压力段、失败只重试当前任务，也尊重氛围玩家的节奏。雨、水渠与余热来自同一设施，具备资源复用和统一叙事的基础。状态可读性、像素尺度、参数职责与质量降级规划较完整，有利于生产。

这些强项支持继续验证，但效果清单和发布检查的完整程度不能证明玩法成立。

### 13.2 关键问题与证据层级

| 问题 | 评审依据 | 结论性质 | 应如何验证/修订 |
| --- | --- | --- | --- |
| 多个解不等于值得选择 | 两条无伤路线、多个站点组合仍可能存在一条更快且更安全的全面占优路线 | 文档论证缺口 | 在具体地图里比较路线成本、当前站点阶段、剩余储能和撤离余量；玩家须能解释此刻为何选择它。 |
| “贪一点”可能只有低成本的定时执行 | 固定周期、线性产出、原采能/危险半径与较长预警；掌握后可能重复等待 | 设计风险，尚未试玩 | 测贴边采集、早撤、晚撤与绕路，不把等待次数当深度；固定路线允许成立，但执行过程仍需有体验价值。 |
| 风险收益可能失衡 | 探索主线不强求快，保守撤离可能总是合理；每任务恢复生命且受伤不丢能量，也可能让主动吃伤更有效 | 待参数与玩法验证 | 对比保守/晚撤/主动吃伤。血换时间可以是合理选择，但要明确是不是设计意图，避免它替代主要判断。 |
| 探索与维修可能只是轮流出现 | 许多流程仍可概括为到控制台、玩采能、开门、读日志 | 设计风险 | 观察得到的空间信息要帮助抢修，维修结果要改变下一次判断。先用泵区证明两者互相需要。 |
| 按键后计时与危险的原因不充分 | 安全探索切入喷发任务，缺少清楚可见的设施状态解释 | 叙事/规则表达缺口 | 用简洁的缓冲供电或临时排热状态解释任务窗口，以现场指示配合；不额外堆世界观。 |
| 故事有概要，尚无清楚的情绪对象 | 异常能源、主动停机、传回记录说明流程，但尚未明确玩家关心谁、什么未完成事务 | 叙事设计缺口 | 切片用一处现场痕迹、短记录与维修结果建立理解/情绪变化；十条记录不是叙事质量保证。 |
| 商业内容预算早于玩法证据 | 四区、十屏、六任务是生产计数，像素资产与修复状态仍有实际成本 | 立项风险 | 先证明选择、探索帮助和维修后果，再批准扩关；不同背景/相位不自动算不同体验。 |
| 旧切片验证少了后半环 | 第 3.1 节要求维修影响第二次任务，原第 10 节只列一次抢修 | 已确认文档不一致，本轮已修正 | 在修复后加一个很短的占位验证任务，复用地图和站点，不先生产一整套第二任务美术。 |

一个具体数值警示：按旧初测采能半径 55、危险半径 80、速度 200，以角色参考点、无遮挡直线移动估算，站在采能圈外沿只需再走约 25 像素，抵达危险边界约需 0.125 秒；旧预警为 2 秒。实际 M0 移动速度为 300，且其范围基准尚待教学核验。这是简化几何推断，不是运行结论，但足以说明原数值尚未证明撤离有实质压力。不能只是极端缩短预警，把氛围探索变成苛刻反应测试；应结合空间、路程、站点价值和信息可读性调整。

有限储能只限制守一个站，不自动带来资源经营深度；最快/无伤记录也不能自动带来重玩。工业像素主题与天气是美术方向，玩家价值仍需落实到“做了什么决定、设施如何响应、为什么愿意继续”。

### 13.3 扩展前必须得到的证据

最小验证对象仍是泵区：两个相邻屏幕、短桥/安全绕路、一次排水、一个修复后的简短验证任务、两条与现场对应的记录。先用占位验证因果链，再补必要像素与视听反馈，不以复杂火焰/折射作为前置门槛。

至少记录四类行为：玩家能自己说明目标与计时原因；能说明一次路线选择的取舍；察觉排水改变空间并在后续利用它；从现场与记录理解一条具体故事信息。同时检查空等、相同操作重复与失误原因。几位陌生玩家的观察只能支持下一轮小规模决策，不能当统计市场结论。

若选择仍只有执行固定流程，应修改采能与路线设计；若探索仍只剩走路，应修改信息与空间结构；若维修结果只有亮灯开门，应让同一变化影响后续行为。先解决这些，再讨论任务数量、总时长和打磨效果。

关于评审方法，可参考游戏设计师 Liz England 对交互规则、可识别性、锁定/解锁与实际行为问题的说明；此处借鉴其提问方式，不把外部案例当成本项目验证证据。[《The Door Problem》](https://lizengland.com/blog/the-door-problem/)
