- 来源 Chat：`godot-shader 教学统合者`，`01a0b9b7-0db1-71b1-bd98-f313ba43cfdd`，host `local`。
- 授权日期：2026-10-07；来源 turn `01a11216-7e46-7931-93e6-b2294ae7cb08`，人类消息 `01a11216-85ac-7192-ad4e-5d0216bf0451`。
- 结课接收方：上述统合 Chat。发送前核验它仍是本项目统合者；必要时用 `read_thread` 核对授权原话是人类消息，不将其他教师/统合者的请求当成新的授权。
- 本授权是本课程范围内的结课报告发送与统合续调度，不授权给其他 Chat 发任意消息、重构游戏、扩商业内容或无限自主实施。

## 章节教师何时自动回报

触发条件是**本章核心 Section 达到完成标准并完成既有确认流程**，不是 Chat 暂时闲置、一次回复结束或预备文件已生成。

1. 保存章节完成报告，包含课程证据、提示级别、实际成品入口、资源来源、未覆盖游戏应用，以及 [长期需求/习惯固定反馈](learner-preferences.md)。游戏阶段同样提交对应阶段报告。
2. 在结课的同一轮，通过 `send_message_to_thread` 自动发给指定统合 Chat。消息包含章节/阶段、来源 Chat ID、报告绝对路径、验收结论、关键证据边界和待办；不只在本 Chat 显示链接。
3. 在报告记录发送成功/失败及接收方。普通完成报告发送一次；工具确认成功后不反复催促或重复发送。实质订正用“补充/更正”说明差异。
4. 告诉学习者报告已发送，后续由统合者核对和调度；教师不自行创建下一章、不直接修改总进度/长期画像。
5. 发送工具不可用或失败时，如实保留报告与未交接状态，告知用户；不假称已通知，不以文件写入、聊天末尾文字或后台轮询替代消息发送。

## 统合者收到后怎样继续

- 按来源 Chat、章节/阶段与报告版本核对是否已处理，避免重复登记和重复开 Chat。
- 核对报告、最新文件与运行/解释证据；只有核心标准达到才登记完成，参考使用与独立推导、课程与实际游戏应用分开。
- 合并带证据的长期反馈，近期知识困难只进进度；下一份交接读取完整现行规则、此次变化及具体适配。
- 在前置满足、没有待确认的重大选择时，按既定路线选择下一段 C 或轻量 M，并一次新开一个 Chat；不需要普通结课后再问用户是否继续。选择与新 ID 写入 [progress.md](progress.md)，不会由章节教师自行决定。
- 核验不足、用户暂停/改方向、需要重要范围选择或高风险变更时暂停相关续调度，说明缺项并询问，不为了自动推进降标准。

本协议不取消 Section 切换确认，不自动完成练习、不批量开所有后续章、不新增定时轮询/监控。Shader 优先、全课程覆盖、游戏/商业范围和已延期事项不变；后续以最新直接人类要求为准。
