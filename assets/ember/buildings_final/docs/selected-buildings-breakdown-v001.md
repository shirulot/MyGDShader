## 1. 三视图的定义

本批“三视图”固定为 **南向正视、东侧右视、纯俯视**。它们是描述同一栋建筑的技术设计图；原来的正交俯视＋正面复合游戏视角继续保留为外观参考。

- 正视：只显示南立面和顶部薄檐，不再显示大面积屋顶纵深；锁定门窗、楼层线和接地线。
- 右视：东侧立面，墙高和层间线与正视一致。附件没有完整东立面，因此本批右侧墙板、窗和检修口标记为 **补设计**。
- 俯视：从正上方看脚印、屋顶板、天窗、加强肋和屋顶设备；不显示竖向立面。图纸约定北在上、东在右，前门位于南边。
- 正视的宽对应俯视的宽；右视的宽对应俯视的深；正／右的墙高与楼层线一致。每栋三图用相同单位比例，不分别拉伸各面来填满版面。
- 可见参考能确定轮廓与部件，不能测出完整三维实尺。本批仍沿用已登记的2D制作目标；墙高是投影制作值，不把它写成实测3D层高。

## 2. 三栋共享的拆分规则

| 层／部件 | 为什么拆 | 交互或表现职责 |
| --- | --- | --- |
| 地基脚印与门洞数据 | 与整图Alpha和屋顶尺寸分开 | 碰撞、可走入口、遮挡区域；不通过PNG透明处猜阻挡 |
| 后墙／上部壳体 | 固定结构与前景排序分开 | 静态结构；所有隐藏部件补齐被门、窗、设备遮住的底图 |
| 南墙与门框 | 让玩家进门时正确遮挡 | 前墙可局部淡出；门框固定，不能随门板开关移动 |
| 屋顶 | 房间内部可见与外观分别控制 | 进入室内时隐藏／淡出；保留北、南、东、西及角件拆件边界 |
| 门板 | 开／关必须共用安装点 | 先准备关闭、开启两端态；运动阶段共用画布、pivot和门洞 |
| 玻璃与框 | 内景、灯光与玻璃外观分别处理 | 窗框静态，玻璃独立；室内亮／暗通过独立层或Mask表达 |
| 状态灯与门禁 | 设备状态来自逻辑 | 灯底、发光区域／Mask分开；关闭、运行、告警有颜色＋形状区别 |
| 屋顶设备与墙面检修件 | 同类设备可复用、状态可变化 | 外壳、活动件、灯窗分开；屋顶设备的控制入口设在可达墙面 |
| 踢脚、柱头、接地影与磨损 | 静态造型与环境表现分开 | 固定柱头与边带可成模块；接地影独立；磨损不重复烘焙每32格 |

“可拆分”指资源和层级可分，不等于建筑可以被玩家拆毁。固定墙、柱、窗框和加强肋以静态资源处理；开门、修复、设备启停等作为建议交互，尚未写入游戏逻辑。

## 6. 动作层与制作优先级

第一批优先做 **完整墙壳、可隐藏屋顶、固定门框、活动门板／卷帘、门禁与状态灯、玻璃层、入口碰撞数据**。这批足够完成开关门、进出、屋顶遮挡和状态变化。

第二批再做屋顶天线通讯、风机叶轮、检修盖板及机组维修表现。屋顶交互通过可达控制面板触发，屋顶检修盖暂不引入登楼或攀爬玩法。

- 普通门先做闭合／开启端态。门动作形式统一后，再补动画；不能从概念图的金属条直接推断真实铰链或滑轨结构。
- 卷帘采用垂直收卷，卷帘、导轨、收纳箱分层；活动卷帘须裁切在门洞范围内，不能遮住人门或伸出整栋基部。
- 锁定、断电、故障是设备逻辑状态，不默认各画一整套建筑。用共享底图、状态区／Mask和独立动画表达。
- 灯色之外还用图标／分段／开关节奏区分状态；不把“红灯”当真实危险范围或门碰撞。
- 每个可交互件登记触发位置、作用对象、动画层、状态反馈和碰撞变化。部件只是设计提案，未接入逻辑时不记作可交互已实现。

## 7. 正式拆件和铺刷契约

所有同栋图层共用建筑世界原点、32 world格、地基脚印和基部pivot；局部部件另记安装点。可裁切局部画布，但必须登记相对于建筑原点的偏移，复装后不许漂移。门框、门板、内景和Mask共用门口几何，开关态位置稳定。

正式底图准备被遮住的完整面。不能把参考图里的门／设备直接扣走后留下洞，也不能把生成拆件说明板均分成生产atlas。说明板的部件示例只表达拆分边界。

建筑自身不烘焙外部平台、桥口或连续地板；门前至少64×64 world可走区由现有地板笔刷产生。墙壳可扩展32 world直段、外角和凹角；固定立面不旋转冒充不同朝向。

若改为可刷墙／屋顶，仍需[建筑规范第7节](../../../../docs/shader-learning/ember-building-standard-v001.md)的47型、门洞覆写和跨层同步验收；三视图与拆件清单不替代实际自动补全工具。入口行走、碰撞开关、门内裁切、屋顶遮挡、保存重载与新工程导入分别检查后才标生产可用。

本批交付为三视图／拆件设计说明板和清单，正／顶依据用户选中参考，完整右侧是补设计；没有实际拆出生产PNG或实现上述交互。
