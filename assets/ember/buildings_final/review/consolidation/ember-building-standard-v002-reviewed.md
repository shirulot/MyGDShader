## 2. 视觉样式

| 项目 | 现行规则 |
| --- | --- |
| 气质 | 有维护痕迹、仍在使用的工业站点。形体稳重、功能明确、细节克制 |
| 视角 | 正交前向俯视复合视角，同时看到顶面与南向正面；地面横平竖直。统一零 yaw、无消失点；转角厚度依照整栋参考 |
| 造型 | 低矮平顶／低坡顶、矩形体量、浅装甲边带、蓝灰基部、有限的圆角或斜切角；控制塔允许两层，其余依功能设计 |
| 材料 | 浅色装甲负责外墙和包边，蓝灰钢材负责屋面与结构，黄铜用于接口、扣件和少量功能强调，玻璃保持深青灰 |
| 光照 | 固定左上体积光；用清楚的大块明暗表达体积。高光面积小，投影和状态光按用途独立处理 |
| 像素质感 | 清楚的像素簇和边界，3～4 个主要明暗层组织一种材料；稀疏成片磨损，保持适度材质颗粒 |
| 细节分布 | 入口、门禁、维护件和主要设备更清楚；屋顶和大墙面更安静。每栋集中 1～2 组主要屋顶功能件 |
| 视觉层级 | 玩家／危险边界 → 当前交互目标 → 通路／建筑入口 → 环境装饰 |

共享锚定色：结构暗部 `#101820 / #182631`；蓝灰钢材 `#2B3E4B / #4D6470 / #829BA3`；浅装甲 `#BECBC4`，小面积高光 `#ECE9D8`；黄铜 `#7B4D35 / #B77C4B / #E2B77A`；状态青 `#51C5C2`。新建筑可登记一致的增补色，不强行量化已选母图，也不另起一套偏色钢材。

直接退回的样式问题：写实镜面金属、塑料般光滑的渐变、大面积霓虹／Bloom、均匀高对比撒点、密集铆钉网格、每块板一圈亮框、过度废墟化，以及为显得精细而缩小门窗或机器人比例。

## 4. 尺度、画布与安装数据

世界格固定为 **32×32 world**。地板继续使用当前 **128 texture px → 32 world、TileMapLayer.scale=0.25** 的生产体系。建筑作为独立 Sprite 登记，采用自身的等比缩放；地板的缩放值不能套到整栋建筑上。

当前示例机器人帧为 64×96 px、显示 scale=0.65，地面接触盒为 18×12 world。角色画布、可见高度、接地碰撞是三项不同数据；门净口须在真实角色通行中验证。

以下是当前 v004r1 的实际登记，不是所有新建筑的固定尺寸模板。三栋均使用 1254×1254 px 源画布；表内缩放和门净口作阅读近似值，程序读取 JSON 原值。

| 建筑 | 地面脚印（world／格） | source pivot（源 px） | 等比缩放 | 普通门净口（world） | 货门净口（world） |
| --- | --- | --- | --- | --- | --- |
| 控制塔 | 256×128／8×4 | (635,1140) | 0.355555556 | 36.62×57.60 | 无 |
| 维修工坊 | 384×128／12×4 | (628,966) | 0.344086022 | 37.51×56.43 | 无 |
| 物流仓库 | 608×224／19×7 | (627,899) | 0.571428571 | 32.57×56.57 | 162.29×81.71 |

从源坐标到建筑局部坐标统一使用：`local_position = (source_position - source_pivot) * uniform_scale`。同栋完整图、功能层和 Mask 共用这套变换；整栋节点保持统一放置，不对屋顶、墙体、门框分别缩放。

地面脚印决定阻挡与进入区域；屋顶和墙面的可见投影不等同于占地。PNG 的透明边、整幅高度及 Alpha 轮廓均不能代替碰撞登记。

旧规范的控制塔 4×4、工坊 6×4、仓库 8×5 格，以及固定 40×56／104×60 门口等早期目标，已由本批最终注册替代。不要为了恢复旧数值而拉伸当前母图。当前大画布也不等同于“1 源像素 = 1 world”的原生像素成品；未来如更改像素密度，须作为新版本重新做同尺度视觉及通行验收。

## 5. 拆分与复装硬规则

**结构连续性是拆件的前提。** 屋面、檐口、柱头、墙面、门窗框共同构成固定主体。每个转角只有一套连续的曲率、明暗和轮廓所有权。

1. 先保留并确认完整母图，再从该图按原坐标提取活动门板、卷帘、盖板、灯面和玻璃。固定屋顶、墙面与角件不分别生图后拼回。
2. 所有层共享画布与 pivot。需要裁切局部 PNG 时，必须保存裁框、原画布及偏移；禁止自动裁掉透明边后丢失安装位置。
3. 同一实体像素只属于一个功能层或固定主体。闭合复装的可见 RGBA 必须与完整生产图一致；没有缺口、重复描边或半透明叠加。
4. 屋顶与墙体不得分别加宽、缩窄、拉伸、补一圈边、二次倒角，也不得靠柱子或装饰遮住接缝。新增一圈檐角即退回。
5. 门开关只改变登记的门洞范围；门框、墙柱、屋顶和相邻圆角保持原位。活动件不得滑出门洞并覆盖外墙。
6. 可拆分表示资源可分层。破坏、拆楼、攀爬、开窗等玩法需要单独立项；不会因 PNG 可拆而自动成立。

当前生产导出为 **3 张完整图 + 15 张功能 PNG（含 3 张固定主体）+ 3 张覆盖图**。每栋 5 张功能 PNG：

| 建筑 | 固定主体外的 4 张功能层 |
| --- | --- |
| 控制塔 | `personnel_leaf`、`roof_hatch`、`status_lenses`、`glass` |
| 维修工坊 | `personnel_leaf`、`maintenance_cover`、`status_lenses`、`glass` |
| 物流仓库 | `personnel_leaf`、`cargo_leaf`、`maintenance_cover`、`status_lenses` |

运行时当前使用完整 Sprite + 已登记区域的 Shader 变化；功能 PNG 是同源拆分交付，不应重复覆盖到完整 Sprite 上形成双层主体。未来切换为 Sprite 分层实现，也须通过相同的复装验收。

固定天线、格栅、管道、加强肋、窗框和设备壳体保持静态。当前工坊屋顶天窗没有独立亮暗区域；风机没有叶轮旋转动画，不能在交付清单中写成已实现。

## 6. 交互契约

每个交互项登记：对象 ID、触发安装点、可达距离、前置状态、动作区域、视觉反馈、碰撞影响、存档字段和验收证据。普通交互当前距离为 64 world，按门口或地面维护安装点测量；检查模式可以绕过距离，但不能据此声称角色可以远程操作。

### 6.1 门与货运卷帘

人门与货门分别保存 `progress`、`target`、`locked`；当前开合时长为 0.8 秒，门板在固定门洞内向上收起。后续改变机构或时长时须重新验收，不能只更换开启图。

| 情况 | 必须发生的行为 |
| --- | --- |
| 关闭 | 门板回到母图位置；入口碰撞阻挡 |
| 开启中／关闭中 | 保留门框，门板只在净口内运动；当前策略是未全开时继续阻挡 |
| 完全开启 | `progress >= 0.9999` 后释放门碰撞；以实际角色移动确认通路 |
| 锁定 | 拒绝新的开门请求，并给出可见反馈。当前加锁不会把已打开的门强制关闭 |
| 断电或故障 | 停在现有进度，拒绝正常门操作；碰撞继续按实际进度判定，灯反馈同步变化 |
| 恢复供电／故障修复 | 条件满足后沿保留的目标继续；不能无条件跳到全关或全开 |
| 关门前有人 | 拒绝关闭，设置重开目标并提示入口被占用 |
| 关门途中有人 | 设置重开目标，防止继续夹人；若同时断电／故障，保持暂停，待运动条件恢复后重开 |

防夹检测使用角色地面接触盒与门口安全区，不使用角色整张绘图画布。货门与人门须各自测试；当前示例 `L` 只切换人门锁，不能当作货门锁定操作的演示。

### 6.2 灯面、玻璃与设备

| 对象 | 当前可用表现／操作 | 制作约束 |
| --- | --- | --- |
| 门禁／设备灯面 | 默认保留原图灯色；开门运动有短促明暗变化；锁定或设备停用压暗原灯色并施加暖色偏移，不统一替换成橙色；故障红橙闪烁；断电显著变暗 | 只影响灯面，固定金属框不变色；状态与门／设备逻辑一致 |
| 窗玻璃 | 控制塔与工坊登记的前墙玻璃可亮／暗；断电时取消通电亮态 | 窗框、分隔肋和外墙不随之发亮；当前没有真实室内灯光照亮地面 |
| 工坊／仓库检修盖 | 可开／关，开盖后可维修清除故障；靠近对应墙面安装点操作 | 固定框保持不动；当前开盖用深暗内口表现，尚无内部机械资产或铰链动画 |
| 控制塔维护 | 从可达地面控制点修复故障；该塔未登记地面检修盖 | 不凭其他建筑的交互强行增加一个盖子 |
| 设备启停 | 切换设备状态并更新灯面；断电／故障时拒绝操作 | 当前仅验证状态与灯面；未制作风扇转动、天线转向或运输机械动画 |
| 控制塔屋顶盖 | 可在资源检视中显示开／闭 | 尚无楼梯、屋顶路径或攀爬；不能列为可达的常规玩家交互 |

当前灯面使用建筑级状态，锁定反馈取人门锁；人门和货门的灯反馈尚非两套独立通道。新增独立设备或门灯时，要另登记状态归属，避免一扇门的状态错误控制另一扇门。

新交互的辨识同时使用位置、亮暗／节奏和文字或图标，不只依赖颜色。故障高于锁定／停用提示；断电优先压暗灯面。基础图保持克制，额外光晕和动态照明另行接入并检查 Compatibility 表现。

### 6.3 进入、遮挡与保存

当前角色地面接触盒中心进入建筑脚印后，**整壳统一透明化至 Alpha 0.14（当前即时切换）**，离开恢复。检查键也能预览这一效果；当前没有渐变动画或过渡时长。透明化只解决可见性，不改变墙、门碰撞。

当前开门显示深暗门洞；没有完整室内地板、家具、机械内腔或按房间／楼层拆分的遮挡。将来需要室内时，先补空间和遮挡方案；分层仍须按母图像素边界原位复装。

存档保留供电、故障、设备启停、盖板、玻璃和各门的进度／目标／锁定。恢复时先还原角色位置并更新占用检测，再恢复建筑状态，最后复核碰撞；避免读档前的角色位置让半关门误判为重开。

## 7. 地板、建筑边界与自动铺刷

地板延续用户偏好的连续低对比处理。建筑生产 PNG 去除背景地板、参照机器人及外部环境投影；基部落在项目现有地板上，不自带一块不同材质、厚框或额外台阶的地基。

人门前至少保留 64×64 world 可走区域；货门通路按实际净口向外保持相应宽度。地板由笔刷生成，门前不应凭空出现平台端帽、亮边或高差。装饰、栏杆和设备不得堵住入口。

现行交付是整栋预制体，**建筑放置不等于建筑墙体／屋顶已支持自动铺刷**。地板自动补全继续以[瓦片专项规范](autotile-production-standard-v002.md)为准；建筑扩为面积笔刷时必须另完成：

- 房间占用、地板、屋顶覆盖、方向性墙面与门洞覆写分别登记，并由共同占用数据生成。
- 面积邻接覆盖 47 种归一形态；方向墙面、门宽、层高和跨栋连接另列规则，不能以“47 块齐全”代替这些语义。
- 直边、凸角、凹角、L／T 形、窄通道、孤岛、封闭房间、桥口和混合材质交界实际试刷；每条接缝遵循共同截面、曲率和像素所有权。
- 绘制、擦除、改门、撤销／重做、保存重载同步更新可见图、碰撞与门口，禁止依靠手摆遮缝。

新增自动铺刷资源仍以“实际连接可用”为最高优先级；完整效果图和拆件说明板不能直接冒充可刷 atlas。

## 8. 三视图与新建筑生成流程

三视图定义为南向正视、东侧右视、纯俯视，用于描述同一栋建筑。正视宽对应顶视宽，右视宽对应顶视深，正／右视共享墙高、层间线和接地线；不得各面单独拉伸填版。参考未展示的侧墙标为补设计，图纸不直接作为生产 Sprite。游戏复合视角仍保持第 2 节的相机规则。

生产顺序：用途和可交互清单 → 完整建筑候选 → 同尺度场景对照及用户选型 → 透明完整母图 → 一次注册 → 同源功能层与覆盖 → Godot 静态及交互场景 → 验收。

可用于新稿的约束摘要：

> 以选中建筑家族为风格和尺度参考，设计一栋完整的工业站点建筑。保持正交前向俯视、浅装甲、蓝灰结构、少量黄铜、固定左上光和清楚像素簇。屋顶、檐口、转角柱与墙面连续成形，门与机器人比例一致，大面安静，维护细节集中。先交完整闭合状态，保留全部轮廓。按用途预留门板、灯面、玻璃及维护区域，但不把固定结构分别生成、重新倒角或拉伸。生产图使用透明背景，不带地板、人物、说明文字或环境光晕。先核对整栋效果，再登记交互区域和同源拆件。

生成提示词表达设计意图，不构成尺寸或连接保证。每次保存参考职责、完整提示词、原始输出、采用／拒收说明、坐标登记及 SHA256；新增构型先少量完整验证再扩展。

## 9. 导出、资源结构与状态标记

正式静态实体使用 RGBA PNG、二值 Alpha 0／255、Nearest 采样及无损导入。当前 v004r1 从每栋原始母图统一以 Alpha≥128 生成实体覆盖，覆盖内 RGB 原样保留；各功能层共享该覆盖。禁止各层单独柔化、膨胀、腐蚀或描边来修缝。光、烟等效果层可另用连续 Alpha。

当前三个 `fixed_architecture` 层在 Alpha0 区域有隐藏白 RGB 的已记录例外；TA 确认不影响 Nearest 可见复合。不能宣称所有文件的透明 RGB 均为 0，也不要为此静默重写已验收 PNG。新导出优先使用透明黑，并重新检查边缘和复合。

资源职责如下，目录可以整合，但职责和追溯关系必须保留：

| 内容 | 必须交付 |

| 图片 | 完整闭合图、固定主体、必要功能层、共享覆盖／Mask，记录采样与通道用途 |

| 状态 | `visual_reference_selected`、`engine_verified`、`ta_verdict`、`user_accepted` 分别记录，注明版本和审核范围 |

## 10. 验收与拒收条件

| 检查 | 通过条件 |
| --- | --- |
| 原图对照 | 门窗、屋顶纵深、墙高、四角和设备位置保持；在真实游戏尺度下具有同一整体效果 |
| 结构连接 | 没有屋顶大一圈、柱头不齐、双倒角、重描边、接缝明暗跳变或被装饰掩住的裂口 |
| 闭合复装 | 同源功能层复合可见 RGBA 等于完整生产图；实际 GPU 的默认闭合状态与直接完整 Sprite 一致 |
| 动作范围 | 关闭／半开／全开和检修状态只修改授权区域；屋顶、檐角、门框等固定像素不动 |
| 入口行为 | 真实角色验证关闭阻挡、半开阻挡、全开通行、防夹、锁定、断电暂停及恢复 |
| 状态反馈 | 门、灯、供电、故障和维修一致；拒绝操作有视口内可读反馈；存档恢复不改变原目标 |
| 显示格式 | 实体二值 Alpha，深／浅底和 4× 最近邻检查没有新彩边、缺口；正常缩放观察也通过 |
| 场景与工具 | 新空工程冷导入可运行，全部依赖明确；演示 UI 在声明视口内；自动铺刷若声明支持则另验完整矩阵 |

验收顺序固定为原始选中整图 → 完整生产 PNG → 实际 Godot 闭合图 → 交互过程。技术数值通过不能代替整体效果审查，概念图、说明板和实际引擎截图必须注明类别。
