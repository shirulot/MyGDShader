# 从已认可效果图到可铺刷地板

2026-10-06。依据用户本轮认可的[场景效果图](../previews/scene_preview_v001.png)。本轮明确把实际自动补全与衔接放在最高优先级。

## 元素分析与制作职责

| 效果图因素 | 在资源包中的实现 | 为什么分开 |
| --- | --- | --- |
| 连续蓝灰钢板 | `floor`完整47型 | 中心低对比、同一材质；外围2px切边，内部连接不封端 |
| 平台浅压顶与暗立面 | `rim`47型透明覆盖层 | 仅暴露周界有结构，内部mask255为透明；由地板占用同步选择 |
| 参考图厚实的平台前立面 | `facade`47型＋89型桥口 | 南向外露边投影16px深钢立面，独立层保持原地板格与桥24px端口；南桥中央通道全高清空 |
| 格栅检修区 | `grate`47型透明功能铺装 | 条距与相位统一，可按区域铺刷；不把全地面变成格栅 |
| 稀疏的大板拼缝 | `seam`16型细线网络 | 按需要画路径，中心底图不强制每格描框；相邻独立笔划不应误连 |
| 水渠间步道 | `bridge`16型 | 24px统一宽度，开放端到格边，L/T/十字交汇无封口梁 |
| 桥端落地 | 额外上下文接头 | 不能把24px桥当成32px全边；中央开放，两侧4px保留肩口 |
| 掉漆／油渍／锈／细裂 | 独立普通图块 | 图中维护痕迹稀疏，不能周期性烘焙到每个中心tile |
| 开关检修口 | 两个同安装点普通图块 | 静态资源只表达外观，掉落或碰撞规则由后续游戏接入决定 |
| 水波、深水与岸线 | 本轮不制作水域Terrain | 本包的rim表示平台边缘，由**地板占用**驱动；它不是由水格占用驱动的`water_bank_47` |
| 管线、栏杆、门、玩家、设备 | 本轮不重做这些完整家族 | 用于判断地面层次和路线，不扩成本轮地板生产的必需资源 |

## 制作方法

内置`image_gen`根据已认可场景生成统一材质母稿，完整提示词保存在同目录。首版仅用于色阶和像素簇方向。用户随后指出生图与实际参考不匹配：首版过于平坦，粗色块出现周期竖纹，桥面与边缘偏亮。修正母稿 v002 的实际像素经局部低频校正和5阶量化进入正式钢板材质，不把图中的设备、岸线或整图阴影切进地板。精确采样范围见 `material_processing_v002.json`。

正式图集通过新的Godot原生像素构建脚本生成：固定32px原生坐标、实际母稿取样材质、同一邻接边界规则、固定方向光照。这样所有47或16型都有可复现的端口，而不是让生成模型逐块猜接头。最终资源来源登记为 **AI材质参考与实际像素取样 + Godot原生几何／色阶整理**，不能称为从概念图直接无损切出的原生素材。

边界、格栅、板缝和装饰使用独立覆盖层。包内工具负责同步，Godot原生Terrain本身不跨层同步；用户在本包场景中铺刷时不需要手动挑选凹角和桥肩口。

Floor 保持基础47型 Terrain 图块，作为可编辑的占用真源。落桥修正在独立的派生 `FloorLanding` 层覆盖，平台 Rim 同步选择上下文边缘。普通接头不写回用户绘制的 Floor 层，避免原生 Terrain 把无 Terrain 身份的上下文格误读为空地。

仅调整钢板材质后，真实GPU拼接仍缺少参考图的平台厚度。因此补充 `FloorFacade` 派生层：32px纹理上半透明、下半16px立面，图层位置 `(0,16)`，将南向立面投影到地板下缘外。南侧有地板时不出现立面，南桥口只保留两边肩柱。这个图层是视觉投影；地板／桥占用、通行宽度及纹理格均不改变。

## 接口要点

- 普通地板世界格和纹理格均32，不缩小旧128pxatlas。
- 面积位序`N NE E SE S SW W NW`；对角由两条相邻正交边约束，256邻域归一为47型。
- 网络位序`N E S W`，16种开放端口组合。
- 桥24px端口位于`[4,28)`；两边2px为侧梁。地板接桥时不能留下横向平台封口。
- 平台rim的宽度与方向明暗是本包额外结构覆盖层的截面；基础floor仍遵守2px低对比切边。
- 上下文接头须考虑原地板47型与桥所在边，实际开放宽度和肩口由像素测试验收。

## 验收边界

结构验收包括完整邻域、格边及邻近带、内部连通、随机布局、绘制／擦除、不同操作顺序、撤销重做、保存重载与4朝向桥端。

图集、Terrain元数据通过只证明结构可用；真实Godot画面还需检查色带、重复边框、内部封梁和格栅周期。用户已认可的是场景视觉方向，正式像素包仍独立登记为视觉候选，不提前记为用户认可。
