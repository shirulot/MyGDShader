# 自动铺刷瓦片规范 v2

日期：2026-10-06。与[美术规范 v2](art-style-standard-v002.md)共同使用。目标是让用户选 Terrain 后连续绘制、擦除、转弯、挖洞都能自动补全，不靠手选角块修补常规布局。

最新地板采用[参考效果生产标准 v002](reference-floor-v002-production.md)：128纹理／32世界格／0.25层缩放，桥为二格宽47型面积地形，联合脚印派生压顶与立面。本页旧32原生格、24px单格桥建议不再约束该新包；面积／网络拓扑原理仍可用于其他家族。

这是新资源设计与交付标准。后续已按本标准生产[可铺刷地板包](pixel-floor-v001-delivery.md)：实际 atlas、TileSet、跨层同步试铺工具和派生平台立面；主游戏未迁移。本规范的水域家族仍是规划，不能把已生产的平台rim视作water_bank。

## 1. 先定义笔刷语义

| 笔刷 | 格子表示什么 | 模式与最低结构覆盖 | 约束 |
| --- | --- | --- | --- |
| 地板 | 可铺设的连续地面区域 | `Match Corners and Sides`，47种归一邻接 | 支持宽区域、单格窄路、岛、端头、洞与复合凹角 |
| 墙体顶面 | 墙体占用区域 | `Match Corners and Sides`，47种 | 南向外露立面按方向表达；立面不能阻断内部连接 |
| 水域＋池岸 | 该格属于水域 | `Match Corners and Sides`，47种 | 岸体与中性水底同层选择；凹凸角按水域邻接解释 |
| 管线 | 同类管线网络的一段 | `Match Sides`，16种 | N/E/S/W四向，固定端口与直径 |
| 栏杆 | 同类栏杆网络的一段 | `Match Sides`，16种 | 转角、端头、T、十字都有一致截面；柱件不堵端口 |
| 单格宽栈桥 | 步道网络的一段 | `Match Sides`，16种 | 整体桥宽固定；T、十字完整重画，内部无封口梁 |
| 贴花、检修口、阀门 | 独立装饰或设备 | 普通 atlas tile／独立节点 | 不参与上述占用掩码；放在装饰层 |

47种是本项目“单一地形与空地、四向连通、对角受限”的完整结构约定，不是 Godot 对所有 Terrain 的固定数量要求。16种对应四个端口各开／关的全部组合。多种地形互相直接过渡、宽度可变的桥或有上下穿越关系的管线，需要另列额外结构，不能宣称现有47／16已覆盖。

Godot 的 Connect 适合依据邻近同类格补全区域；Path 适合沿所画路径连接。管线若需要相邻平行线保持独立，必须验证 Path 工作流或增加明确连接信息，不能默认“相邻就必接”。过桥、跨管等视觉相交但不相连的情况用独立层或专用节点。

## 2. 固定掩码、坐标与图集

本项目新套统一使用以下方向约定；不要混用 v007 或第三方模板的槽位顺序。

```text
8邻接 bits：N=1, NE=2, E=4, SE=8, S=16, SW=32, W=64, NW=128
4邻接 bits：N=1, E=2, S=4, W=8
坐标原点：左上，x向右，y向下；像素区间使用 [start,end)
```

面积型对角只有在两条相邻正交边均存在时才参与匹配：NE需要N与E，SE需要E与S，SW需要S与W，NW需要W与N。将256种八邻域按该规则归一后得到47种。仅对角相邻的两个区域仍保持四向分离。

| 图集 | 格大小 | 排列 | 正式图尺寸 | 槽位规则 |
| --- | --- | --- | --- | --- |
| 47型面积 | 32×32 | 8列×6行 | 256×192 | 归一mask升序，前47格；最后1格透明且不创建tile |
| 16型网络 | 32×32 | 8列×2行 | 256×64 | mask=0～15升序 |
| 随机变体 | 32×32 | 单独 atlas 或登记的扩展槽 | 逐包登记 | 对应mask、端口和闭合轮廓完全一致 |

该排列是项目选择，Godot 不强制采用8×6，也不强制采用旧版12×4模板。最终无外边距、无格间留白，`margins=(0,0)`、`separation=(0,0)`。生成稿里的留白必须在整理阶段逐格注册，不能先均分碰运气。

结构清单见[邻接矩阵 JSON](autotile-neighborhoods-v002.json)，包含256→47的映射及全部16网络mask。它是规范数据，不是已生产图片目录。

## 3. 共享截面与形状

以下数值为32px新套的首版设计基准。若小样选择不同尺寸，先更新规范，再同步整套关联构件；不能单独放宽一块的接头。

| 构件 | 首版截面 | 开放接头要求 |
| --- | --- | --- |
| 地板 | 满格实体；低对比面板切边2px，向所属格内部收，不做厚结构梁 | 连到同类地板的开边无横向端帽；真实实体与板缝逐项接续 |
| 水岸 | 水格外露边内侧8px岸带：压顶5px、暗立面2px、末端线1px | 接头按靠格边的岸带位置匹配；岸体内部连续 |
| 管线 | 直径8px；中心端口 `[12,20)` | 各方向同宽，L/T/十字以同一管径连接 |
| 栏杆 | 总轮廓带12px，居中 `[10,22)`；两梁各2px | 两条梁分别贯通；中间真实透空，不能用黑底填实 |
| 单格栈桥 | 宽24px，居中 `[4,28)`；两侧边梁各2px | 开口足宽到边界，内部交汇处无横向封口或重复侧梁 |

岸线压顶与立面按水侧方向定义，不把北向截面旋转后当成所有方向的最终光照。北岸与西岸的内部凹角需要在真实“仅缺NW水格”的3×3邻域中确认对应端口位置；不能把外L角、偏移环形弯头或两个直条叠合称为凹角。

每个端口至少登记：方向、实心或透空区间、主体宽度、边梁位置、表面／立面分界、板缝落点、允许相接的截面类别。中心对直边的板面接口，与直边对外角的含边梁接口具有不同截面角色。

开放端必须真实到达格边，主体内部也必须连通；只复制最外一排像素让边缘相等不算修复。材质变体只能改变内部低对比细节，不改变连接边、收边、Alpha轮廓和端口位置。带定向光照的成品不得以旋转图块省略朝向制作。

## 4. 水与岸线的自动补全

**首版采用 `water_bank_47`：同一Terrain图块包含中性水底与应有池岸。** 连续刷水格或擦除水格时，Godot 在当前层自动选择包括岸线的完整结构。动态水纹、流向、涟漪通过实际水域派生的 Mask 表达，岸带从水效果可见区中排除；基础图不烘焙高对比流动反射。

水面可见Mask必须从**最终选中图块的配套32px水面Mask**拼接到世界坐标，绘制／擦除／重选后同步更新。不能把每个水域占用格整格填白，否则水动画会覆盖8px岸带。水纹采样在世界坐标连续，Mask只控制作用范围，不能每格独立重启水纹相位。

水占用数据、地板占用数据和角色可走区域分别登记。沿用水mask的岸线必须写明“mask描述水域”，否则凹凸角会反向解释。水格负责8px结构岸体；相邻地板的2px仅是面板低对比切边，不额外叠厚梁。地板47型仅识别同类／非同类，若以后要求对水完全取消切边，需另做交界识别或覆盖规则。

如果后续必须将岸体拆成 `BankOverlay`：

1. 同一份水域占用集合驱动 Water 与 BankOverlay；交付显式同步工具，处理绘制、擦除、撤销／重做、整区重铺与保存重载。
2. BankOverlay同样覆盖全部47种水域结构。完全内部的mask255图块可以全透明，但仍要创建tile、设置中心terrain和全部连接bits，维持占用拓扑。
3. 透明内部块没有可见岸体，不放碰撞、导航阻挡或额外装饰。
4. Godot原生Terrain不会因为另一个图层变化自动同步。未提供并验证工具的拆层包只能标记为拆层素材候选，不能作为完整自动补全交付。

## 5. Godot配置契约

| 配置 | 新套要求 |
| --- | --- |
| TileSet.tile_size | `Vector2i(32,32)` |
| TileMapLayer.scale | `(1,1)`；世界格32 |
| TileSetAtlasSource.texture_region_size | `Vector2i(32,32)` |
| 纹理 | 无损、无mipmap；节点Nearest；Atlas `use_texture_padding=true` |
| 地形集 | 一个明确连接家族一套terrain定义；面积模式Corners and Sides，网络模式Sides |
| 中心terrain | 所属terrain ID；最小示例用0 |
| peering bits | 有同类邻居／开放端口=0；缺邻居／闭合侧=-1，即empty |
| 边界参与匹配 | 代码调用显式 `ignore_empty_terrains=false`，编辑器操作也验收对空边界的收口 |
| 概率 | 首版每个结构一个确定图块；变体后续才配置，必须共享边缘契约 |
| 遮挡与碰撞 | 与视觉Alpha分别登记；格栅虽透空仍可走，管线装饰不默认阻挡角色 |

若terrain ID不是0，以上0全部替换为该资源的真实ID；Godot 的peering bit枚举映射必须登记，不能把本文件位权当成引擎枚举值直接写入。

`set_cells_terrain_connect`用于区域重新匹配，可能重选邻格；`set_cells_terrain_path`用于连接所给路径。`ignore_empty_terrains=false`只是把空边界纳入约束，无法补出不存在的结构图块。擦除后的周边也要重新匹配并检查，不能仅测试一次初始填充。

所有匹配规则仅针对当前TileMapLayer。独立碰撞／水岸／导航层需明确同步方案。后续示例工程按用户实际Godot版本验证，不把文档API存在当作本项目新资源已通过。

## 6. 必须通过的验收矩阵

| 测试 | 动作 | 判定 |
| --- | --- | --- |
| 完整邻域 | 256种面积邻域→47归一；16网络端口 | 可选到正确结构，中心、bits、图像ID一致，无缺块或误连 |
| 连续底面 | 6×6区域，至少8格长直边 | 无亮度棋盘、重复厚框、板缝断裂、内部封口和透明裂口 |
| 狭窄与分叉 | 孤岛、单格端头、1格窄路、四向L/T/十字 | 宽度稳定，开放方向正确，封端只在终点 |
| 凹洞与角 | 四朝向外角／凹角，多个缺对角，封闭洞 | 收边完整，凹凸语义正确，组合角无覆盖冲突 |
| 斜对角接触 | 仅对角相邻两格、对角擦除 | 不误建四向桥接；轮廓符合四向连通约定 |
| 水岸闭环 | 单格池、矩形池、L形池、带岛池、窄水渠 | 岸宽一致，无双岸叠梁；水动画不越岸，拆层时同步完整 |
| 邻近网络 | 平行线、靠近未连接线、T/十字、回环 | Connect/Path行为符合笔刷说明；视觉穿越不冒充连接 |
| 动态编辑 | 连续画→擦端点／转角／中心→补回→撤销重做 | 周边收口自动更新，无残留岸、帽或旧碰撞 |
| 场景复用 | 保存重载，新空工程导入、复制相同笔刷 | 不依赖旧缓存，图集注册与Terrain信息保留 |
| 最终画面 | 正常世界尺度与Nearest放大4倍；中性底色与真实场景 | RGBA、结构、采样和GPU画面均通过，角色／危险边界清楚 |

边界实心／透空轮廓、梁宽和连接落点必须精确符合登记值，不设“看起来差不多”的容差。材料RGB不要求所有接边像素完全相同，但不能出现可见色带；数值和连通性检查通过后仍要做整片视觉审查。

交付至少包含：生产PNG、TileSet `.tres`、逐格catalog（ID/mask/coord/variant/terrain/端口）、Godot可操作试铺场景、全部结构覆盖结果、实际GPU截图、配套Mask定义、来源／整理记录。手工atlas不能替代Terrain配置，PNG预览不能替代可铺刷资源。

## 7. 官方依据与适用边界

- [Godot Terrain创建与模式](https://docs.godotengine.org/en/stable/tutorials/2d/using_tilesets.html#creating-terrain-sets-autotiling)：中心、边与角参与匹配，empty使用-1。
- [Godot TileMap绘制Terrain](https://docs.godotengine.org/en/stable/tutorials/2d/using_tilemaps.html#handling-tile-connections-automatically-using-terrains)：Terrain的编辑器连接工作流与图案覆盖。
- [TileMapLayer terrain_connect](https://docs.godotengine.org/en/stable/classes/class_tilemaplayer.html#class-tilemaplayer-method-set-cells-terrain-connect) 与 [terrain_path](https://docs.godotengine.org/en/stable/classes/class_tilemaplayer.html#class-tilemaplayer-method-set-cells-terrain-path)：相邻图块重选、路径连接、空地形约束与缺组合限制。
- [Atlas padding](https://docs.godotengine.org/en/stable/classes/class_tilesetatlassource.html#class-tilesetatlassource-property-use-texture-padding)：引擎图集边缘采样保护。
- [Godot 3.5的3×3 minimal示意](https://docs.godotengine.org/en/3.5/tutorials/2d/using_tilemaps.html#x3-minimal)：47邻域模型的历史说明。仅借用邻接理论，Godot4交付使用Terrain，不使用旧版bitmask编辑配置。

47结构、8×6排列、32px截面和分层方案是本项目设计决策；官方文档用于核对引擎机制。本轮没有以新素材运行上述验收，完成的是可直接交给后续生产与接入工作的规范。
