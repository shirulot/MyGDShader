# 《余烬采能站》完整建筑规范 v001

> 历史设计稿。后续生产以[建筑样式与交互规范 v002](../../assets/ember/buildings_final/docs/ember-building-standard-v002.md)为总入口。下文早期候选尺寸与独立屋顶／墙壳拆分目标已由完整母图和 v004r1 实际登记替代。

日期：2026-10-06。用户要求按已有风格生成完整建筑选型图，并在现有规范未覆盖时先补齐规范。本文件补充整栋建筑的占地、尺度、屋顶、入口、遮挡和后续拆件要求；与[美术规范 v2](art-style-standard-v002.md)共同使用。

## 1. 依据与适用范围

继承安静的旧工业像素风：浅装甲、蓝灰结构、少量黄铜、清楚像素块面、固定左上光、低对比磨损。机器人和设备的形状语言参考[原生比例板](../../art-source/ember/references/full_native_scale_v003.png)，不沿用其中已被用户否定的地板。

现有规范规定了门、设备与墙段，尚未完整规定整栋可进入建筑。本文件新增的建筑尺寸是本批设计约定，不是声称旧素材已经实现了整栋建筑、碰撞或屋顶遮挡。

## 2. 统一视角与尺度

- 正交前向俯视，看到顶面和南向正面。俯视角、顶面纵深和设备保持一致；yaw=0，不露出东／西侧立面。水平边横平、纵深边竖直、立墙边竖直，无消失点、斜放地基或菱形等距网格。
- 世界格固定为 32×32 world。建筑脚印以完整格登记；建筑高度投影是独立的 world 值，不能把整张 PNG 高度当成占地深度。
- 地板保持 128 texture px 映射 32 world、TileMapLayer.scale=0.25。建筑为独立 Sprite，本批正式注册目标为 1 原生纹理像素对应 1 world、节点 scale=1；禁止把地板的 0.25 套到整栋建筑上。
- 当前实际地图的机器人使用 64×96 原生帧、scale=0.65；约40×64的参考主体在此配置下约26×42 world。本批选型沿用这个实际场景比例。原生角色画布、脚底与动画规范不变，未来更换角色缩放时须同步检查门和建筑，不能单独放大人物。
- 选型图统一以 1 world=2 display px 的视觉目标比较，普通门与机器人保持同一大小。生图尺寸及模型对像素尺寸的服从不是正式注册验收；不得把大图直接 Nearest 缩小后宣称生产完成。

## 3. 墙、门、屋顶和脚印

| 构件 | 本批统一设计值／规则 |
| --- | --- |
| 普通一层南墙 | 从接地点向上投影 80 world；横向按 32 world 模块伸长 |
| 两层控制塔南墙 | 总高投影 160 world；上下层使用同一门窗和墙板尺度 |
| 普通门框 | 沿用当前可见主体约64×67 world的门比例；安装槽宽64 world |
| 普通门净口 | 设计目标40×56 world；与约26×42 world的当前机器人留出余量，正式门洞几何另验收 |
| 仓库货运门 | 安装槽宽128 world；净口104×60 world；另保留一个普通人门 |
| 门前可走区域 | 至少宽64、深64 world的现有连续地板；没有设备、栏杆、突起门槛挡路 |
| 屋顶 | 封闭、低矮平顶或低坡顶，蓝灰大面板；顶面跟随同一脚印，无侧向透视压缩 |
| 檐口 | 向脚印外最多8 world；薄而低对比，不能复制平台压顶或每块屋顶描粗亮框 |
| 基部 | 低矮蓝灰踢脚，最多8 world高；直接落在现有地板上，不另带围框、厚台阶或独立地板块 |
| 顶部装置 | 每栋最多1～2个主要功能组；风口、天窗和短天线尺寸沿用设备模块语言 |
| 窗 | 青灰暗玻璃与薄浅装甲框；普通窗带高24 world，塔上层观察窗高32 world；青色只作小状态点 |

屋顶、上墙和南墙在同一脚印上产生垂直高度投影，不能将整个屋顶向侧面偏移。门洞必须位于实际南墙平面且触达地面阈线，不能悬空、贴在屋顶或做成独立机器的控制屏。

门面尺寸应先确定，再扩展建筑壳体。建筑体现完整房间、墙、屋顶、门和窗；维修工坊不是裸设备架，仓库不是放大的货箱，控制塔不是能源圆筒，实验站不是露天水池或实验机器组合。

## 5. 像素与材料

继承共享锚定色：结构暗部 `#101820`／`#182631`，钢材 `#2B3E4B`／`#4D6470`／`#829BA3`，装甲 `#BECBC4`，小面积高光 `#ECE9D8`，黄铜 `#B77C4B`，状态青 `#51C5C2`。允许登记一致的增补色，不要求强行量化已有材质。

- 用大块明暗描述屋顶与墙面，一种材料以3～4个主要层级组织；内部线低对比，轮廓清楚，细节集中在入口、通风和维护位置。
- 屋顶比主要交互设备安静；不得满铺格栅、细密铆钉、亮铜框、高对比划痕或均匀撒点。
- 轻微老化使用成片磨损和稀疏边缘缺口；四栋维护状态相当，D 可有极少苔迹，不做废墟化。
- 基础图不烘焙强投影、雾、Bloom、天气、强灯光和大面积发光。接地影与状态灯分别处理，玻璃不做写实镜面反射。
- 正式静态实体底图沿用二值Alpha要求；选型预览允许不透明背景，不冒充透明生产素材。Nearest只是采样设置，仍需在目标原生大小审阅像素簇。

## 6. 层级、入口和后续拆件

一栋建筑后续至少登记以下职责，所有层共享世界原点和脚印：

1. `Footprint`：实际阻挡脚印、门洞、可走入口；与整幅图像Alpha分开。
2. `RearShell`：北侧与上部墙壳，登记深度排序依据。
3. `Roof`：完整屋顶，记录是否整栋隐藏或按房间淡出；不从旧场景缓存推定已经实现。
4. `FrontWall`／`DoorFrame`：南墙与门框；前景遮挡单独控制，门洞内不能残留整墙遮挡。
5. `DoorLeaf`：开／关两态共享安装槽、阈线与pivot；不得裁切后位置跳动。
6. `Trim`／`State`／`Shadow`：装饰、状态灯、接地影分别登记；不扩张实际碰撞与危险范围。

进入建筑的遮挡验收须用机器人从门前走到门洞及内部：屋顶、前墙、门框正确遮挡；透明或淡出可见区不等于碰撞已解除。开门要同时核对可走宽度、视觉净口和状态，不以贴图开口代替碰撞更新。

门前地板继续由现有地板笔刷产生，建筑不内置另一套地板。入口接在连续底面的内部，不额外触发平台周界；建筑基部也不增加独立平台压顶。地板仍优先保持铺刷和擦除后自动补全。

## 7. 墙体与屋顶的自动补全约束

完整建筑选型图不是建筑自动笔刷。现有 `map_assets_v001` 墙段为手摆装饰，不能凭墙段PNG或本规范声称已实现墙体 Terrain。

若选定方案扩为可刷建筑：

- 墙体占用、房间地板、屋顶覆盖、门洞登记为不同语义。面积笔刷须覆盖47归一邻接，方向性外墙／南立面由共同占用派生；门洞作为明确覆写数据。
- 32 world墙板共享截面。直边、外角、凹角、L/T、窄墙、孤岛与封闭房间不能靠手工叠片遮缝；保持零yaw与固定左上光，不旋转完整光照贴图冒充方向。
- 屋顶至少覆盖矩形、L形与凹角的完整收口。跨栋连接规则、层高变化、门宽变化另登记，不能用基础47型假称全覆盖。
- 绘制、擦除、改门、撤销／重做、保存重载应同步更新墙、屋顶、门洞和实际阻挡；提供工具与验收后才标记自动补全可用。
- 建筑与外部地板的交界、门口64 world通道、平台边、桥口及前景遮挡必须在真实Godot组装画面中检查。地板的技术PASS不自动继承给新建筑。

## 8. 生产与验收

选型阶段先保存完整提示词、参考职责、原始输出、版本、SHA256与人工审查结论。四张统一检查视角、比例、完整建筑轮廓、门洞、材料、地板安静程度；不合格稿先纠正再交给用户选择。

选定后按目标画布整理与拆件，登记真实Alpha、可见主体、pivot、脚印、入口、层级、Godot导入参数与逐项测试。正式可用至少通过：目标尺寸与Nearest观察、同机器人／设备实拼、开关态对齐、入口行走与遮挡、保存重载、新空工程导入；自动笔刷另通过第7节完整矩阵。

状态分别记录：`CONCEPT_CANDIDATE` → `USER_SELECTED` → `PIXEL_FINISHED` → `ENGINE_PASS`；如涉及建筑笔刷，再记录 `CONNECTIVITY_PASS`。四张选型图均不能提前标记 `USER_SELECTED`、`ENGINE_PASS` 或自动补全通过。

本批未采用候选不再作为生产参考。当前选中参考、母图、提示词及清理执行状态见[最终建筑入口](../../assets/ember/buildings_final/README.md)。

## 9. 用户选中的建筑与三视图补充

2026-10-06后续：用户以本轮三张附件选中控制塔、维修工坊、物流仓库的外观。之后制作以[选中建筑清单](../../assets/ember/buildings_final/docs/selected-buildings-breakdown-v001.md)及保存的用户附件为准，不以更晚但未被选中的简化候选替换造型。外观选中不等于尺寸、拆层、交互或自动补全通过。

三视图固定为南向正视、东侧右视和纯俯视；它们用于技术设计，允许观察侧立面。第2节零yaw仍约束游戏复合俯视图，不约束技术右视图。三个正交面共享脚印、单位比例、墙高和层间线，正视宽对应顶视宽，右视宽对应顶视深。参考未显示的完整侧墙标记为补设计。

固定屋顶／墙壳、门框、活动门板、玻璃／内景、状态灯／Mask、屋顶设备、接地影分别登记。所有同栋层共用建筑原点和基部pivot，局部裁切通过登记偏移恢复安装点；被挡底图须补齐。卷帘沿门洞裁切，灯与门状态来自同一逻辑，遮挡淡出不代替碰撞更新。可拆分资源不自动表示可拆毁玩法。
