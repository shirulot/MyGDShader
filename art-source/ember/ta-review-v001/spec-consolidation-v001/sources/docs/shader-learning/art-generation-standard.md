## 2026-10-05 用户纠正后的优先规则

以下规则优先于本文历史批次中的尺寸、色板及原生像素限制：

- 官方模板约束图块排列、连接语义和形状覆盖，不约束美术必须方块化或采用阶梯状低像素角。以用户认可母稿的金属倒角、厚度、圆润转折、黄铜及细腻明暗为视觉基准。
- 不再强制将完整美术压成 32px、16 色。逻辑格仍可为 32 世界单位，纹理分辨率独立登记；本轮保真纹理为 128px，通过层缩放保持逻辑尺度。不要用放大低清贴图冒充高保真。
- 连接测试必须同时检查实际 Alpha、RGB、导入采样和引擎渲染。只验证 Terrain 编号或单像素透明连续不足以证明无裂图；还要排除外框被重复画进内部的情况。
- 整张 atlas 不得先缩放再裁切；单块预览先裁后缩，Godot 启用 TileSetAtlasSource 纹理 padding。连接修正只处理必要接口，不增加模板式方角，不改变整套美术造型。
- 当前版本是 [v007 旧 tile 全项风格统一](autotile-v007-style-unification.md)：覆盖旧 67 个手工笔刷 ID，提供 236 种自动连接配置。包含四种地板、检修口两态、六类贴花及管线阀门。技术验证通过，用户视觉认可仍待确认；历史版本保留作比较。
- 新旧素材不能混用分辨率规范：新版 TileSet 使用 128px 纹理，层缩放 0.25；旧 ID 与坐标可通过迁移清单查找，但不能把新图直接覆盖到旧 32px atlas 配置。相同构件应从统一母稿和 Terrain 图集派生，避免手工笔刷与自动笔刷各画一套。
- 生图整张图集必须检查逐格注册和额外留白。不能仅凭外框尺寸可整除就直接均分；允许整体裁切/对齐修正排版漂移，不得借此程序化替换美术轮廓。新稿跨格阴影或连接语义错误应拒收。
- 接口校验增加端口到主体的连通性：防止只有最外一排像素匹配，内部仍断开。透空栈桥、双梁栏杆按真实结构检查，不强制中央实心。
- 新角色「铆钉」是独立替代形象：紧凑单目履带底盘、蓝灰装甲、黄铜护圈、服务工具臂。母稿、完整帧和动画均单独交付；不自动覆盖旧角色及课程玩家逻辑。

## 1. 固定美术方向

**主题：雨后的旧工业能源设施，一台小型维修机器人逐步恢复设备。风格：清晰、克制、有温度的俯视像素美术。**

| 项目 | 统一要求 |
| --- | --- |
| 视角 | 俯视三分之四正交视角；能看见设备顶面和少量正面。地面网格横平竖直，无消失点；不用等距菱形地块、侧视或镜头透视 |
| 美术语言 | 保留用户认可母稿的完整构件、清楚轮廓与细腻金属明暗；控制随机颗粒，不强制压成 1px 描边或固定 3～4 档色阶 |
| 形状语言 | 机器人为圆角装甲与紧凑四肢；设备为方形基座、圆筒、管线、可拆装面板。所有设备像来自同一制造体系 |
| 光照 | 基础图只有轻微左上方体积明暗；不画强投影、光晕或环境照明。接地影与动态灯光独立处理 |
| 材质 | 蓝灰涂装钢板、浅色陶瓷装甲、少量黄铜接头和锈迹；玻璃及水面保持低对比 |
| 叙事气质 | 有维护痕迹、轻微老化、安静而可探索；避免满屏废墟、血污、军事武器和密集霓虹 |
| 阅读顺序 | 玩家与危险提示 → 当前交互设备 → 可走路线 → 环境细节。地面最安静，关键提示最清楚 |
| 世界范围 | 维护前庭、露天泵区、热处理庭、中继核心；共享一套工业构件。未来 3D 学习场延续形状与配色 |

本标准同时覆盖“人物”和“任务”：人物负责身份与动作，任务通过目标设备、现场状态和 UI 图标表达。

## 2. 像素、画布与锚点

以下尺寸均为**最终生产 PNG 的原生像素**，不是模型生成大图的尺寸。建议新美术的构图基准为 960×540；1920×1080 对应整数 2 倍展示。视口不必整除图块，关卡拼接必须按图块网格进行。显示分辨率迁移不在本次文档工作中执行。

| 资源 | 最终画布 | 主体与留边 | 锚点 / 接口 |
| --- | --- | --- | --- |
| 地板及地形连接片 | 32×32 | 满铺，无透明边；四边连接设计一致 | 左上角贴网格 |
| 人物每帧 | 64×96 | 主体最大 40×64，建议 x=12～51、y=16～79；每帧固定画布 | 脚底接地点 `(32,80)`；不随动作自动裁切 |
| 采能站 | 128×160 | 主体最大 96×128，四边至少 16 像素 | 基座接地点 `(64,144)`；能量窗口另记中心 |
| 控制台 / 小设备 | 96×96 | 主体最大 64×64，四边至少 16 像素 | 基座接地点 `(48,80)` |
| 泵 / 排热 / 冷却设施 | 160×192 | 主体最大 128×160，四边至少 16 像素 | 基座接地点 `(80,176)` |
| 中继核心 | 192×256 | 主体最大 160×224，四边至少 16 像素 | 基座接地点 `(96,240)`；高处构件单独记录遮挡 |
| 门框与门板 | 96×128 | 开 / 关态共用画布、安装点和基座 | 基座接地点 `(48,112)` |
| 灯、记录载体、目标小物 | 64×64 | 主体最大 48×48，至少 8 像素留边 | 接地点或安装点逐项记录 |
| 任务 / HUD 图标 | 32×32 | 图案约 24×24，四边留 4 像素 | 中心 `(16,16)`；不用文字解释图案 |
| UI 面板 | 96×96 | 四角各 8×8 保持完整，中部可拉伸 | 记录九宫格边距 8 像素 |
| 水纹 / 泡沫 / 烟团 | 64×64 | 水纹满铺；泡沫、烟团透明背景 | 水纹 XY 平铺，泡沫沿 X 平铺 |
| 3D 材质底色 | 256×256 | 无定向光照，XY 平铺 | 与对应派生贴图严格对齐 |
| 3D 草叶 | 64×128 | 透明背景，根部统一在底部 | 根部 `(32,120)`；高度权重从根部为 0 |

建筑按地基、主体、可动部件、前景遮挡分层。大建筑通过地块与设备组合，不为每个房间画一张不可拆的大背景。主体尺寸上限用于控制比例，不要求填满每个像素。

全套素材采用同一原生像素尺度。不要分别放大人物、缩小设备来补救比例；先把人物、门、控制台和地块放在同一张比例验收图上修正。

## 3. 调色板与状态语义

基础美术使用以下 16 色；允许在生产整理阶段少量增补过渡色，但要登记，不能每批任意换色。Alpha、Normal、Mask、Noise 等数据图不受美术调色板限制。

| 色值 | 用途 | 色值 | 用途 |
| --- | --- | --- | --- |
| `#101820` | 最深轮廓 | `#182631` | 深阴影 |
| `#2B3E4B` | 深蓝灰主体 | `#4D6470` | 钢板中间色 |
| `#829BA3` | 金属亮面 | `#BECBC4` | 浅装甲 |
| `#7B4D35` | 铜锈暗部 | `#B77C4B` | 黄铜接头 |
| `#E2B77A` | 修复后暖灯 | `#51C5C2` | 能量 / 可操作 |
| `#E5A44B` | 预警 | `#E65B4A` | 危险 / 伤害 |
| `#566B78` | 冷却 / 停机 | `#203A4B` | 水面暗部 |
| `#406B78` | 水面纹理 | `#ECE9D8` | 小面积最高亮点 |

底图的能量窗口画成中性、可辨识的深浅区域；青色、橙色、红色等运行状态由材质与独立灯层赋予。安全用稳定点 / 环，预警用条带，危险用明确边线 / 实心标记，冷却用暗轮廓；不能仅靠颜色分辨。

## 4. 人物与动画

只规划一台玩家维修机器人：浅色胸甲、深蓝灰关节、黄铜工具接口、一个小型状态灯；不携带武器。远端维修代理复用同一套动画，通过标识或材质区分。

| 动作 | 方向 | 每方向帧数 | 合计 |
| --- | --- | ---: | ---: |
| 待机 | 下、左、右、上 | 1 | 4 |
| 移动循环 | 下、左、右、上 | 4 | 16 |
| 采集小动作，可选增强 | 下、左、右、上 | 2 | 8 |

基础共 **20 帧**，可选增加 **8 帧**。移动建议先以 8 FPS 预览，最终节奏按移动速度调整。全帧头身比例、工具位置、脚底锚点一致，脚步交替清楚；左右不自动镜像非对称工具。

受击闪白、低血脉冲、死亡溶解、扫描传送、护盾由 Shader 表现，不新增对应整套人物图片。动画先定四向关键姿势，再补循环帧；AI 输出后仍需逐帧校正，不能用每帧独立随机生成代替一致性制作。

## 6. 全量数量预算

“单元”指一帧动画、一块图块、一个部件或一张纹理。**不是生图调用次数，也不等于最终 PNG 文件数**；图集打包不改变单元数。下列精确数量是本标准制定的生产预算，课程本身只要求功能覆盖。

| 类别 | 基础 / 预留单元 | 数量依据 |
| --- | ---: | --- |
| 人物 | 20 | 4 方向 ×（1 待机 + 4 移动） |
| 场景地形与装饰 | 62 | 地板 4 + 墙体连接 13 + 栏杆 8 + 管线 12 + 水岸 12 + 桥 5 + 检修口 2 + 贴花 6 |
| 建筑、设备、任务物件 | 19 | 采能站 / 控制台 / 泵 / 排热 / 冷却 / 中继各 1；灯 2；门 2；传送底座 1；终端与屏幕框 2；校准目标 3；记录载体 3 |
| UI 与任务图标 | 15 | HUD 6 + 六任务图标 6 + 训练任务图标 2 + 面板 1 |
| 特效艺术输入 | 4 | 水纹 2 + 泡沫 1 + 烟团 1 |
| 2D 合计 | **120** | 含未来商业区域预留，不是首批最低量 |
| 3D 纹理预留 | 3 | 草叶 1 + 金属底色 1 + 混凝土底色 1；基本课程可先用程序材质 |
| 全套艺术单元 | **123** | 120 + 3 |
| 可选人物采集动画 | +8 | 四方向各 2 帧；加入后 131 单元 |
| 非入库参考稿 | 6 | 比例 / 风格板 1 + 四区域气氛稿 4 + 3D 造型板 1，单独计数 |

技术输入另计 **40 个基准单元**：课程测试输入 16、设备区域 Mask 10、2D Normal 3、小粒子图 4、3D 材质派生图 6、草叶高度权重 1。部分用 Godot 资源或 Shader 函数表达，不需要导出 PNG。

另预留**最多 30 张布局区域 Mask**：按十屏 × 水面 / 露天降雨 / 热区三类计算上限；只对实际存在的区域生成。岸线优先由水面 Mask 派生。终端与通路的简单区域用几何表达；布局扩展后重新核算。该上限不是已经确定的实际张数。

因此文件包预算为 **123 个艺术单元 + 40 个技术输入 + 0～30 个布局 Mask**；可选动画和 6 份参考稿单列。模型、场景文件、音频、字体、文本与 Shader 程序不混入图片数量。

## 7. 特效拆分规则

| 效果 | 需要准备的图片 / 输入 | 运行时制作 |
| --- | --- | --- |
| 受击、灰度、低血、描边、柔光 | 人物 / 设备底图与 Alpha | 颜色混合、邻域采样、动画参数 |
| 溶解与边缘色带 | 两种 Noise、颜色 Ramp，复用主体 | 阈值、边带、显隐生命周期 |
| 能量流与预警 | 设备窗口 Mask、能量条纹 | UV 滚动、扫描线、状态与进度 |
| 火焰与热浪 | 排热设备、程序火焰区域 / Noise；烟团可选参与粒子 | 火焰轮廓、色带、扰动、热浪；不生成整张带火的设备 |
| 雨、水滴、涟漪 | 小雨线 / 水滴图、露天与水面区域 | 发射、寿命、落点、环扩散 |
| 水渠、泡沫 | 2 张可平铺水纹、1 张泡沫、水面 / 岸线区域 | 滚动、扰动、泡沫限制、可选局部折射 |
| 护盾、传送、能量波 | 径向 Ramp、Noise、主体、设备底座 | 环形范围、扫描显隐、局部受击亮点、衰减 |
| 终端诊断、CRT、Glitch、转场 | 终端框与窗口区域；画面来自真实场景 | 屏幕采样、量化、色散、扫描线、故障、转场 |
| 2D 灯光 | 与新底图逐像素匹配的 Normal；遮挡轮廓 | 实际灯光与遮挡；不生成“照亮版底图” |
| 3D 护盾 / 全息 / 水 / 草 / Toon | Mesh、可复用 Noise、草叶、按需 PBR 派生图 | 材质、空间与顶点逻辑；效果成品截图不能替代资产 |

数据图必须由几何、像素选择、程序或已确认底图派生。不得让生图模型凭文字独立猜测精确 Mask、Normal、粗糙度或碰撞边界。

设备 Mask 先为以下 10 个部件预留：采能站、控制台、泵、排热、冷却、中继、壁灯、地灯、传送底座、终端窗口。每张与对应底图同尺寸、同锚点；通道约定为 R=可变色区域、G=发光区域、B=允许扰动区域、A=主体轮廓。某通道不用时填 0，通道不能凭视觉颜色猜测。

2D Normal 先做采能站、控制台、干净地板三张；后续设备确有灯光用途才增加。3D 金属 / 混凝土各预留 Normal、Roughness、Metallic 三张；常量材质可省略纹理文件。草叶高度权重从根部 0 到顶部 1，可用顶点色代替贴图。

## 10. 分批制作顺序

1. **首批 6 个艺术单元**：机器人朝下待机 1、采能站 1、地板 4。拼一张比例验收图，确认视角、像素尺度、色彩和轮廓。首批已包含在 123 中，不重复计数。
2. **可玩基础包**：补齐另外 19 帧人物；控制台、门、灯、栏杆、管线、基础墙体；先制作泵区两屏实际使用的子集。
3. **泵区与课程输入包**：泵、水岸、桥、检修口、水纹与泡沫；按当前章节准备测试图、Mask、Noise。实际首批布局确定后再画区域 Mask。
4. **2D 学习全覆盖包**：终端、校准目标、传送底座、排热 / 冷却设备、烟团及所需 UI；按课程接入动态效果。
5. **商业预留扩展包**：中继核心、其余区域组合、六任务图标、记录载体；区域气氛稿指导模块组合。
6. **3D 包**：到 C14～16 准备 Mesh 与纹理，沿用新风格；可选采集动画按实际需要追加。

每批定稿后再扩下一批。一次生成整张含几十个对象的大图容易造成尺寸和视角漂移，生产阶段优先单对象、少量同类变体。

## 11. 交付文件与验收

建议目录从正式开始生产时建立：

```text
assets/ember/                         # 全新正式素材
  characters/robot/                  # 单帧与动画图集
  environment/tiles/                 # 地形、墙、栏杆、桥、管线
  buildings/                         # 设备主体与可动部件
  props/                             # 目标和叙事载体
  ui/                                # 图标、面板；文字由UI渲染
  vfx/                               # 水纹、泡沫、烟与小粒子
  data/                              # Mask、Noise、Ramp、Normal
  three_d/                           # 3D纹理与模型
art-source/ember/                     # 原始生成稿、工程源文件、提示词、参考图
```

命名示例：`robot_walk_down_f00_base_v001.png`、`station_base_v001.png`、`station_mask_v001.png`、`floor_clean_base_v001.png`。同一组 `_base`、`_mask`、`_normal` 使用相同版本与画布；图集由整理后的单帧打包，不把图集预览当唯一源文件。

每项交付记录：ID、最终尺寸、有效包围盒、脚底 / 基座锚点、发光窗口与发射点、分层方式、平铺方向、动画方向 / 帧序 / 预览帧率、生成工具与日期、完整提示词、参考版本、人工修改。来源与使用条件随生成记录保存；生成内容不自动登记为 CC0。

验收清单：

- 在原生尺寸和整数 2 倍显示下，人物、门、设备比例一致，轮廓可辨，像素没有忽大忽小。
- 透明对象确有 Alpha；没有棋盘格底、白边、裁切或烘焙投影。主体通常使用 0/255 Alpha，柔烟可例外。
- 所有动画帧固定画布和锚点；循环无跳位、肢体增减、工具换边和颜色漂移。
- 地板分别检查自身 3×3 平铺，以及不同类型的相邻连接。墙 / 岸 / 桥检查全部连接片；尺寸相同不代表可任意互拼。
- Mask 与底图叠加逐像素检查，Normal 用移动灯光检查凸凹与方向。换底图后同步重做对应派生图。
- 关掉装饰特效仍能看清道路、交互和危险边界；开特效后关键读数保持清楚。
- 开 / 关门、排水前 / 后检查结构对齐、遮挡与通路；图像不承担碰撞与任务状态判定。
- 验证 Alpha 描边与图集边界，采样不能串到邻帧；宽柔光使用独立效果层。

Godot 接入建议：2D 像素底图使用 Lossless 压缩，通常关闭 mipmaps，CanvasItem 过滤采用 Nearest；平铺与非平铺素材分别设置 Repeat。Godot 4 的过滤 / 重复由 CanvasItem 或自定义 sampler 控制。3D 纹理的 mipmap 与过滤另按远近观察验证，不套用全部 2D 设置。[官方图片导入说明](https://docs.godotengine.org/en/stable/tutorials/assets_pipeline/importing_images.html)、[CanvasItem 过滤与重复](https://docs.godotengine.org/en/stable/classes/class_canvasitem.html)。

2D 的底色与 Normal 可通过 CanvasTexture 配对；实际响应仍需灯光及正确材质接入。[CanvasTexture 官方说明](https://docs.godotengine.org/en/stable/classes/class_canvastexture.html)。

本次只建立全新标准与预算，不代表图片制作、场景接入或课程效果已验收。
