## 3. 共同视觉与颜色

**继承的风格规则：**安静、低饱和的旧工业维护站；紧凑维修机械的制造语言；浅暖灰/米白装甲、深蓝灰骨架、少量暗黄铜接头、克制灰棕磨损。形体依靠清楚的色簇、阶梯轮廓和少量大块明暗。敌我识别采用不同轮廓和小面积暗橙红传感窗，不把整机改成大片鲜红。

禁止写实亮面金属、连续柔焦渐变、密集细铆钉/细线杂件、满面划痕、霓虹和大面积Bloom。材料通常3～4个主要明暗层；轮廓一般1px，大件局部可2px，内部线更低对比。这是共同设计指南，不是对已过每张PNG强行重新描边的命令。

共享锚定色来自`art-style-standard-v002.md`，**不是硬性16色表，也不是最终PNG实际颜色数的断言**：

|材料/语义|锚定色|
|---|---|
|轮廓/结构阴影|`#101820`、`#182631`|
|蓝灰钢|`#2B3E4B`、`#4D6470`、`#829BA3`|
|浅甲|`#829BA3`、`#BECBC4`、少量`#ECE9D8`|
|铜/黄铜|`#7B4D35`、`#B77C4B`、`#E2B77A`|
|可操作/能量|`#51C5C2`|
|预警/危险/冷却|`#E5A44B`、`#E65B4A`、`#566B78`|

已通过PNG保持原色与SHA，不为“统一色板”再次量化或改色。小传感窗可以是静态暗橙红像素；普通帧不烘焙大光晕、接地影、子弹、烟、雨、受击闪白或伤害数值。死亡允许按已登记传感像素暗下；连续Alpha的光烟等另层处理，不能由此宣称本包已包含独立传感窗Mask或全部特效。

## 4. 镜头、比例、像素、注册

轻俯视正交游戏镜头，能看顶面及部分正面，画面左上光照固定；没有已定的数值俯角，不应补造30°/45°等相机参数。八向是角色绕竖轴每45°转向，不能把整张正面图旋转或水平镜像当独立方向。这里的45°是方向间隔，不是相机pitch。

正式全部帧为128×128透明PNG，虚拟地面root固定`(64,104)`。悬浮机root为地面投影点，悬浮/坠落由机身像素运动表现。画布透明边用于动作空间，不等于主体或碰撞占地。移动序列原地播放，世界位移由后续游戏节点控制。

上表是初始造型尺度参考，**不是160条动作每一帧bbox都必须相同**。最终注册和真实像素以通过包的catalog、rig、source/ownership及逐帧登记为准。没有全套敌人统一锁定的主玩法世界缩放/碰撞盒；不要把地板0.25、建筑示例玩家0.65或64×96玩家画布直接套给敌人。

每张生成源图若格分辨率不同，在静态母版阶段进行一次共同等比像素密度换算，再登记源格/offset/root。同一源图所有视图共用该比例，同方向全部帧共用注册；不分别缩放头、胸、风扇或某方向来掩盖设计偏差。禁止逐帧bbox裁切后居中、齐底或归一化。

解剖学左右以角色本体为准：down时右工具在屏幕左，up时在屏幕右。允许侧向真实遮挡，但需登记遮挡者及层序，不能为露出工具而换手、移到背后、凭空补部件。

## 6. 动画、动作事件与方向

方向后缀及顺序：`down, down_left, left, up_left, up, up_right, right, down_right`，对应S/SW/W/NW/N/NE/E/SE。每款40段240帧。

|动作|帧数/FPS|循环|动作意图及端点|
|---|---|---|---|
|idle|4 / 4|是|约0～1原生像素受控微动，最后→第一帧连贯；不以大幅整机晃动替代结构|
|move|8 / 8|是|双足交替/四足对角支撑/履带相位/双转子相位，含接触、经过、抬升与完整闭环|
|attack|6 / 10|否|准备、蓄势、F03释放、回收；现有工具，不新增导弹/机枪/特效|
|hit|4 / 12|否|短回缩/侧倾后复位，闪白/粒子独立|
|death|8 / 10|否|失去支撑、塌落/坠地、唯一残骸；F07保持，不自动重播|

帧号从0开始，F03是第四帧。巡逻攻击为短枪后坐；切割为圆锯短切；重装为短炮后坐；侦察为既有光学传感/下方部件的锁定与短前倾，不扩造新武器。背向隐藏攻击工具时可用合理机身蓄力/释放让动作可读；不能强行翻出被挡武器。

脚底/履带按实际接触语义登记，俯视远近支撑点屏幕y可不同；死亡最终地面接触与侦察悬浮高度单独验证。名义sole、真实可见脚底像素和动态遮挡状态分开记录。各批的角度、源UV、脚轨迹和末帧重复安排属于该批通过实现，不把某次像素修复坐标当所有角色的通用公式。

切方向保持同类动作的`frame`和`frame_progress`，恢复原播放/暂停状态；不同动作切换从新动作开始。调用`set_frame_and_progress`，不调用不存在的`AnimatedSprite2D.advance`。相邻方向维持对应腿/履带/转子运动相位，根点、体量和工具侧别稳定。

## 7. 命名、导出、Godot和审阅界面

资源文件为`enemy_patrol.tres`、`enemy_cutter.tres`、`enemy_tracked_heavy.tres`、`enemy_scout_drone.tres`。各含40条`动作_方向`，例如`attack_up_left`。

安装相对结构：`enemies_v003/<unit>.tres`；图集`<unit>/<action>_<direction>.png`（每格128×128，横向）；单帧`<unit>/<action>_<direction>/f00.png`起；neutral缩略图与相应idle F0相同。4个TRES合计196,556 bytes，以相对路径引用PNG；迁移时TRES与单位目录关系一起保持。160图集+960单帧+32neutral=1152PNG，另4TRES+catalog=1157载荷。

正式实体二值Alpha（0/255）；当前通过PNG直接保留原RGBA，不再阈值/换色“清理”。Godot `SpriteFrames + AnimatedSprite2D`，`centered=false`，`offset=Vector2(-64,-104)`，Nearest。PNG为Lossless `compress/mode=0`、`detect_3d/compress_to=0`、`mipmaps/generate=false`、`process/fix_alpha_border=false`、`process/premult_alpha=false`。透明区RGB也纳入完整RGBA比对；Fix Alpha Border会改透明区RGB，不能忽略此差异后声称字节保真。

只给新资产目录设置导入项，未修改主工程默认设置/玩法。1152新PNG在同res相对路径隔离项目生成导入结果后安装到实际项目；TA又以真实主项目`--path`独立加载四资源复核。独立冷包的导入默认值和真实安装的`.import`证据分别保留。

审阅界面属于**作者制作且已TA验证的资源查看工具**，不是用户选择的正式游戏UI皮肤。功能：四单位、五动作、八方向；播放/暂停、从头播放、前后单帧；正常/1FPS；1×/4×最近邻；浅/深底；同相位已过原正向对照；单次动作结束停末帧；方向缩略图。源实现见V027 `build_web.py`和`preview.gd`，固定入口和当前入口文件绑定已验收。

## 8. 验收闸门及事实范围

先八向静态母版+每类SE移动小样，获TA通过后分批补动作；新增方向不能继承旧down通过。正常FPS至少两个循环/完整单次、1FPS、原生1×/4×深浅底、刚性部件叠加、末首与回idle、接地/工具拓扑/遮挡、实际方向切换共同核查。静态帧晃动、镜像、空槽和未制作占位不能计完成。
