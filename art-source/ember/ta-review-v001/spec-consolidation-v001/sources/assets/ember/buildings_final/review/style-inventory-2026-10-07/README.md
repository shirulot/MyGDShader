## 3. 视觉与相机 T

- 低饱和、仍在维护使用的旧工业站点；浅装甲外墙／包边、蓝灰钢材屋面／结构、少量黄铜接口／扣件、深青灰玻璃。机器人／设备比例语言沿用原基准。
- 正交前向俯视复合视角，看到顶面与南面；地面横平竖直、yaw=0、无消失点、无菱形等距网格。转角厚度依选中整图。**现行规范没有给出可据以重建的统一俯角度数、镜头焦距或 Camera2D zoom 数值**；不得自行补成“45°统一相机”。
- 固定左上光；每材质以 3～4 个主要明暗层组织清楚像素簇；高光面积小，磨损稀疏成片。大屋面／墙面安静，入口／门禁／维护件清晰；每栋集中 1～2 组主要屋顶功能件。
- 低矮平顶／低坡顶、矩形体量、少量圆角／斜切角；控制塔可两层。视觉层级：玩家／危险边界 → 当前交互目标 → 通路／入口 → 环境装饰。
- 共享锚定色：暗结构 `#101820 #182631`；蓝灰钢 `#2B3E4B #4D6470 #829BA3`；浅装甲 `#BECBC4`；小面积高光 `#ECE9D8`；黄铜 `#7B4D35 #B77C4B #E2B77A`；状态青 `#51C5C2`。允许登记一致的增补色，不强制量化已选母图。
- 退回：镜面写实金属、塑料般渐变、大面积霓虹／Bloom、均匀高对比噪点、密铆钉网格、每板亮框、过度废墟化、靠缩小门窗／人物显得更精细。

识别特征：控制塔为紧凑两层、上三格观察窗、下两窄窗和中门、连续层间带、中央屋顶盖及右后短天线／格栅；工坊为宽一层、左三格窗带、中人门、右下检修件、两条天窗和右后风机接管；仓库为长矩形、左人门、中宽卷门、右维护墙、两条内部屋顶加强肋、边梁、格栅与小机组。

## 5. 拆分、动画与状态 T/R

固定屋面、檐口、柱、墙、窗框及门框共同构成连续主体。每个实体像素只有一个固定或功能层归属；闭合可见 RGBA 复装等于完整生产图。活动层从同一母图按同坐标提取，保持画布、pivot；裁切时记录裁框和偏移。不得新增第二圈倒角、拉伸、描边或用装饰遮缝。

3 张完整图＋15 张功能 PNG（每栋固定主体＋4活动层）＋3 mask；另11张原审核预览。活动层为：塔 `personnel_leaf/roof_hatch/status_lenses/glass`；工坊 `personnel_leaf/maintenance_cover/status_lenses/glass`；仓库 `personnel_leaf/cargo_leaf/maintenance_cover/status_lenses`。当前运行是一个完整 Sprite＋区域 Shader，功能 PNG 不再叠到整图上。

门 R：每门独立 progress/target/locked，0.8秒升降，完全打开 progress≥0.9999 才释放碰撞；按源像素 `floor(progress*height+0.5)` 向上收起并限制在门洞内。没有帧表/FPS 合同。锁定拒绝新开门请求，不强制关已开门；断电／故障保持当前进度，恢复后按原目标继续。开关前与关门中检测接地盒，挡门则目标改为重开；同时失电时等恢复运动条件再重开。门板变化不得影响固定门框／圆角／屋顶。

交互距离64 world，按门地面入口或服务控制点测；检视模式可绕距离，不能声称远程正常操作。工坊／仓库有地面检修盖，先开盖再维修清故障；塔没有地面盖，靠地面点维修。盖板为布尔状态暗口显示，无铰链动画。设备启停在失电／故障时拒绝。天线、格栅、肋、壳和窗框静态；代码保留的空 `_rotors` 循环（4 rad/s）没有注册风机，不是已实现风机动画。

灯／玻璃实现 R（线性着色数值，不是新增通用色板）：断电灯 RGB×0.2；故障周期0.7秒、前0.35秒 RGB=(0.76,0.28,0.14)、另半周期原色×0.12；锁定或设备停用×(0.88,0.57,0.23)，是压暗暖偏而非统一橙灯；运动周期0.32秒中最后0.08秒×0.25；其余原灯色。优先级断电→故障→锁定/停用→运动。前窗通电亮态 RGB×(1.22,1.24,1.20)，各通道上限1；灯面/玻璃数组容量各6，实际登记以 JSON 为准。灯状态为建筑级，锁定只取人门锁，人门／货门尚非独立灯通道。

深暗门洞／开盖 RGB=(0.055,0.089,0.109)。进入脚印的判定取角色接地盒中心；整壳即时 Alpha=0.14，离开1.0，无透明度渐变、无过渡时长，碰撞不受此透明变化影响。保存供电、故障、设备、盖板、玻璃、各门进度/目标/锁；读档先玩家位置→接地盒→建筑状态→碰撞复核。检视开关和 interior_visible 不作为保存的完整室内系统。
