## 小包来源、注册与 Alpha

- 新五向全部绑定同一 v004 源 PNG，SHA `e2b3641d7fe3d1f6f32cf606a18a38c6d7cd86abb9a4d94f2ff42f8711ac5832`，1536×1024；五个 512×512 ROI 一次固定。v003 仅作为返修历史来源保留，正式五向没有误绑旧源。包内两版 PNG/提示词与 provenance 指定原文件的 4 项字节/SHA 一致。
- 每个新方向共同使用等轴 `52/392 = 13/98` 密度，source_anchor 分别登记，target_anchor 均为 `(64,104)`。没有单方向 bbox 归一化、水平镜像或独立横纵拉伸。catalog 与 registration 的字段绑定一致；scale 的 JSON 重存末位约 2e−16 差不是实际比例变更。
- 九张原生图均为 128×128，实际 Alpha 全为 0/255，counts 与 QA 登记一致；黑白底 1×/4× 联系图由九张实际 PNG 独立重合成，全 RGBA 零差。
- 理想 CPU floor 采样与保存输出有少量整数纹素边界差：W/NW/N/NE/E 的覆盖差分别 2/1/0/1/0，双边都可见的 RGB 差像素分别 68/158/68/46/124。逐点按实际变换逆查，这些样本均位于源整数纹素边界，可由 Nearest 浮点采样落在相邻纹素解释；用边界候选及最多 1 码值读回容差未发现无法归属的可见样本。**不宣称 CPU 与保存 GPU 全 RGBA 零差，也不把边界采样现象判为重绘。**
- 原生 PNG 的 Alpha 0 区仍有隐藏白 RGB，与保留的 c002/down 同类；Nearest 的可见覆盖和上述黑白合成正常。这不是“透空 RGBA 全零”证明。源连续 Alpha 经 0.5 覆盖导出，也不冒充原生逐像素 Alpha 精修。
- 包内导出器是工作项目快照，引用外部 `entity_cutout.gdshader`；README 明确该包不是独立 Godot 动画工程。此处是静态来源登记，不据此扩大为可独立运行的动画资源验收。
