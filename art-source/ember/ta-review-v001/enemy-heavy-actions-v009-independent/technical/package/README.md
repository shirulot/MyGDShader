# 履带重装机攻击/死亡 v009 — 等待 TA

本候选仅包括 attack_down 6 帧、death_down 8 帧。已通过的 v007 待机、移动、受击不改；它们的冻结包仍有效。

128×128 透明 PNG，根坐标 (64,104)，10 FPS，两个动作均不循环。攻击 f03 释放事件，死亡 f07 残骸保持。实际输出是 Godot 固定源部件动画的栅格化结果，不逐帧生成人物。

攻击：固定双履带，炮口组件相对安装座向上后坐 2px，塔体下沉 1px，再回中性。死亡：塔体从 0 下沉至 13px；炮口在固定枢轴附近倾斜 12 度、下沉 1px；传感器按源区域渐暗。上盖随塔体保持刚性，两个履带未变形/倾倒，最后两帧同一个残骸保持。盖体没有凭空出现未画出的内腔。

`rig.json` 定义塔壳、炮口、履带与下底盘的固定源区域。下沉露出的隐藏底座由一次 imagegen 补画，保留原始生成 PNG 与 prompt；固定 source_rect → destination_rect 的坐标映射，并用固定中性轮廓限制覆盖。中性帧与原始 canonical 的有效 RGB/Alpha 覆盖完全一致。隐藏底座仅在动作露出后可见，未逐帧缩放归一化。

`verify.gd` 检查 14 帧原生深浅底 GPU/PNG 的 28 组一致性、双履带 Alpha/RGB 与底边静止、连通与攻击末帧复位。`capture.gd` 实际播放两个 SpriteFrames，包含正常速度和 1 FPS 的遍历与结束信号。自动检查不能代替 TA 对炮口、安装座、下沉层次及残骸轮廓的判断。

请重点审查：炮口收缩后的安装座是否连续；塔壳下沉的挡压关系；倾斜炮口是否仍属于同一刚性组件；地面支撑和死亡最终高度是否合理。

启动：Godot `--path <本目录>`；检查：先 `--script export.gd`，再 `--script verify.gd`，最后 `--script capture.gd`。正式冻结包中的像素与脚本不能覆盖更新，后续修正另起版本。
