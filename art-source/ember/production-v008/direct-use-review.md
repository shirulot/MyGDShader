# 当前瓦片能否直接使用：复核结论

2026-10-05。审核范围为 production-v008 当前地板和池岸候选，以及其对照用 v007 图块；不扩展为角色动画或其他道具的验收。

**结论：不能直接作为完整、可复用的 TileSet 交付。当前只能用于样稿审查与铺刷诊断。手动用 TileMapLayer 摆放，也无法消除同套构件的端口、轮廓和材质跳变。**

本次重新查看了当前 8 类对比、地板原尺度/GPU 放大试铺、窄条与端头来源拼接图，以及池岸 GPU 图。另直接读取当前 PNG 的主体边界位置，确认下表尺寸。没有新增生图，没有修改素材像素，也没有把旧的技术检查重写为美术通过。

## 阻碍直接使用的问题

| 问题 | 当前证据 | 使用时的结果 | 判定 |
| --- | --- | --- | --- |
| 窄条与端头、转角不属于同一宽度体系 | 新 mask17 的 N/S 主体区间为 `[41,87)`，宽 46px；试铺沿用的旧 mask16 南端、mask1 北端均为 `[1,127)`，宽 126px | 直路接端头或 L 形时轮廓突然扩宽，两侧各跳变约 40px；世界格32下仍有约10单位跳变 | 阻止作为通用地板套使用 |
| 地板板缝、边框和造型尺度不连续 | 当前 GPU 试铺中，细密新地板接到旧大面板时出现明显纹理跳变；旧边块还有周期性亮条、突起和重复内部收边。新北直边与新外角的边梁厚度也不同 | 铺出的区域明显露出瓦片边界，长边和凹洞无法形成统一构件 | 阻止直接使用；不能把旧版当作已合格回退版 |
| 池岸凹角端口位置尚未统一 | v003 凹角 N/W 主体区间均为 `[31,63)`；当前北直岸横向接头为 `[0,30)`，外角向南接头为 `[0,32)`。这是不同位置，不能只比较“约32px宽” | 弧形单块虽连通，但当前构件家族尚未证明可以组成连续闭合岸线；相邻方向应逐对验证 | 阻止作为完整池岸套使用 |
| 新版形态覆盖不完整 | official/catalog.json 与 GPU 标题均记录 42 个旧块 + 5 个新地板样稿；池岸只有三类、北向局部连接 | 当前47槽图集只是混合诊断，无法视为47型新版美术；其他方向、T形、端头及闭环未统一 | 阻止发布正式整套 |

边界主体诊断使用 `Alpha > 127`，只用于测量，未对 PNG 做阈值处理。轻微 RGB 或抗锯齿差异本身不等于视觉失败；本次否决依据是可见的轮廓跳变、材质/结构不连续以及覆盖不足。现有10对接口测量也不是完整的邻接兼容矩阵。

## 已通过的检查意味着什么

现有独立 Godot 项目可以导入纹理、保存 TileSet 配置、按邻域选择47种 mask，并执行绘制和擦除。导入像素检查也未发现当前图集的 Alpha 或可见 RGB 被改变。

这些结果说明引擎读到了所登记的图块，不能说明图块美术能够自然接起来。官方排列正确只完成了排列与连接标签；实际轮廓、共享接头和材质连续性仍需单独验收。因此，当前 `production_ready: false` 的状态应保留。

## 修正顺序与验收条件

1. 先定同一套地板和池岸的共享接头：每个方向的实际边界区间、梁宽、压顶/立面分界、板缝尺度及光照。不要把模板示意中的红色宽度直接当成美术宽度要求。
2. 在这套共享接头下修正首批完整构件，并同时验证窄条、端头、转角和凹角的匹配；独立生成后直接塞进 mask 槽位不足以解决问题。不能通过混入旧块宣称新版形态完成。
3. 首批通过后补齐同一风格的全部必需方向与形态，建立实际相邻接口检查；保持128px纹理、32世界格与0.25层缩放的登记一致。
4. 最终用同一套完整美术实际铺出大面积、长边、L/T形、窄路端头、凹洞、封闭池岸，并测试擦除后的收口。普通游戏显示尺度和放大图均应无明显轮廓/板缝/阴影跳变，再交付可直接复用的 TileSet 与布局说明。
